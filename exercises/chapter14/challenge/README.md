# 第14章 チャレンジ課題

## 学習目標
- 自分で決めたテキスト形式（タブ区切り、UTF-8）でデータを保存し、読み込む
- 壊れた行があっても全体を読むのをやめず、行番号付きの警告にして読み飛ばす
- `Files.copy`で上書きの前にバックアップを取るなど、NIO.2の`Files`・`Path`でファイルを扱う
- `Serializable`と`ObjectOutputStream`・`ObjectInputStream`でオブジェクトを丸ごと保存し、`transient`の働きを確かめる
- テキストブロックのひな形に値を埋め込んで、まとめのファイルを書き出す
- 何度実行しても同じ結果になるよう、作業用のファイルをプログラム自身で用意する

## 課題一覧

### 課題1: ToDoリストの保存と復元
**ファイル**（このフォルダーのファイルは解答例です）:
```
challenge/
├── Task.java           1件のタスク（レコード、Serializable）
├── TodoList.java       タスクの一覧（Serializable）
├── TodoFileStore.java  テキスト形式・直列化での保存と読み込み
└── TodoApp.java        mainメソッド
```

ToDoリストを、人が読めるテキスト形式と、オブジェクトの直列化の2つの方法で保存・復元するプログラムを作成してください。

**要求仕様**:
- `Task`
    - 番号・題名・期限（「11/20」のような文字列）・完了したかを持つレコードにし、`Serializable`を実装する
    - `complete()`は完了にした新しい`Task`を返す
- `TodoList`
    - タスクの一覧と次の番号を持ち、`Serializable`を実装する
    - 保存していない変更があるかを表す`modified`は、保存する必要のない情報なので`transient`にする
    - `add`（番号を振って加える）、`restore`（ファイルから読んだタスクを番号を変えずに加える）、`complete`（番号で完了にする）を持つ
- `TodoFileStore`
    - `saveText(パス, 一覧)`
        + 1行目に見出し`#todo v1`、2行目からタスクを1行ずつ「番号、題名、期限、完了」のタブ区切りで、UTF-8で書く
        + 題名にタブが含まれていたら空白に置き換える
        + ファイルがすでにあれば、上書きの前に「`.bak`」を付けた名前でコピーする
    - `loadText(パス)`
        + 1行目が見出しでなければ`IOException`にする
        + 項目が4つでない行、番号が整数でない行は読み飛ばし、「N行目: 理由」の警告を集める
        + 読み込んだ一覧と警告の一覧をレコード`LoadResult`で返す
    - `saveObject`・`loadObject`は、`ObjectOutputStream`・`ObjectInputStream`で一覧を丸ごと保存・復元する。`ClassNotFoundException`は`IOException`に包む
- `TodoApp`
    - 作業用の`todo-data`ディレクトリを用意する。前回の実行で作ったファイルがあれば消す
    - 4件を保存し、1件を完了にして1件（題名にタブを含む）を加えてから、もう一度保存する（2回目はバックアップができる）
    - 保存したファイルの中身を表示する
    - ファイルの末尾に、壊れた行2つと正しい行1つを追記してから読み込み、警告と件数を表示する
    - 直列化で保存・復元し、内容が同じことと、`transient`のフィールドが保存されないことを確かめる
    - テキストブロックのひな形で、件数と未完了のタスク（期限の早い順）のまとめを`report.txt`に書き出し、その中身を表示する
    - 最後に、作業用ディレクトリのファイルを名前順に表示する

**実行例**:
```
=== 準備 ===
todo-data を空の状態で用意しました

=== テキスト形式で保存 ===
保存していない変更: true
todo.tsv に4件保存しました（168バイト）
保存していない変更: false
  前のファイルを todo.tsv.bak にコピーしました
todo.tsv に5件保存しました（204バイト）

=== todo.tsv の中身 ===

1 | レポートの下書き | 11/20 | false
2 | 図書館に本を返す | 11/15 | true
3 | サークルの会費を払う | 11/18 | false

警告: 7行目: 項目が4つではありません（6 ゼミの発表準備）

=== まとめを書き出す ===

------------------
```

読み込んだ最大の番号が8なので、そのあとに加えたタスクの番号は9になります。

## コンパイルと実行

```bash
javac *.java
java TodoApp
```

実行したディレクトリに`todo-data`ディレクトリができます。何度実行しても同じ結果になります。

## 実装のヒント

```java
// 上書きの前にバックアップを取る
if (Files.exists(path)) {
    Path backup = path.resolveSibling(path.getFileName() + ".bak");
    Files.copy(path, backup, StandardCopyOption.REPLACE_EXISTING);
}

// 末尾に追記する
Files.writeString(path, "6\tゼミの発表準備\n", StandardCharsets.UTF_8, StandardOpenOption.APPEND);

// ディレクトリの中のファイルを名前順に並べる。Files.listのStreamは閉じる必要がある
try (Stream<Path> files = Files.list(dir)) {
    files.map(p -> p.getFileName().toString()).sorted().forEach(IO::println);
}
```

- `resolveSibling`は、同じディレクトリにある別の名前のパスを作る
- `Files.list`が返す順序はOSやファイルシステムによって変わる。表示する前に`sorted()`で並べると、どの環境でも同じ結果になる
- 1行ずつ読むときは、行番号を自分で数える。見出しの行も1行と数えると、エディターで開いたときの行番号と一致する
- `readObject()`の戻り値は`Object`型なので、`(TodoList)`でキャストする
- 直列化するクラスのフィールドの型も直列化できる必要がある。`ArrayList`、`String`、`Serializable`を実装したレコードは直列化できる
- テキストブロックの中の`%d`・`%s`には、`formatted`で値を埋め込める。閉じる`"""`を最後の行の末尾に置くと、最後に余分な改行が付かない
- 直列化は、信頼できないファイルを読み込むと危険なことがある。自分のプログラムが書いたファイルだけを読む用途にとどめる

## 応用のポイント

1. 形式の使い分け
    - テキスト形式は人が読んで直せるが、壊れた行への備えが要る。直列化は手軽だが、人は読めず、クラスを変えると読めなくなることがある
2. 安全な上書き
    - 上書きの前にバックアップを取ると、保存に失敗したときや間違えて保存したときに元に戻せる
3. 毎回同じ結果
    - 作業用のファイルをプログラムが用意し、ファイル一覧を並べてから表示すると、実行例と照らし合わせて確かめられる

## 発展（任意）

- `loadText`で、同じ番号のタスクが2回出てきたら警告にする
