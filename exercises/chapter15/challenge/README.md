# 第15章 チャレンジ課題

## 学習目標
- `BlockingQueue`で、注文を受けるスレッドと調理するスレッドをつなぐ（プロデューサー・コンシューマー）
- 待ち行列がいっぱいのときに`put`が待つことで、受付の速さを調理の速さに合わせる
- `Semaphore`で、同時に使える設備（コンロ）の数を制限する
- `ExecutorService`のスレッドを、目印（ポイズンピル）と`shutdown`で終わらせる
- `CompletableFuture`を自分で`complete`させ、別のスレッドの処理が終わったことを知らせる
- `synchronized`・`AtomicInteger`・`ConcurrentHashMap`を、守りたいものに合わせて使い分ける

## 課題一覧

### 課題1: 学食の注文処理
**ファイル**（このフォルダーのファイルは解答例です）:
```
challenge/
├── Menu.java          メニュー（列挙型。値段・調理時間・コンロを使うか）
├── Order.java         1件の注文（レコード）
├── Kitchen.java       厨房（待ち行列、コック、コンロ、売上）
├── OrderWindow.java   注文を受ける窓口（Runnableを実装）
└── CafeteriaApp.java  mainメソッド
```

2つの窓口で受けた注文を、3人のコックが手分けして調理する学食のプログラムを作成してください。
麺類（ラーメン・うどん）をゆでるにはコンロを使いますが、コンロは2台しかありません。

**要求仕様**:
- `Menu`（列挙型）
    - カレー（450円）、定食（600円）、ラーメン（500円）、うどん（350円）
    - 調理時間（ミリ秒）と、コンロを使うかどうかを持つ。ラーメンとうどんがコンロを使う
- `Order`（レコード）
    - 食券番号（窓口の記号と連番。例: A1、B3）、客の名前、メニューを持つ
- `Kitchen`（厨房）
    - コックの人数・コンロの台数・待ち行列の長さをコンストラクターで受け取る
    - 注文は`ArrayBlockingQueue`の待ち行列に入れる。待ち行列がいっぱいなら、空くまで受付が待つ
    - コックは`ExecutorService`のスレッドで動き、待ち行列から注文を取り出して調理する
    - コンロを使うメニューは、`Semaphore`の許可を受け取ってから調理し、終わったら返す
    - `placeOrder(注文)`は、調理が終わると完了する`CompletableFuture<Order>`を返す
    - `close()`で受付を終える。受付を終えたあとの注文は、`IllegalStateException`を投げて断る
    - `close()`は、コックの人数分の目印を待ち行列に入れ、コックが残りの注文を作り終えるのを待つ
    - メニューごとの販売数を`ConcurrentHashMap`、受け付けた件数・作り終えた件数・同時に使ったコンロの最大数を`AtomicInteger`で数える
- `OrderWindow`（窓口）
    - `Runnable`を実装し、決められた客の注文を順に厨房へ渡す
    - 受け取った`CompletableFuture`を、注文の順にリストに残す
- `CafeteriaApp`
    - 窓口A・Bに6件ずつの注文を持たせ、それぞれ別の`Thread`で同時に動かし、`join`で両方が終わるのを待つ
    - `CompletableFuture.allOf`ですべての注文ができあがるのを待ってから、できあがった注文を食券番号の順に表示する
    - 受付を終えたあとに来た客の注文が断られることを示す
    - メニューごとの売上と合計、件数の確認を表示する

**実行例**:
```
=== 学食の注文処理 ===
コック3人、コンロ2台、注文の待ち行列は4件まで

=== できあがった注文 ===
  A1 佐藤 ラーメン
  A2 鈴木 カレー
  A3 高橋 うどん
  A4 田中 ラーメン
  A5 伊藤 定食
  A6 渡辺 うどん
  B1 山本 うどん
  B2 中村 ラーメン
  B3 小林 カレー
  B4 加藤 定食
  B5 吉田 ラーメン
  B6 山田 カレー

=== 受付終了後 ===
  A7 松本: 受付は終了しました

=== 売上 ===
  カレー: 3食 1,350円
  定食: 2食 1,200円
  ラーメン: 4食 2,000円
  うどん: 3食 1,050円
  合計: 12食 5,600円

=== 確認 ===
  受け付けた注文: 12件、作り終えた注文: 12件
  同時に使ったコンロは2台以内: はい
```

どのコックがどの注文を作るか、注文ができあがる順序は、実行ごとに変わります。
そのため、調理の途中では何も表示せず、すべてができあがってから食券番号の順に表示しています。

## 実装のヒント

```java
public class Kitchen {
    private record Job(Order order, CompletableFuture<Order> done) {
    }

    // コックに終わりを知らせる目印。中身は使わず、==で見分ける
    private static final Job END = new Job(null, null);

    private void cookLoop() {
        try {
            while (true) {
                Job job = queue.take();  // 注文が来るまで待つ
                if (job == END) {
                    return;
                }
                cook(job.order().menu());
                job.done().complete(job.order());  // 窓口側に、できあがったことを知らせる
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}
```

- コンロを使う処理は、`stoves.acquire()`のあとを`try`、`stoves.release()`を`finally`に書く。調理の途中で例外が起きても許可を返せる
- 同時に使ったコンロの最大数は、使い始めに`incrementAndGet()`した値を`accumulateAndGet(値, Math::max)`で最大値と比べて残す
- 受付を終えたかどうかのフラグを`volatile`にしても、「受付中か調べてから待ち行列に入れる」あいだに`close()`が割り込むのは防げない。`placeOrder`と、`close`のフラグを書き換える部分を`synchronized`にする
- `close()`で目印を入れるのは、受付を止めたあと。目印より後ろに注文が入ると、その注文はだれにも作られない
- 窓口のスレッドが作ったリストは、`join()`でスレッドの終わりを待ってから読む。`join()`のあとなら、そのスレッドが書き込んだ内容が見える
- `new CompletableFuture<>()`で作ったオブジェクトは、`complete(値)`を呼ぶまで完了しない。別のスレッドで`complete`すると、`join()`や`allOf`で待っているスレッドに終わりが伝わる
- 待ち行列の長さを4件にしているので、窓口は注文をすべて一度に入れられず、コックが取り出すのを待つことがある

## 応用のポイント

1. 受付と調理を分ける
    - 窓口は注文を待ち行列に入れるだけで、調理の終わりを待たない。窓口とコックの人数を別々に変えられる
2. 設備の数の制限
    - コックが3人いても、`Semaphore`の許可が2枚なら、麺類は同時に2つまでしかゆでない
3. 終わらせ方
    - コックの人数分の目印を入れると、それまでに受けた注文をすべて作り終えてから、コックのスレッドが終わる

## 発展（任意）

- コックごとに作った注文の数を数えて表示する（実行ごとに変わるので、合計が12件になることを確かめる）
- 待ち行列の長さやコックの人数、コンロの台数を変え、すべての注文ができあがるまでの時間を`System.nanoTime()`で比べる
- `ArrayBlockingQueue`の代わりに、`wait()`と`notifyAll()`を使った待ち行列のクラスを自分で書いて置き換える。`wait()`は`while`のループで囲む
- 注文を受けてから一定時間（例: 500ミリ秒）で作り終わらない注文を、`orTimeout`で「遅れています」と表示する
