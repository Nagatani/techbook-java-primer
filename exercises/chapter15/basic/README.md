# 第15章 基本課題

## 学習目標

- Threadの継承とRunnable（ラムダ式）の2通りでスレッドを作り、`start`と`join`で動かして待つ
- 共有する値の更新が失われる（データ競合）ことを確かめ、synchronizedとAtomicIntegerで防ぐ
- volatileで、別のスレッドへ停止の合図を確実に伝える
- ExecutorService・Callable・Futureで仕事をスレッドプールに任せ、結果を受け取る
- ConcurrentHashMap、CompletableFuture、BlockingQueue、Semaphoreを使い分ける

## 課題一覧

各課題の「作成するファイル」は、自分で作成するファイルの名前の例です。課題ごとの解答例は[solutions/](../solutions/)にあり、実行例はその解答例を動かした出力です。

複数のスレッドが同時に`IO.println`すると、表示の順序は実行のたびに変わります。
どの課題も、結果をスレッドの中で表示せずに配列や`Future`に集め、`join`や`get`で待ってから決まった順序で表示します。

### 課題1: スレッドを作って待つ

**作成するファイル**: `BasicThreading.java`

1から1,000,000までの和を2つのスレッドで半分ずつ求め、Runnableでも3つのスレッドを動かします。

**要求仕様**:

- `Thread`を継承した`SumThread`は、名前と範囲を受け取り、`run`で範囲の和を求めてフィールドに残す
- 2つの`SumThread`を`start`し、`join`で待ってから、それぞれの和と全体の和を表示する
- `getState()`で、`start`の前（`NEW`）と`join`の後（`TERMINATED`）の状態を表示する
- ラムダ式で書いたRunnableを3つのスレッドに渡し、結果を配列の決まった位置に書かせる。全員を`join`してから、配列の順に表示する

**実行例**:

```
メインスレッド: main

--- Threadを継承する ---
start前の状態: NEW
join後の状態: TERMINATED
前半の合計: 125000250000
後半の合計: 375000250000
全体の合計: 500000500000

--- Runnableをラムダ式で渡す ---
作業者1 が 1番目の仕事を終えた
作業者2 が 2番目の仕事を終えた
作業者3 が 3番目の仕事を終えた

メインスレッド終了
```

### 課題2: データ競合と同期

**作成するファイル**: `SynchronizationDemo.java`

10個のスレッドが1000回ずつカウンターを増やし、同期のあるなしで結果を比べます。

**要求仕様**:

- 「10個のスレッドで、それぞれ1000回`Runnable`を実行し、全員を待つ」メソッドを作り、次の3つに使う
- 同期のない`count++`、`synchronized`メソッドの`count++`、`AtomicInteger`の`incrementAndGet`
- `synchronized`の`deposit`・`withdraw`を持つ口座に、10個のスレッドが1000回ずつ300円入金して200円出金する。最終残高が計算どおりになることを確かめる
- `volatile`の`boolean`フラグを見て回り続けるスレッドを作り、メインスレッドから`false`にして止める

**実行例**:

```
--- カウンター（10スレッド×1000回） ---
同期なし: 8696
synchronized: 10000
AtomicInteger: 10000

--- 口座（10スレッドが1000回ずつ入金と出金） ---
最終残高: 1010000円（10000 + 100 × 10000回）

--- volatileの停止フラグ ---
作業スレッド: 停止の合図を受け取りました
メインスレッド: 作業スレッドが終わりました
```

「同期なし」の値は実行のたびに変わり、10000より小さくなることが多くなります（たまたま10000になることもあります）。
ほかの行は毎回同じです。

### 課題3: スレッドプールと非同期の処理

**作成するファイル**: `ExecutorDemo.java`

仕事をスレッドプールに任せて結果を受け取り、CompletableFutureで処理をつなぎます。

**要求仕様**:

- `Executors.newFixedThreadPool(3)`に、「limit以下の素数を数える」Callableを4つ（10、100、1000、10000）投入し、投入した順に`Future.get`で結果を表示する
- 3つのかごの果物を、別々の仕事として`ConcurrentHashMap`の`merge`で数える。全部の`Future`を待ってから、`TreeMap`に移して名前順に表示する
- `shutdown`のあと`awaitTermination`でプールの終了を待つ
- `CompletableFuture.supplyAsync`でリストを作り、`thenApply`で2倍にしてから合計する。`thenCombine`で2つの結果を合わせる

**実行例**:

```
--- ExecutorServiceとCallable ---
10以下の素数: 4個
100以下の素数: 25個
1000以下の素数: 168個
10000以下の素数: 1229個

--- ConcurrentHashMapで集計 ---
集計（名前順）: {ぶどう=2, みかん=3, りんご=3}
プールの終了を待つ: true

--- CompletableFutureで処理をつなぐ ---
2倍にした値: [2, 4, 6, 8, 10]
合計: 30
2つの結果を合わせる: 1200円・在庫あり
```

### 課題4: 生産者と消費者

**作成するファイル**: `ProducerConsumer.java`

BlockingQueueで生産者から消費者へ値を渡し、Semaphoreで同時に使える数を制限します。

**要求仕様**:

- 大きさ5の`ArrayBlockingQueue`に、生産者のスレッドが1〜100を`put`する。最後に、消費者の数だけ終わりの合図（`-1`）を入れる
- 2つの消費者のスレッドは`take`で取り出し、合図を受け取ったら終わる。取り出した数と値の合計を、消費者ごとの配列の要素に足す
- 全員を`join`してから、取り出した数の合計（100）と値の合計（5050）を表示する
- 許可が3つの`Semaphore`を8つのスレッドで取り合い、同時に使っている数の最大が3を超えないことを`AtomicInteger`で確かめる

**実行例**:

```
--- BlockingQueue ---
消費した数の合計: 100
値の合計: 5050（1〜100の和は5050）
キューに残った数: 0

--- Semaphoreで同時に使える数を制限 ---
利用者: 8人、プリンター: 3台
同時に使った数は3以下: true
使い終わったあとの空き: 3台
```

どちらの消費者が何個取り出したかは実行のたびに変わるので、合計だけを表示します。

## コンパイルと実行

```bash
javac BasicThreading.java
java BasicThreading
```

ほかの課題も同じように実行します。

## ヒント

### 課題1のヒント

- `run()`を直接呼ぶと、新しいスレッドは作られず、呼んだスレッドで実行される。スレッドを始めるのは`start()`
- ラムダ式の中から使うループ変数は、`int index = i;`のように実質的にfinalな変数へ写してから使う

### 課題2のヒント

- `count++`は「読む・足す・書く」の3つの操作なので、途中で別のスレッドが割り込むと更新が失われる
- メソッド参照`counter::increment`は、Runnableとして渡せる
- 回り続けるループの中では`Thread.onSpinWait()`を呼んでおくと、CPUへの負担が減る

### 課題3のヒント

- `Future.get()`は結果が出るまで待つ。投入した順に`get`すれば、表示の順序は投入した順になる
- `shutdown()`を忘れると、プールのスレッドが残ってプログラムが終わらない

### 課題4のヒント

- `put`はキューが満杯のとき、`take`は空のときに待つ。待つ処理は`InterruptedException`を投げる
- 消費者が複数いるときは、終わりの合図を人数分入れないと、合図を受け取れない消費者が待ち続ける
- Semaphoreの`release`は`finally`で呼ぶ

## よくある落とし穴

- `run()`メソッドを直接呼び出す（スレッドの開始は`start()`）
- 共有する値を同期なしで更新する
- 複数のロックを取る順序がスレッドによって違い、デッドロックになる（ロックを取得する順序をそろえる）
- ExecutorServiceの`shutdown()`を忘れる
