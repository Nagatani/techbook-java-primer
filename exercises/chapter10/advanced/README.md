# 第10章 発展課題

## 学習目標
- 型パラメーターを持つクラスを作り、同じクラスを違う型の値に使う
- 境界のある型パラメーター（`<T extends Comparable<T>>`）で、型パラメーターの値のメソッドを呼ぶ
- 上限境界ワイルドカード（`? extends T`）と下限境界ワイルドカード（`? super T`）を、引数の役割に合わせて使い分ける
- ジェネリックメソッドを定義し、型引数が推論されることを確かめる
- 右辺から型がわかる場面で`var`を使う

## 課題一覧

### 課題1: ランキング表
**ファイル**（このフォルダーのファイルは解答例です）:
```
advanced/task1-ranking/
├── Ranking.java     上位の件数だけを残すランキング
├── GameScore.java   ゲームの得点（レコード）
└── RankingApp.java  mainメソッド
```

テストの点数やゲームの得点のように、大小を比べられるものの上位だけを残すランキングを、ジェネリッククラスで作成してください。

**要求仕様**:
- `Ranking<T extends Comparable<T>>`
    - 残す件数をコンストラクターで受け取り、要素を大きい順に`ArrayList`で持つ
    - `add`で要素を正しい位置に入れ、入った順位（1から）を返す。件数を超えたら最下位を外し、ランキングに入らなければ0を返す
    - 同じ値のときは、先に入った要素を上にする
    - 順位を指定して要素を返す`get`、件数、最下位の要素、中身のコピーを返すメソッドを持つ
    - 静的なジェネリックメソッド`of(件数, List<? extends T>)`で、リストの要素をまとめて加えたランキングを作る
- `GameScore`
    - 名前と得点を持つレコード。`Comparable<GameScore>`を実装し、得点で比べる
- 同じ`Ranking`クラスを、`Integer`（テストの点数・身長）と`GameScore`に使う

**実行例**:
```
=== テストの点数（上位3件） ===
72点 → 1位に入りました
88点 → 1位に入りました
65点 → 3位に入りました
88点 → 2位に入りました
95点 → 1位に入りました
70点 → ランキング外
ランキング: [95, 88, 88]
3位の点数: 88

=== ゲームの得点（上位3件） ===
1位: たろう 1500点
2位: じろう 1500点
3位: さくら 1200点

=== リストからまとめて作る ===
身長の上位2件: [180, 172]
```

`Ranking<Object>`のように`Comparable`を実装していない型を指定すると、コンパイルエラーになります。

### 課題2: 元に戻す・やり直すの履歴
**ファイル**（このフォルダーのファイルは解答例です）:
```
advanced/task2-history/
├── History.java     値の履歴
└── HistoryApp.java  mainメソッド
```

文書作成ソフトの「元に戻す」「やり直す」のしくみを、どんな型の値にも使えるジェネリッククラス`History<T>`として作成してください。

**要求仕様**:
- `History<T>`
    - 今の値と、元に戻すための値の`ArrayList`、やり直すための値の`ArrayList`を持つ（どちらも末尾が最新）
    - `change`で値を変える。今の値を元に戻す側に積み、やり直す側を空にする
    - `undo`・`redo`で値を1つ戻す・進める。できなければ`false`を返す
    - `changeAll(List<? extends T>)`で、変更をまとめて適用する
    - `exportTo(Collection<? super T>)`で、これまでの値（古い順）と今の値を、渡されたコレクションに加える
    - 静的なジェネリックメソッド`describe(History<A>, History<B>)`で、2つの履歴の今の値を組にした文字列を返す
- 同じ`History`クラスを、メモの文章（`String`）と文字の大きさ（`Integer`）に使う
- `History<Integer>`の値を`List<Number>`に、`History<String>`の値を`List<Object>`に書き出す

**実行例**:
```
=== メモの文章 ===
今の文章: 買い物: 牛乳、卵
元に戻す: 買い物: 牛乳
元に戻す: 買い物
やり直す: 買い物: 牛乳
書き換え: 買い物: 牛乳、パン
やり直せるか: false

=== 文字の大きさ ===
今の大きさ: 18
3回元に戻した: 12
さらに元に戻せるか: false

=== 履歴の書き出し ===
文字の大きさ: [12, 14, 16]
メモ: [買い物, 買い物: 牛乳, 買い物: 牛乳、パン]

今の状態: (買い物: 牛乳、パン, 16)
```

文字の大きさは、3回元に戻したあと2回やり直したので16です。
書き出しには、元に戻す側の値と今の値が入り、やり直す側に残っている18は入りません。

## 実装のヒント

```java
// 課題1: 境界を付けると、T型の値に対してcompareToを呼べる
public class Ranking<T extends Comparable<T>> {
    public int add(T item) {
        int position = 0;
        while (position < entries.size() && entries.get(position).compareTo(item) >= 0) {
            position++;
        }
        // ...
    }
}

// 課題2: 入れる先の引数は? super T
public void exportTo(Collection<? super T> dest) {
    dest.addAll(undoValues);
    dest.add(current);
}
```

- 境界を付けない`<T>`のままだと、`T`は`Object`のメソッドしか呼べないので、`compareTo`がコンパイルエラーになる
- `compareTo`は、自分が大きければ正の数、小さければ負の数、等しければ0を返す
- 値を取り出して使う引数は`? extends T`、値を入れる先の引数は`? super T`にする（PECS原則）
- ジェネリックメソッドは、戻り値の型の前に`<T extends Comparable<T>>`や`<A, B>`を書く。呼び出すときの型引数は、引数から推論される
- `var memo = new History<String>("買い物");`のように右辺に型引数を書けば、`var`を使っても型がわかる。`var list = new ArrayList<>();`のように`var`と`<>`（ダイヤモンド演算子）を組み合わせると、型引数が`Object`になってしまう

## 応用のポイント

1. 1つのクラスを複数の型に
    - 型ごとに`IntegerRanking`や`StringHistory`を書かずに済み、しかも`Object`を使ったときのようなキャストも要らない
2. 境界は「使いたいメソッド」から決める
    - 比べたいから`Comparable<T>`、という順に考える
3. ワイルドカードで受け取れる型を広げる
    - `exportTo(Collection<T>)`のままだと、`History<Integer>`から`List<Number>`へは書き出せない
