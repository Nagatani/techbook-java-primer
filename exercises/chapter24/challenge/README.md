# 第24章 チャレンジ課題 - 大学院生も成績を持てるようにする

## 課題概要

付録Dのフェーズ6（`appendix/d-integrated-project/phase6/`）のアプリケーションでは、大学院生（`GraduateStudent`）が成績を持てず、データベースにも保存できません。
第24章の事例2で見たとおり、原因は「大学院生かどうか」と「成績を持つかどうか」を、1本の継承の木で表していることにあります。

フェーズ6のアプリケーションを直し、大学院生も成績を持ち、保存・読み込みができるようにしてください。

## 要件

- 学部生も大学院生も、成績を記録・削除でき、GPAを計算できる
- 大学院生の研究分野と指導教員も、データベースに保存し、次に起動したときに読み込める
- 画面で学生を追加するときに、学部生か大学院生かを選べる。大学院生なら研究分野と指導教員を入力する
- 一覧表に在籍区分の列を加える
- 学部生だけを扱っていたときの機能（検索・絞り込み・CSVの取り込みと書き出し）は、これまでどおり動く
- 設計判断記録を1つ書く（継承の階層をどう直したか、選ばなかった案は何か）

## 進め方のヒント

- 一度に書き換えず、第25章の「初版から改善版へ移す」の手順のように、小さく変えては動かして確かめる
- 第24章のサンプルコード24-1のように、在籍区分をsealedインターフェイスとRecordにし、成績を`Transcript`に任せる設計が一案。`GradeableStudent`に大学院生用のフィールドを足す案、`GraduateStudent`に`Gradeable`を実装させる案と比べてみる
- データベースの`students`表に列が増える。以前の版で作った`student_management.db`は表の構造が違うので、削除してから起動するか、書き出したCSVから取り込み直す
