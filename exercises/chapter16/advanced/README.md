# 第16章 発展課題

## 学習目標
- 複数のクライアントが同時に接続するサーバーを、スレッドプールとスレッドセーフなコレクションで作る
- コマンドと本文を区別する、自分たちの通信手順（プロトコル）を決めて実装する
- `DataInputStream`・`DataOutputStream`で、文字列・数値・バイト列を決まった順に送受信する
- `HttpClient`で、HTTPメソッド・ヘッダー・ステータスコードを扱う
- 接続の失敗や途中の切断を、例外処理とtry-with-resourcesで扱う

## 課題一覧

### 課題1: チャットアプリケーション
**ファイル**（解答例は`../solutions/`にあります）:
```
solutions/
├── ChatServer.java  チャットサーバー
└── ChatClient.java  チャットクライアント
```

複数のクライアントのあいだでメッセージをやりとりするチャットを作成してください。
第16章のチャットサーバー（サンプルコード16-9、16-10）に、ユーザー名・個人あてのメッセージ・履歴を加えたものです。

**要求仕様**:
- サーバー
    - クライアントごとの処理をスレッドプールのスレッドで行う
    - 接続したらユーザー名を受け取り、ほかのユーザーと重なる名前は断る
    - ユーザー名と接続の対応を`ConcurrentHashMap`で管理する
    - 入室・退室をほかのユーザーに知らせる
    - `/`で始まる行はコマンドとして扱う（`/list`で接続中のユーザー、`/pm 名前 本文`で個人あてのメッセージ、`/history`で直近のメッセージ、`/quit`で退室）
    - 直近のメッセージを決まった件数だけ残しておき、`/history`で返す
- クライアント
    - 受信用のスレッドと、キーボードから読んで送るメインのスレッドを分ける
    - 終了するときは、受信用のスレッドを終わらせてからソケットを閉じる

解答例のサーバーには、このほかにチャットルーム（`/join`、`/leave`、`/rooms`）があります。

**実行例**: サーバーと2つ以上のクライアントを別々のターミナルで起動し、片方のクライアントで送ったメッセージが、もう片方に表示されることを確かめます。
画面の表示は操作によって変わるので、ここでは出力を載せていません（起動の手順は「コンパイルと実行」）。

### 課題2: ファイル転送
**ファイル**（このフォルダーのファイルは解答例です）:
```
advanced/task2-file-transfer/
├── FileTransferServer.java  ファイルを受け取って保存するサーバー
├── FileTransferClient.java  ファイルを送るクライアント
├── TransferResult.java      1つのファイルを送った結果（レコード）
└── FileTransferDemo.java    サーバーとクライアントを1つのプログラムで動かす確認用のmain
```

TCPでファイルを送り、受け取った側が同じ内容を保存できたかを確かめるプログラムを作成してください。

**要求仕様**:
- 通信の手順
    - クライアントは、ファイル名（`writeUTF`）、ファイルの大きさ（`writeLong`）、中身の順に送る
    - サーバーは、受け取ったバイト数とチェックサム（どちらも`writeLong`）を返す
- サーバー
    - 接続ごとの受信をスレッドプールで行い、複数のファイルを同時に受け取れる
    - 中身は8KBずつ読み、受け取りながらファイルに書き込む（大きなファイルを一度にメモリに読み込まない）
    - ファイル名からフォルダーの部分を取り除き、保存先のフォルダーの外に書き込ませない
    - 大きさが上限（100MB）を超えるファイルは受け取らない
- クライアント
    - 8KBずつ送り、25%進むごとに進み具合を知らせる
    - 自分で計算したチェックサムとサーバーが返した値、送った大きさと受け取られた大きさを比べて、成功したかを判定する
- 確認用のmain（`FileTransferDemo`）
    - 一時フォルダーに送るファイルを作り、ポート番号0でサーバーを起動する
    - 1つのファイルを進み具合つきで送ったあと、3つのファイルを`ExecutorService`で同時に送る
    - 受け取ったファイルが元のファイルと同じ内容かを確かめ、最後に一時フォルダーを消す

**実行例**:
```
=== 1つのファイルを送る ===
  photo.bin: 25%
  photo.bin: 50%
  photo.bin: 75%
  photo.bin: 100%
  photo.bin 300,000バイト: 成功（大きさ・チェックサムが一致）

=== 3つのファイルを同時に送る ===
  report.txt 190,893バイト: 成功（大きさ・チェックサムが一致）
  music.bin 1,000,000バイト: 成功（大きさ・チェックサムが一致）
  memo.txt 611バイト: 成功（大きさ・チェックサムが一致）

=== 受け取ったファイル ===
  memo.txt 611バイト 元のファイルと同じ
  music.bin 1,000,000バイト 元のファイルと同じ
  photo.bin 300,000バイト 元のファイルと同じ
  report.txt 190,893バイト 元のファイルと同じ
```

3つのファイルを送り終える順序は実行ごとに変わりますが、結果は`Future`を投入した順に受け取るので、表示は変わりません。

### 課題3: REST APIクライアント
**ファイル**: `RestApiClient.java`（解答例はありません）

`HttpClient`で、Web APIにデータを問い合わせたり送ったりするクライアントを作成してください。
第16章の「JSON APIクライアントの実装」（サンプルコード16-11）を発展させる課題です。

**要求仕様**:
- GET・POST・PUT・DELETEのリクエストを送るメソッドを持つ
- POSTとPUTでは、JSONの文字列を本文として送り、`Content-Type: application/json`を付ける
- 認証が必要なAPIのために、`Authorization: Bearer トークン`のヘッダーを付けられる
- ステータスコードが200番台でなければ、コードと本文を含む例外を投げる
- 接続とリクエストにタイムアウトを設定する
- 複数のGETを`sendAsync`で同時に送り、`CompletableFuture.allOf`ですべての応答を待つ

JSONは文字列のまま扱っても、Jacksonで変換してもかまいません。
Jacksonは外部ライブラリで、プロジェクトへの追加方法は第22章で学びます。
試す相手には、認証の要らない公開のテスト用APIを使います。
GETだけなら、チャレンジ課題のHTTPサーバーを相手に試せます。

## 実装のヒント

```java
// 受け取る側: 大きさの分だけ読む。readの戻り値は、要求より少ないことがある
long received = 0;
while (received < size) {
    int n = in.read(buffer, 0, (int) Math.min(buffer.length, size - received));
    if (n == -1) {
        throw new EOFException("ファイルの途中で接続が切れました");
    }
    file.write(buffer, 0, n);
    received += n;
}
```

- ファイルの中身の前に大きさを送るので、受け取る側はどこまでがファイルかがわかる。ソケットを閉じなくても、続けて返事を送れる
- `in.read(buffer)`は、配列がいっぱいになる前に戻ることがある。戻り値の数だけを書き込む
- チェックサムには`java.util.zip.CRC32`が使える。`update(配列, 位置, 長さ)`で少しずつ足し込み、`getValue()`で値を取り出す
- 受け取ったファイル名は信用しない。`Path.of(名前).getFileName()`で最後の部分だけを使うと、`../`で保存先の外を指されても書き込まない
- サーバーのポート番号に0を指定すると、空いているポートが選ばれる。実際の番号は`getLocalPort()`で調べる
- チャットのクライアントでは、受信用のスレッドが`readLine()`で待っているあいだにソケットを閉じない。サンプルコード16-10と同じく、`shutdownInput()`と`join()`で受信用のスレッドを終わらせる
- REST APIクライアントの非同期のリクエストは、サンプルコード16-6の`sendAsync`と同じ形で書ける

## 応用のポイント

1. 通信の手順を先に決める
    - どちらが何をどの順で送るかを決めておくと、サーバーとクライアントを別々に作って組み合わせられる
2. 相手の入力を信用しない
    - ファイル名やファイルの大きさは、相手が好きな値を送ってくる。保存先の外への書き込みや、上限を超える大きさを断る
3. 同時に動くクライアント
    - サーバーは接続ごとの処理をスレッドプールで動かすので、共有するデータ（チャットのユーザーの一覧など）はスレッドセーフにする
