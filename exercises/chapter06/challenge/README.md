# 第6章 チャレンジ課題

## 学習目標
- 省略できる値の多い不変クラスを、ビルダーパターンで組み立てる
- 1つずつの値はビルダーのメソッドで、値の組み合わせは`build()`でまとめて検証する
- 不変クラスのルール（`final`クラス、`private final`のフィールド、setterなし、コンストラクターで初期化を終える、防御的コピー）をすべて満たす
- 既存のオブジェクトの一部だけを変えた新しいオブジェクトを、`toBuilder()`で作る
- 不変オブジェクトのリストを持つ注文クラスを作り、`equals`で同じ内容のものを数える

## 課題一覧

### 課題1: カフェのドリンク注文
**ファイル**（このフォルダーのファイルは解答例です）:
```
challenge/
├── Drink.java      ドリンク1杯（不変クラス）と、それを組み立てるDrink.Builder
├── CafeOrder.java  1回の注文（不変クラス）
└── CafeApp.java    mainメソッド
```

サイズやトッピングを選べるカフェのドリンクと、その注文を作成してください。

**要求仕様**:
- `Drink`（ドリンク）
    - 名前・基本の値段・サイズ（S・M・L）・追加のショットの数・ミルク（普通・豆乳・なし）・トッピングのリスト・アイスかどうかを持つ不変クラスにする
    - サイズやミルクの選択肢、上限の数は`public static final`の定数にする（列挙型は第8章で学ぶので、ここでは文字列の定数を使う）
    - コンストラクターは`private`にし、`Drink.Builder`の`build()`からだけ作れるようにする
    - 値段は「基本の値段 + サイズの差額（S -50円、M 0円、L +60円）+ ショット1つ60円 + 豆乳50円 + トッピング1つ50円」で計算する
    - `getToppings()`はリストのコピーを返す
    - `toBuilder()`で、同じ内容が入ったビルダーを返す。これで一部だけを変えた1杯を作る
    - `equals`・`hashCode`・`toString`をオーバーライドする。`toString`は「アイスモカ(L) ショット+1 ミルク:豆乳 [ホイップ, チョコソース] 770円」の形にし、標準の値（ショット0、ミルク普通、トッピングなし）は書かない
- `Drink.Builder`（ビルダー）
    - 必須の値（名前・基本の値段）はコンストラクターで受け取る。それ以外は標準の値（M・ショット0・普通・トッピングなし・ホット）を持つ
    - `size`・`shots`・`milk`・`addTopping`・`iced`は`this`を返し、呼び出しをつなげられるようにする。範囲の外の値（ショット3以上、決まっていないサイズなど）では`IllegalArgumentException`を投げる
    - `build()`で値の組み合わせを確かめる。トッピングが4つ以上、ミルクなしにホイップを載せるときは`IllegalStateException`を投げる
    - `build()`のあとでビルダーにトッピングを足しても、作ったドリンクは変わらないようにする
- `CafeOrder`（注文）
    - お客さんの名前とドリンクのリストを持つ不変クラス
    - `withDrink(ドリンク)`は、ドリンクを足した新しい注文を返す
    - `countOf(ドリンク)`は、`equals`で等しいドリンクの杯数を返す
    - 3杯以上で合計から100円を引く。小計・割引・合計を表示する

**実行例**:
```
=== ドリンクを組み立てる ===
標準のまま: ホットラテ(M) 450円
指定あり:   アイスモカ(L) ショット+1 ミルク:豆乳 [ホイップ, チョコソース] 770円

=== 一部だけ変えた1杯を作る ===
変えた1杯: ホットモカ(S) ショット+1 ミルク:豆乳 [ホイップ, チョコソース] 660円
元の1杯:   アイスモカ(L) ショット+1 ミルク:豆乳 [ホイップ, チョコソース] 770円

=== ビルダーを使い回す ===
1杯目: ホット抹茶ラテ(M) [白玉] 530円
2杯目: ホット抹茶ラテ(M) [白玉, あずき] 580円

=== 受け取ったリストを書き換える ===
受け取ったリスト: []、モカのトッピング: [ホイップ, チョコソース]

=== 注文 ===
  佐藤様のご注文
    1. ホットラテ(M) 450円
    2. アイスモカ(L) ショット+1 ミルク:豆乳 [ホイップ, チョコソース] 770円
    3. ホットラテ(M) 450円
    小計 1670円、割引 100円、合計 1570円
  標準のラテ: 2杯
  最初の注文は空のまま: 0杯
```

「ビルダーを使い回す」では、1杯目を作ったあとのビルダーにあずきを足しています。
`Drink`のコンストラクターがトッピングのリストをコピーしているので、1杯目は白玉だけのままです。

## 実装のヒント

```java
public final class Drink {
    private final List<String> toppings;

    private Drink(Builder builder) {
        // ビルダーのリストをそのまま使うと、build()のあとの変更が入り込む
        this.toppings = new ArrayList<>(builder.toppings);
    }

    public Builder toBuilder() {
        Builder builder = new Builder(name, basePrice).size(size).shots(shots).milk(milk).iced(iced);
        for (String topping : toppings) {
            builder.addTopping(topping);  // ビルダーには別のリストに入れる
        }
        return builder;
    }

    public static class Builder {
        private String size = SIZE_M;  // 標準の値
        // ...
    }
}
```

- `Builder`は`Drink`の中に`static`を付けて書いたクラス（静的ネストクラス）で、外からは`new Drink.Builder(...)`と書く。くわしくは第8章で学ぶ。`Drink`の中にあるので、`Drink`の`private`のコンストラクターを呼べる
- 1つの値だけで決まる検証（ショットの数など）はビルダーのメソッドに、複数の値の組み合わせで決まる検証（ミルクなしとホイップ）は`build()`に書く
- `toBuilder()`のあとで変更しても元のドリンクが変わらないのは、`Drink`が不変だから。ビルダーは可変で、ドリンクは不変という役割の分け方を確かめる
- 例外を受け止める方法（`try`〜`catch`）は第13章で学ぶ。`main`では正しい値で組み立て、不正な値を渡すと例外で止まることは個別に試して確かめる
- `equals`は第5章のサンプルコード5-15と同じ形で書く。トッピングのリストは`List`の`equals`で、要素を順に比べられる

## 応用のポイント

1. 読みやすい組み立て
    - `new Drink.Builder("モカ", 500).size(Drink.SIZE_L).shots(1)`のように、どの値が何かが名前でわかる。引数が7つ並ぶコンストラクターより読みまちがえにくい
2. 作ったあとは変わらない
    - ビルダーで値を集め、`build()`で一度に不変オブジェクトを作る。作られたドリンクは、ビルダーを使い回しても変わらない
3. 一部だけを変える
    - `toBuilder()`を使うと、値の多いオブジェクトでも、変えたい値だけを書いて新しいオブジェクトを作れる

## 発展（任意）

- サイズごとに上限のショットの数を変える（Sは1まで、M・Lは2まで）。どのメソッドで確かめるのがよいかを考える
