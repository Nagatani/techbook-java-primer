# 第4章 チャレンジ課題

## 学習目標
- クラスを役割ごとにパッケージへ分け、別のパッケージから`import`して使う
- `public`・`private`・パッケージプライベート（修飾子なし）を使い分けて、決まった入り口からしか状態を変えられないようにする
- `this(...)`でコンストラクターを呼び出し、オーバーロードで呼び出し方を増やす
- コンストラクターで値を検証し、不正なオブジェクトを作らせない
- 責任を1つのクラスに集めすぎない（第4章の節「神クラス（Godクラス）の問題」）

## 課題一覧

### 課題1: ホテルの客室予約システム
**ファイル**（このフォルダーのファイルは解答例です）:
```
challenge/
└── hotel/
    ├── domain/
    │   ├── Room.java         客室（番号・種類・1泊の料金・埋まっている日）
    │   ├── Guest.java        宿泊客（名前・電話番号）
    │   ├── Reservation.java  1件の予約
    │   └── Hotel.java        客室と予約をまとめて管理する
    └── app/
        └── HotelApp.java     hotel.domainのクラスを使うプログラム（mainメソッド）
```

ある月（1日〜31日）の客室の予約を管理するプログラムを作成してください。
予約に関わるクラスは`hotel.domain`パッケージに、それを使う`main`メソッドは`hotel.app`パッケージに置きます。

**要求仕様**:
- `Room`（客室）
    - 部屋番号・種類（シングル・ダブル・スイート）・1泊の料金を持ち、どの日の夜が埋まっているかを記録する
    - 料金を省いたコンストラクターでは、種類ごとの標準の料金（シングル8000円・ダブル12000円・スイート30000円）にする。`this(...)`で、料金を指定するコンストラクターを呼ぶ
    - 部屋番号が0以下、料金が0以下などの不正な値では`IllegalArgumentException`を投げる
    - 「何日から何泊が空いているか」を調べるメソッドは`public`にする。予約で埋める・空けるメソッドはパッケージプライベートにして、`hotel.app`から呼べないようにする
- `Guest`（宿泊客）
    - 名前と電話番号を持つ。電話番号を省いたコンストラクターも用意する
    - 名前が空、電話番号に数字とハイフン以外が含まれるときは`IllegalArgumentException`を投げる
- `Reservation`（予約）
    - 予約番号（`R001`からの連番）・宿泊客・客室・泊まり始める日・泊数・取り消したかどうかを持ち、料金の合計を計算する
    - コンストラクターはパッケージプライベートにして、`Hotel`を通してしか予約を作れないようにする
- `Hotel`（ホテル）
    - 客室と予約を配列で管理する
    - 空室の表示を、3つのオーバーロードで用意する（期間だけ／期間と種類／期間と種類と料金の上限）。条件の少ないメソッドは、条件の多いメソッドに処理を任せる
    - 予約する。部屋がない・期間が1日〜31日に収まらない・すでに埋まっているときは予約せず`null`を返す
    - 予約番号で取り消す。取り消した部屋は、ふたたび予約できるようになる
    - 予約の一覧と、取り消していない予約の売上を表示する

**実行例**:
```
=== ホテル青葉 ===
10日から2泊で空いている部屋:
  101号室（シングル、1泊8000円）
  102号室（シングル、1泊7000円）
  201号室（ダブル、1泊12000円）
  301号室（スイート、1泊30000円）

予約しました: R001 田中太郎様 102号室 10日から2泊 14000円
予約できませんでした
予約しました: R002 鈴木花子様 101号室 11日から3泊 24000円
予約できませんでした

11日から1泊で空いているシングル:
  条件に合う空室はありません
11日から1泊で1泊15000円以下の空室:
  201号室（ダブル、1泊12000円）

R001の取り消し: 取り消しました
R001の取り消し: 取り消せません
予約しました: R003 鈴木花子様 102号室 11日から1泊 7000円

予約の一覧:
  R001 田中太郎様 102号室 10日から2泊 14000円（取り消し済み）
  R002 鈴木花子様 101号室 11日から3泊 24000円
  R003 鈴木花子様 102号室 11日から1泊 7000円
売上: 31000円
```

## コンパイルと実行

`challenge/`フォルダーで、次のように実行します。
`-d out`で、パッケージに合わせたフォルダー構成のクラスファイルが`out/`の下にできます。

```bash
javac -d out hotel/domain/*.java hotel/app/*.java
java -cp out hotel.app.HotelApp
```

## 実装のヒント

```java
public class Room {
    // 料金を省いたときは、種類ごとの標準の料金で、もう1つのコンストラクターを呼ぶ
    public Room(int number, String type) {
        this(number, type, standardPrice(type));
    }

    // 修飾子を付けないと、同じパッケージ（hotel.domain）からだけ呼べる
    void occupy(int checkIn, int nights) {
        // checkIn日からnights泊の夜を埋める
    }
}
```

- 埋まっている日は`boolean`の配列（大きさ32、0番は使わない）で持つと、`occupied[日]`で調べられる
- `checkIn`日から`nights`泊すると、埋まるのは`checkIn`日〜`checkIn + nights - 1`日の夜
- 予約番号の連番は、すべての予約で共有する`static`のフィールドで数える。`"%03d".formatted(番号)`で3桁にそろえられる
- `hotel.app`で`new Reservation(...)`や`room.occupy(...)`と書いて、コンパイルエラーになることを確かめる
- 不正な値で投げた例外を受け止める方法（`try`〜`catch`）は第13章で学ぶ。ここでは、正しい値で呼び出すプログラムを書く。予約が埋まっているなど、ふつうに起きる失敗は例外ではなく`null`や`false`で知らせる
- 配列を`return`で外へ渡すと、受け取った側が中身を書き換えられる。これを防ぐ方法は第6章で学ぶので、ここでは配列を返さず、`Hotel`の中で表示する

## 応用のポイント

1. 入り口を1つにする
    - 客室を埋める処理を`Hotel`にだけ許すと、「予約がないのに埋まっている部屋」は作れなくなる
2. パッケージとアクセス修飾子
    - パッケージプライベートは「同じパッケージの仲間には見せるが、外には見せない」範囲を作る
3. オーバーロードの処理を1か所に
    - 条件の少ないメソッドが条件の多いメソッドを呼ぶと、絞り込みの処理を1か所に書くだけで済む
