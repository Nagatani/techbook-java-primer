# 第7章 チャレンジ課題

## 学習目標
- 共通のデータと処理を抽象クラスにまとめ、商品ごとに違う値を抽象メソッドで子クラスに任せる
- 一部の商品だけが持つ能力をインターフェイスで表し、defaultメソッドとstaticメソッドで処理を提供する
- 抽象クラスを継承しながら、インターフェイスも実装する
- オブジェクトの作り方をファクトリに隠し、呼び出し側を具体的なクラスから切り離す（Simple Factory）

## 課題一覧

### 課題1: コンビニのレジ
**ファイル**（このフォルダーのファイルは解答例です）:
```
challenge/
├── Item.java          商品（抽象クラス）
├── Discountable.java  値引きできる（インターフェイス）
├── Food.java          食品（軽減税率、値引きできる）
├── Drink.java         飲み物（お茶などは軽減税率、酒類は標準税率）
├── DailyGoods.java    日用品（標準税率）
├── ItemFactory.java   商品マスターの1行から商品を作るファクトリ
├── Register.java      レジ
└── RegisterApp.java   mainメソッド
```

商品マスターの行から商品を作り、レジで読み取ってレシートを表示するプログラムを作成してください。
消費税は、食品と、酒類を除く飲み物が軽減税率（8%）、それ以外が標準税率（10%）です。
税額は商品ごとではなく、税率ごとの合計金額に税率をかけて求めます（1円未満は切り捨て）。

**要求仕様**:
- `Item`（抽象クラス）
    - 商品コード・名前・税抜きの定価を持つ
    - 税率を返す`taxRate()`と種類の名前を返す`category()`を抽象メソッドにする
    - 実際に売る税抜きの価格`salePrice()`は、定価を返すメソッドとして書く（値引きのある商品がオーバーライドする）
    - レシートの1行を返す`receiptLine()`を持つ。軽減税率の商品には先頭に「※」を付ける
- `Discountable`（インターフェイス）
    - 抽象メソッド`discountPercent()`（値引き率）
    - defaultメソッド`applyDiscount(int price)`（値引き後の金額、1円未満は切り捨て）と`isDiscounted()`
    - staticメソッド`isValidPercent(int percent)`（0〜50%なら使える）
- 商品クラス
    - `Food`: `Item`を継承し、`Discountable`を実装する。税率8%。範囲外の値引き率は0%として扱う。`salePrice()`は`applyDiscount`で値引きした金額にし、値引きしているときはレシートの行に「（30%引き）」のように付け足す
    - `Drink`: 酒類かどうかを持ち、酒類なら10%、そうでなければ8%
    - `DailyGoods`: 10%
- `ItemFactory`
    - `create(String line)`で「種類,商品コード,名前,税抜き価格」の行から商品を作る。食品だけは末尾に値引き率を書ける
    - 種類は「食品」「飲料」「酒類」「日用品」。知らない種類や項目の足りない行には`null`を返す
- `Register`（レジ）
    - 商品を`Item`型の配列で持つ
    - 税率ごとの税抜き合計・税額・総額を求める。この計算では商品の種類を調べない
    - 値引きした金額の合計を求める。ここだけ`instanceof Discountable`で調べる
    - 預かった金額を受け取り、レシートを表示する

**実行例**:
```
=== 商品の登録 ===
F01 幕の内弁当（食品、税率8%）
F02 おにぎり 鮭（食品、税率8%）
D01 緑茶 500ml（飲料、税率8%）
D02 缶ビール 350ml（酒類、税率10%）
G01 ボールペン（日用品、税率10%）
登録できません: 文具,S01,ノート,150

---------- レシート ----------
※幕の内弁当  385円（30%引き）
※おにぎり 鮭  160円
※緑茶 500ml  140円
  缶ビール 350ml  220円
  ボールペン  120円
------------------------------
  8%対象 685円（消費税 54円）
 10%対象 340円（消費税 34円）
  合計   1113円
  （値引き 165円）
  お預かり 2000円
  お釣り   887円
  ※は軽減税率（8%）の対象です

=== 値引き率の確認 ===
30%: true
80%: false
※サンドイッチ  300円 ← 範囲外の値引き率は使わない
```

「文具」はファクトリが知らない種類なので登録されません。
最後のサンドイッチは値引き率80%で作ろうとしたため、値引きなしになります。

## 実装のヒント

```java
public class Food extends Item implements Discountable {
    @Override
    public int taxRate() {
        return 8;
    }

    // Discountableのdefaultメソッドで値引きした金額を、売る価格にする
    @Override
    public int salePrice() {
        return applyDiscount(getPrice());
    }
}

public class ItemFactory {
    public static Item create(String line) {
        String[] f = line.split(",");
        // ...
        return switch (f[0]) {
            case "食品" -> new Food(/* ... */);
            case "酒類" -> new Drink(code, name, price, true);
            // ...
            default -> null;
        };
    }
}
```

- `extends`と`implements`は同時に書ける。順序は`extends`が先
- `Register`の合計の計算は、`taxRate()`と`salePrice()`を呼ぶだけにする。食品か飲み物かは、各クラスのオーバーライドが受け持つ
- `isValidPercent`はオブジェクトを作る前に使うので、defaultメソッドではなくstaticメソッドにする。`Discountable.isValidPercent(30)`と呼ぶ
- ファクトリのメソッドの戻り値の型は`Item`にする。呼び出し側は`Food`や`Drink`のコンストラクターを知らなくてよい
- 税抜き合計に税率をかけて100で割ると、整数の割り算なので1円未満が切り捨てられる

## 応用のポイント

1. 抽象クラスとインターフェイスの組み合わせ
    - すべての商品が持つもの（コード・名前・価格・税率）は抽象クラス、一部の商品だけが持つ能力（値引き）はインターフェイスにした
2. 種類を調べない合計
    - 新しい種類の商品（例: 税率10%の「雑誌」）を足しても、`Register`を直さなくてよい
3. ファクトリの効果
    - 商品の種類を増やしても、変更するのは新しいクラスと`ItemFactory`だけで、`RegisterApp`は変わらない

## 発展（任意）

- `DailyGoods`にも`Discountable`を実装し、「2割引きセール」のような値引きをできるようにする。`Register`の変更が要らないことを確かめる
- レシートの各行の金額を、`Item`のメソッドで税込みにして表示する。税率ごとにまとめて計算した税額と、行ごとに計算した税額の合計がずれる場合があることを確かめる
