### 課題1: 図形の抽象クラス

**ファイル**: `Shape.java`、`Circle.java`、`Rectangle.java`、`ShapeDemo.java`

抽象クラス`Shape`を継承して、円と長方形のクラスを完成させます。

**要求仕様**:

- `Shape`の抽象メソッド`calculateArea`（面積）と`calculatePerimeter`（周囲の長さ）を、`Circle`と`Rectangle`で実装する
- 情報の表示（`displayInfo`）は`Shape`に書いた共通の処理を使う。面積と周囲の長さは小数点以下2桁で表示する
- `ShapeDemo`では、円（半径5.0）と長方形（幅4.0・高さ6.0）の情報を表示し、`Shape`型の配列に4つの図形を入れて面積の合計を求める
- `new Shape(...)`がコンパイルエラーになることを確かめる

**実行例**:

```
=== 図形デモプログラム ===

図形: 円
面積: 78.54
周囲の長さ: 31.42

図形: 長方形
面積: 24.00
周囲の長さ: 20.00

=== ポリモーフィズムのデモ ===
円: 面積 78.54
長方形: 面積 24.00
円: 面積 3.14
長方形: 面積 4.00

=== 面積の合計計算 ===
全図形の面積の合計: 109.68
```

### 課題2: 支払いのインターフェイス

**ファイル**: `Payable.java`、`Employee.java`、`Invoice.java`、`PayableDemo.java`

従業員と請求書という、継承の関係にない2つのクラスに、インターフェイス`Payable`を実装させます。

**要求仕様**:

- 従業員の支払い金額は「基本給＋基本給×ボーナス率」、請求書の支払い金額は「数量×単価」
- 請求書のコンストラクターは、負の数量と単価を0にする
- `Payable`のデフォルトメソッド`displayPaymentInfo`で、支払い金額を表示する
- `Payable`型の配列で、従業員と請求書の支払い金額をまとめて合計する

### 課題3: 動物の行動のインターフェイス

**ファイル**: `Flyable.java`、`Swimmable.java`、`Walkable.java`、`Bird.java`、`Fish.java`、`Duck.java`、`AnimalInterfaceTest.java`（新しく作る）

飛ぶ・泳ぐ・歩くという行動をインターフェイスにして、動物ごとに組み合わせます。

**要求仕様**:

- `Flyable`は飛ぶ高さを返す抽象メソッド`getAltitude`と、デフォルトメソッド`fly`を持つ。`Swimmable`も同じように`getDepth`と`swim`を持つ
- `Walkable`は抽象メソッドを持たず、デフォルトメソッド`walk`だけを持つ
- `Bird`は飛ぶ・歩く（高度100m）、`Fish`は泳ぐ（深度10m）、`Duck`は飛ぶ・泳ぐ・歩く（高度50m・深度2m）
- `Flyable`型の配列で、飛べる動物をまとめて飛ばす

**実行例**:

```
=== 動物行動インターフェイステスト ===
鳥の行動:
空を飛んでいます（高度: 100m）
地面を歩いています

魚の行動:
水中を泳いでいます（深度: 10m）

アヒルの行動:
空を飛んでいます（高度: 50m）
水中を泳いでいます（深度: 2m）
地面を歩いています

飛べる動物:
空を飛んでいます（高度: 100m）
空を飛んでいます（高度: 50m）
泳げる動物の数: 2
```

### 課題4: 通知とログのインターフェイス

**ファイル**: `Notifiable.java`、`Loggable.java`、`LogCounter.java`、`EmailNotifier.java`、`SMSNotifier.java`、`SystemLogger.java`、`NotificationTest.java`（新しく作る）

通知を送る機能とログを残す機能を、別々のインターフェイスにして組み合わせます。

**要求仕様**:

- `Notifiable`のデフォルトメソッド`notify`は「[EMAIL] メッセージを送信しました: …」の形で表示する。送り先の種類は抽象メソッド`getChannel`で返す
- `Loggable`のデフォルトメソッド`log`は「[LOG] 送り元: …」の形で表示し、記録した件数を数える。件数は静的メソッド`Loggable.totalLogs()`で返す
- `EmailNotifier`と`SMSNotifier`は両方のインターフェイスを実装し、`notify`をオーバーライドして、通知のあとにログを残す（`Notifiable.super.notify(message)`で元の処理を呼ぶ）
- `SystemLogger`は`Loggable`だけを実装する

**実行例**:

```
=== 通知システム複合インターフェイステスト ===
Emailによる通知:
[EMAIL] メッセージを送信しました: システム開始
[LOG] Email送信: システム開始

SMSによる通知:
[SMS] メッセージを送信しました: エラー発生
[LOG] SMS送信: エラー発生

システムログ:
[LOG] システム情報: 処理完了

ログを記録できるもの: 3種類
記録したログ: 3件
```

## ヒント

- 抽象クラスは`new`できない。`Shape s = new Circle(5.0);`のように、サブクラスのオブジェクトを抽象クラスの型の変数に入れて使う
- サブクラスで抽象メソッドを1つでも実装し忘れると、コンパイルエラーになる
- インターフェイスのメソッドは、書かなくても`public`になる。実装するクラスでは`public`を付けて書く
- 2つのインターフェイスに同じ名前のデフォルトメソッドがあると、実装するクラスでどちらを使うかを決める（オーバーライドする）必要がある
- インターフェイスのフィールドは定数（`public static final`）になるので、件数のように変わる値は持てない
