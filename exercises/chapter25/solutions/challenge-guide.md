# 第25章 チャレンジ課題 - 解答の方針

この課題にはコードの解答例を用意していません。
ここでは、第25章のサンプルコード25-1の設計に寄せる場合の方針と、変更するファイルを示します。

## 継承の階層の直し方

候補は3つあります。

1. `GraduateStudent`に`Gradeable`を実装させる
    + 変更は小さいが、成績を扱うコードが`GradeableStudent`と`GraduateStudent`に重複する。研究生など区分が増えるたびに同じことを繰り返す
2. `GradeableStudent`に研究分野と指導教員のフィールドを足し、学部生では空にする
    + クラスは1つになるが、学部生にも意味のないフィールドができる。どちらの学生かを見分けるにはnullかどうかを調べることになる
3. 学生のクラスを1つにし、在籍区分（sealedインターフェイスとRecord）と成績表（`Transcript`）を持たせる（合成）
    + 変更は大きいが、区分と成績が独立になる。区分を足したときに直す箇所をコンパイラーが教えてくれる

ここでは3を選ぶ前提で進めます。
どの案を選んだ場合も、設計判断記録に、選ばなかった案とその理由を書いてください。

## 変更するファイルと順序

各手順の終わりで、`Phase6Test`を実行し、画面を少し操作して確かめます。

1. `Enrollment`・`Undergraduate`・`Graduate`・`Grade`・`Transcript`を加える（サンプルコード25-1・25-2から写す）
    + この時点では、まだ誰も使わない。コンパイルできることだけを確かめる
2. `GradeableStudent`の中で成績を`Transcript`に任せる
    + 外から見たメソッドは変えない。`Phase6Test`の結果が変わらないことを確かめる
3. 学生のクラスに在籍区分を持たせる
    + コンストラクターに`Enrollment`を加え、`GraduateStudent`を使っている箇所を在籍区分に置き換える
4. `DatabaseManager`の表を変える
    + `students`表に`kind`・`admission_year`・`research_field`・`advisor`の列を加え、`gpa`列をなくす。読み込みでは`kind`から在籍区分を組み立てる（サンプルコード26-1の`toStudent`が参考になる）
5. 画面を変える
    + 学生の追加のダイアログに区分の選択（`JComboBox`）と研究分野・指導教員の欄を加え、区分に応じて欄を有効・無効にする。一覧表に在籍区分の列を加える
6. 使わなくなったクラスを消す
    + `GraduateStudent`と`Gradeable`を消し、`Phase2Test`のように古いクラスを使う確認のプログラムは、新しいクラスに合わせて直すか、役目を終えたものとして消す

## 注意すること

- GPAの計算方法を単位数で重み付けした平均に変える場合は、成績に単位数が加わり、CSVの形式と成績の入力画面も変わる。この課題では評価点の単純な平均のままにしてもよい（変えない理由を設計判断記録に書く）
- 以前の版で作った`student_management.db`は表の構造が違うので読み込めない。フェーズ6の画面でCSVに書き出してから、新しい版で取り込み直す
