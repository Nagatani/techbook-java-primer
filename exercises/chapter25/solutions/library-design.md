# 研究室の図書貸し出しシステム - 要求と設計判断（解答例）

## ユーザーストーリー

1. 研究室の学生として、論文を書くのに必要な本を探すために、書名や著者で本を検索したい
2. 研究室の学生として、自分の席で読むために、本を借りたことを記録したい
3. 研究室の学生として、次に借りたい人が困らないように、本を返したことを記録したい
4. 本を管理する担当者として、本の行方がわからなくなるのを防ぐために、誰が何を借りているかを一覧で見たい
5. 本を管理する担当者として、長く返されていない本を返してもらうために、返却の期限を過ぎた貸し出しを一覧で見たい
6. 本を管理する担当者として、新しく買った本を貸し出せるように、本を登録したい

## 非機能要求

- 扱う量
    + 本は数百冊（多くても1,000冊）、利用者は研究室の学生20人程度、貸し出しの記録は年に数百件
- 利用者
    + 研究室に置いた1台のパソコンで使う。同時に使うのは1人
- 環境
    + Windows・macOSのどちらでも動く。サーバーは用意しない
- 配布
    + 担当者が交代しても使い続けられるように、ファイルをコピーするだけで動かせる

## 作らないもの

- 予約の機能
    + 研究室の人数なら、借りている人に直接声をかければ足りる
- 利用者のログイン
    + 研究室のパソコンを使えるのは研究室の学生だけなので、この版では氏名を選ぶだけにする
- 本の購入の申請
    + 購入は別の手続き（大学の会計）で行うので、このシステムでは扱わない

## 設計判断記録：本が貸し出し中かどうかの持ち方

- 状況
    + 本の一覧に「貸し出し中」を表示したい（ストーリー4）。また、期限を過ぎた貸し出しを一覧にしたい（ストーリー5）
- 選択肢
    + 案Aは、本のクラスに`boolean onLoan`を持たせ、貸し出しと返却のたびに書き換える。表示は簡単だが、貸し出しの記録と食い違うおそれがある
    + 案Bは、貸し出しの記録（本・借りた人・貸出日・期限・返却日）だけを持ち、返却日のない記録がある本を貸し出し中とみなす。「貸し出し中」は記録から計算で求める
- 決定
    + 案Bを採用する
- 理由
    + ストーリー5のために、どのみち貸し出しの記録（期限）を持つ必要がある。案Aでは同じ情報を2か所に持つことになり、片方だけを書き換える誤りが入りやすい
    + 本は多くても1,000冊、記録は年に数百件なので、一覧を表示するたびに記録から計算しても時間はかからない
- 影響
    + 「本を返す」操作は、本ではなく貸し出しの記録に返却日を書き込む操作になる
    + 同じ本に返却日のない記録が2件できないように、貸し出すときに確かめる
    + 記録が数万件に増えて一覧の表示が遅くなったら、貸し出し中の記録だけを引ける索引（`Map`など）を加えることを検討する
