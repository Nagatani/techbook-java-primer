# 第18章 基本課題

## 学習目標

- ActionListenerで、ボタンの操作に合わせて状態と表示を更新する
- ItemListener・ChangeListener・FocusListenerなど、操作の種類に合ったリスナーを選ぶ
- 状態を持つロジックを画面のクラスから分け、リスナーは「ロジックを呼んで表示を合わせる」だけにする
- アダプタークラス（MouseAdapter・WindowAdapter・FocusAdapter）で、必要なメソッドだけを書く

### 課題1: 入室カウンター

**ファイル**: `task1-counter/Counter.java`、`task1-counter/CounterApp.java`

教室に入った人数を数えるカウンターを作ります。

**要求仕様**:

- `Counter`は画面に依存しないクラスで、0から上限（10）までの値を持ち、増やす・減らす・0に戻す操作と、増やせるか・減らせるかを返すメソッドを持つ
- 「+1」「-1」「リセット」の3つのボタンに、1つのActionListenerを登録する。どのボタンかは`setActionCommand`で付けた名前（`getActionCommand()`）で区別する
- 操作のたびに人数を表示し直す。0人のときは「-1」、上限のときは「+1」を押せなくし（`setEnabled(false)`）、上限に達したことを表示する

**実行例**:

- 起動すると、大きな文字で「0人」と表示され、「-1」は押せない
- 「+1」を押すたびに人数が1ずつ増え、「-1」が押せるようになる
- 10人になると「+1」が押せなくなり、「定員（10人）に達しました」と表示される
- 「リセット」で0人に戻る

### 課題2: ピザの注文

**ファイル**: `task2-pizza/PizzaOrder.java`、`task2-pizza/PizzaApp.java`

選んだ内容に合わせて、合計金額がすぐ変わる注文画面を作ります。

**要求仕様**:

- `PizzaOrder`は、サイズ（S 800円・M 1200円・L 1600円）とトッピング（チーズ増量200円・きのこ150円・コーン100円・ベーコン250円）をenumで持ち、合計金額と注文の説明を返す
- サイズは`JRadioButton`を`ButtonGroup`にまとめ、1つだけ選べるようにする。最初はMを選んでおく
- トッピングは`JCheckBox`で、いくつでも選べる
- どちらもItemListenerで変化を受け取り、注文の説明と合計金額をすぐ表示し直す。ラジオボタンは選択が外れたときにもイベントが届くので、`getStateChange()`が`ItemEvent.SELECTED`のときだけ処理する

**実行例**:

- 起動すると「注文: Mサイズ」「合計: 1200円」と表示される
- Lを選び、ベーコンとチーズ増量にチェックを入れると「注文: Lサイズ＋チーズ増量＋ベーコン」「合計: 2050円」になる。トッピングは選んだ順ではなく、決まった順に並ぶ
- ベーコンのチェックを外すと「合計: 1800円」になる

### 課題3: 色の調合

**ファイル**: `task3-color/ColorApp.java`

赤・緑・青のスライダーで色を作り、見本の色とコードを表示します。

**要求仕様**:

- 赤・緑・青のそれぞれに、0〜255の`JSlider`と`JSpinner`を並べる（最初は255・128・0）
- スライダーのChangeListenerでスピナーの値を合わせ、スピナーのChangeListenerでスライダーの値を合わせる。どちらを動かしても、もう一方が追いかける
- 値が変わるたびに、見本のパネルの背景色と「RGB(255, 128, 0)  #FF8000」の形の表示を更新する
- スライダーをドラッグしている間（`getValueIsAdjusting()`が`true`の間）は「調整中...」と表示する

**実行例**:

- 起動すると見本がオレンジ色になり、「RGB(255, 128, 0)  #FF8000」と表示される
- 青のスライダーを200まで動かすと、青のスピナーも200になり、見本の色と表示が変わる。ドラッグしている間だけ「調整中...」と出る
- 赤のスピナーに10と入力すると、赤のスライダーも10の位置へ動き、「RGB(10, 128, 200)  #0A80C8」になる

### 課題4: 会員登録フォーム

**ファイル**: `task4-member/MemberValidator.java`、`task4-member/MemberFormApp.java`

入力欄を離れたときに内容を検査する登録フォームを作ります。

**要求仕様**:

- `MemberValidator`は、名前（空でない）・年齢（0〜120の整数）・メールアドレス（`@`が1つあり、その後ろに`.`がある）を検査し、正しければ`null`、誤りがあれば理由を返す
- 各入力欄にFocusListener（`FocusAdapter`）を登録する。フォーカスを得たら背景を薄い黄色にし、失ったら検査して、誤りがあれば背景を薄い赤にして理由を表示する
- テキストフィールドでEnterを押すと、ActionListenerで次の欄へフォーカスを移す（`requestFocusInWindow()`）
- 「登録」ボタンにマウスが乗ったとき（`mouseEntered`）と離れたとき（`mouseExited`）で、下の説明の文を切り替える
- 何か入力したあとにウィンドウを閉じようとしたら、`DO_NOTHING_ON_CLOSE`とWindowAdapterの`windowClosing`で確認のダイアログを出す

**実行例**:

- 名前の欄をクリックすると背景が薄い黄色になる
- 年齢に「abc」と入れて次の欄へ移ると、年齢の欄が薄い赤になり「年齢: 年齢は数字で入力してください」と表示される
- 3つの欄を正しく入れて「登録」を押すと、「〜さんを登録しました」のダイアログが出て、欄が空に戻る
- 入力の途中で閉じるボタンを押すと「入力した内容は保存されていません。閉じますか？」と聞かれ、「いいえ」なら閉じない

## コンパイルと実行

課題のフォルダーごとにコンパイルして実行します。

```bash
cd exercises/chapter18/basic/task1-counter
javac *.java
java CounterApp
```

課題2は`PizzaApp`、課題3は`ColorApp`、課題4は`MemberFormApp`を実行します。

## 実装のヒント

- 画面の部品はコンストラクターで組み立て、`main`では`SwingUtilities.invokeLater`でEDTに作らせる（第17章の定型）
- リスナーの中では、ロジックのメソッドを呼んだあと、表示を合わせるメソッド（解答例の`updateView`）を1つだけ呼ぶようにすると、表示の更新漏れが起きにくい
- スライダーとスピナーのように互いに値を合わせるときは、値が同じなら`setValue`してもイベントが起きないので、行き来が止まる
- 入力欄の検査に使うメソッドは`Function<String, String>`としてメソッド参照（`MemberValidator::checkAge`）で渡せる（第11章）
