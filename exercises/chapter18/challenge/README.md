# 第18章 チャレンジ課題

## 学習目標
- ActionListener・KeyListener・WindowListenerを組み合わせて、1つのアプリを組み立てる
- `javax.swing.Timer`で制限時間を数え、時間切れもイベントの1つとして扱う
- アダプタークラス（`KeyAdapter`・`WindowAdapter`）で、必要なメソッドだけを書く
- 進行の状態（出題中・回答済み・終了）をGUIでないクラスで管理し、画面はその状態を表示する
- `SwingUtilities.invokeLater`でEDT上に画面を組み立て、リスナーの中で部品を安全に更新する

## 課題一覧

### 課題1: 制限時間つきクイズ
**ファイル**（このフォルダーのファイルは解答例です）:
```
challenge/
├── Question.java  4択の問題（レコード）
├── Result.java    1問ごとの結果（列挙型）
├── QuizData.java  出題する問題
├── Quiz.java      クイズの進行と採点（GUIなし）
└── QuizApp.java   画面とイベント処理、mainメソッド
```

1問ごとに10秒の制限時間がある4択クイズを作成してください。
ボタンのクリックでも、キーボードの数字キーでも答えられるようにします。

**要求仕様**:
- `Question`は、問題文・4つの選択肢・正解の番号（0〜3）を持つレコードにする。選択肢が4つでない、正解の番号が範囲外のときは例外を投げる
- `Quiz`（GUIに依存しない）
    - 問題の一覧と制限時間（秒）を受け取り、現在の問題・残り時間・1問ごとの結果を管理する
    - `answer(選択肢の番号)`は正解か不正解かを記録して返す。回答済みのときは`null`を返し、何も記録しない
    - `tick()`は1秒たったときに呼ぶ。残り時間を1減らし、0になったら時間切れを記録して返す
    - `next()`は回答済みのときだけ次の問題へ進め、残り時間を戻す
    - 終わったかどうか、途中かどうか、正解数、最初からやり直す`restart()`を持つ
- `QuizApp`（画面）
    - 上に「第2問 / 全5問　残り 7秒　正解 1問」の形の状態と問題文、中央に4つの選択肢のボタン、下に結果のメッセージと「次の問題へ」ボタンを置く
    - `javax.swing.Timer`を1秒ごとに動かし、残り時間を表示する。時間切れになったら回答したときと同じように結果を表示する
    - 回答するか時間切れになったら、タイマーを止め、選択肢のボタンを押せなくし、正解のボタンの背景を薄い緑にする。不正解と時間切れのときは正解を赤い文字で示す
    - 数字キーの1〜4で選択肢を選び、Enterキーで次の問題へ進む（`KeyAdapter`）
    - 最後の問題ではボタンを「結果を見る」にし、押すと1問ごとの結果と正解数をダイアログで示して、もう一度挑戦するかを尋ねる
    - 途中でウィンドウを閉じようとしたら、確認のダイアログを出す（`WindowAdapter`と`DO_NOTHING_ON_CLOSE`）。「いいえ」なら出題中のタイマーを再開する

**実行例**:

`java QuizApp`を実行すると「Javaクイズ」というウィンドウが開き、1問目が表示されます。

- 上の行は`第1問 / 全5問　残り 10秒　正解 0問`で、残りの秒数が1秒ごとに減っていく
- 中央には「1. start」「2. main」「3. run」「4. init」の4つのボタンが2行2列で並ぶ
- 「2. main」をクリックする（またはキーボードの2を押す）と、残り時間が止まり、下に緑の文字で「正解です」と表示される。4つのボタンは押せなくなり、「2. main」の背景が薄い緑になる。上の行は`正解 1問`に変わる
- 「次の問題へ」を押す（またはEnterキーを押す）と2問目が表示され、残り時間が10秒に戻る
- 2問目で何も押さずに10秒たつと、赤い文字で「時間切れです。正解は「ActionListener」」と表示される
- 3問目で「1. mainスレッド」を選ぶと、「不正解です。正解は「イベントディスパッチスレッド」」と表示される
- 5問目に答えるとボタンが「結果を見る」になる。押すと次の内容のダイアログが出る

```
5問中3問正解でした

第1問: 正解
第2問: 時間切れ
第3問: 不正解
第4問: 正解
第5問: 正解

もう一度挑戦しますか？
```

- 「はい」を押すと1問目からやり直し、「いいえ」を押すとアプリが終わる
- 2問目以降でウィンドウの閉じるボタンを押すと、「クイズの途中です。終了しますか？」と確認される。「いいえ」を押すと、残り時間の続きから数え直す

## 実装のヒント

```java
// 時間切れも「イベント」の1つ。回答したときと同じメソッドで結果を表示する
timer = new Timer(1000, e -> {
    Result result = quiz.tick();
    if (result == Result.TIME_UP) {
        showResult(result);
    } else {
        updateStatus();
    }
});

for (int i = 0; i < choiceButtons.length; i++) {
    int index = i;  // ラムダ式の中で使うため、変更しない変数に写す
    choiceButtons[i] = new JButton();
    choiceButtons[i].addActionListener(e -> answer(index));
}
```

- ラムダ式の中からはループ変数`i`を直接使えない（値が変わるため）。ループのたびに新しい変数`index`に写してから使う
- キー入力は、フォーカスを持つ部品に届く。ボタンを`setFocusable(false)`にし、選択肢などを置いたパネルを`setFocusable(true)`にして`requestFocusInWindow()`を呼ぶと、キー入力がそのパネルのKeyListenerに集まる
- ボタンのクリックと数字キーは、どちらも同じ`answer`メソッドを呼ぶ。回答済みかどうかは`Quiz`が判断するので、ボタンを2回押しても結果は1回しか記録されない
- 回答したら、まず`timer.stop()`を呼ぶ。止め忘れると、結果の表示中に時間切れが起きる
- `Quiz`はウィンドウを開かずに動かせる。`answer`・`tick`・`next`を順に呼び、結果が正しく記録されるかを`main`から確かめるとよい

## 応用のポイント

1. 進行の管理を画面から分ける
    - 「回答済みなら答えを受け付けない」「回答してからでないと次へ進めない」という決まりは`Quiz`にあり、画面のクラスは結果を表示するだけである
2. 複数の入力を同じ処理へ
    - マウスのクリック、数字キー、時間切れの3つが、同じ`showResult`で結果を表示する
3. ウィンドウのイベント
    - `DO_NOTHING_ON_CLOSE`にして`windowClosing`で確認すると、途中で閉じてしまう誤操作を防げる
