# 第19章 チャレンジ課題

## 学習目標

- ドラッグ&ドロップ・キーバインディング・プロパティの変化の通知を組み合わせて、1つのアプリを組み立てる
- `TransferHandler`で、リストの項目をほかのリストへ運ぶ
- データを持つクラスが`PropertyChangeSupport`で変化を知らせ、画面はその通知を受けて表示を作り直す

## 課題一覧

### 課題1: タスクボード

**ファイル**（このフォルダーのファイルは解答例です）:

```
challenge/
├── Column.java          列（列挙型）
├── TaskBoard.java       3つの列のタスクと、変化の通知（GUIなし）
├── TaskBoardCheck.java  TaskBoardの動作確認
└── TaskBoardApp.java    画面とイベント処理、mainメソッド
```

「未着手」「作業中」「完了」の3つの列にタスクを並べ、ドラッグで列の間を動かせるボードを作成してください。

**要求仕様**:

- `Column`は、`TODO`・`DOING`・`DONE`の3つの定数と、表示用の名前（未着手・作業中・完了）を持つ列挙型にする
- `TaskBoard`（GUIに依存しない）
    - 列ごとのタスク名のリストを`EnumMap`で持つ
    - `add(名前)`: 前後の空白を除いて、未着手の列の末尾に足す。空の名前と、どこかの列にすでにある名前は足さずに`false`を返す
    - `move(名前, 移す先の列, 位置)`: タスクを別の列の指定した位置へ移す。位置が範囲外（-1など）なら末尾に置く。同じ列の中での並べ替えにも使え、下へ動かすときは取り除いた分だけ位置を1つ前にずらす
    - `remove(名前)`: タスクを消す
    - `find(名前)`: タスクがある列を返す。どこにもなければ`null`
    - 中身が変わるたびに、`PropertyChangeSupport`で`"tasks"`プロパティの変化を知らせる。新しい値は列ごとのタスクの数（`counts()`）にする。`firePropertyChange`は古い値と新しい値が等しいと通知しないので、並べ替えでも通知されるよう、古い値には`null`を渡す
- `TaskBoardApp`（画面）
    - 上に新しいタスクの入力欄と「追加」ボタン、中央に3つの`JList`を並べる。Enterキーでも追加できる
    - `TaskBoard`に`PropertyChangeListener`を登録し、通知が来たら3つのリストのモデル（`DefaultListModel`）を作り直し、「未着手 1 / 作業中 1 / 完了 2」の形で件数を表示する
    - 3つのリストで1つの`TransferHandler`を共有する
        - `getSourceActions`は`MOVE`を返す
        - `createTransferable`は、選んでいるタスクの名前を`StringSelection`に入れて返す
        - `canImport`は、ドロップで文字列が運ばれてきたときだけ`true`を返す
        - `importData`は、ドロップされたリストの列と位置（`JList.DropLocation`の`getIndex()`）を調べて、`TaskBoard`の`move`を呼ぶ。表示はリスナーが作り直すので、`exportDone`で元のリストから消す処理は書かない
    - リストは`setDragEnabled(true)`にし、`setDropMode(DropMode.INSERT)`で項目と項目の間に差し込めるようにする
    - キーバインディング
        - リストでDeleteキー（またはBackSpaceキー）を押すと、選んでいるタスクを消す（`WHEN_FOCUSED`）
        - ウィンドウのどこにいてもCtrl＋Nで入力欄へ移る（ルートペインの`WHEN_IN_FOCUSED_WINDOW`）
    - 起動したときに、4つのタスクを入れておく

**実行例**:

`java TaskBoardApp`を実行すると、「タスクボード」というウィンドウが開きます。

- 未着手に「サンプルコードを動かす」「レポートを書く」、作業中に「演習の課題を読む」、完了に「環境を構築する」が並び、下に「未着手 2 / 作業中 1 / 完了 1」と表示される
- 「レポートを書く」を完了の列へドラッグすると、完了の列に移り、表示が「未着手 1 / 作業中 1 / 完了 2」になる。完了の列の中でドロップした位置に差し込まれる
- 同じ列の中でドラッグすると、順番を入れ替えられる
- 入力欄に「質問をまとめる」と入れてEnterキーを押すと、未着手の列の末尾に追加され、入力欄が空になる。同じ名前をもう一度追加しようとすると「空の名前と、すでにある名前は追加できません」と表示される
- リストのタスクを選んでDeleteキーを押すと消える
- どこにいても、Ctrl＋Nで入力欄にカーソルが移る

`java TaskBoardCheck`を実行すると、追加・移動・削除と通知の届き方を確かめられます（最後に「15件中15件OK」と表示されます）。

## 本文で扱っていないAPI

- `DropMode.INSERT`: ドロップする位置を、項目の上ではなく項目と項目の間にする
- `TransferSupport.isDrop()`: ドラッグ&ドロップによる受け渡しかどうかを調べる（貼り付けのときは`false`になる）
- `getRootPane()`と`JComponent.WHEN_IN_FOCUSED_WINDOW`: ウィンドウ全体で使うキーを、いちばん外側の部品（ルートペイン）に登録する

`JList`と`DefaultListModel`の詳しい使い方は、第20章で学びます。


## 実装のヒント

- ドラッグで運ぶのはタスクの名前（文字列）だけにして、実際の移動は`TaskBoard`に任せる。こうすると、表示を作り直す処理が通知を受けたときの1か所にまとまる
- どのリストにドロップされたかは`support.getComponent()`でわかる。リストと列の対応を`EnumMap`に入れておくと、列を調べられる
- 同じ列の中で下へ動かすとき、たとえば[A, B, C]のAをCの後ろ（位置3）へ動かすと、Aを取り除いたあとのリストは[B, C]なので、差し込む位置は2になる
- 通知を受けたらリストのモデルを作り直すので、選んでいた項目の選択は外れる
