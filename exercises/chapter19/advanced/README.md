# 第19章 発展課題

## 学習目標

- 高い頻度で届くイベントを、`javax.swing.Timer`でまとめて処理する（デバウンス）
- 時間のかかる処理を`SwingWorker`で別のスレッドに任せ、その間も画面を操作できるようにする
- `publish`・`process`と`setProgress`で途中経過を表示し、`cancel`で処理を止める

## 課題一覧

### 課題1: 入力が止まってから検索する

**ファイル**（このフォルダーのファイルは解答例です）:

```
advanced/task1-search/
├── WordSearch.java       単語の一覧から探す（GUIなし）
├── WordSearchCheck.java  WordSearchの動作確認
└── SearchApp.java        画面とイベント処理、mainメソッド
```

入力欄に打った文字を含むクラス名を探す画面を作成してください。
1文字打つたびに検索するのではなく、入力が300ミリ秒止まってから1回だけ検索します。

**要求仕様**:

- `WordSearch`（GUIに依存しない）
    - 単語の一覧を受け取り、コピーして持つ
    - `search(文字列)`は、大文字と小文字を区別せず、その文字を含む単語を一覧の順で返す。前後の空白は除き、空になったら空のリストを返す
    - 画面で使う40語（JavaのAPIのクラス名）を返す静的メソッド`sampleWords`を持つ
- `SearchApp`（画面）
    - `new Timer(300, ...)`を作り、`setRepeats(false)`で1回だけ動くようにする
    - 入力欄の`DocumentListener`では検索せず、入力の回数を数えてタイマーを`restart()`するだけにする。続けて打つと、そのたびに待ち時間が最初からになる
    - タイマーが動いたら検索し、結果を下の`JTextArea`に1行に1語ずつ表示する
    - いちばん下に「入力 3回   検索 1回   ヒット 3件」の形で、入力と検索の回数を表示する

**実行例**:

`java SearchApp`を実行すると、「クラス名の検索」というウィンドウが開きます。

- 「map」と続けて打つと、打っている間は何も表示されず、手を止めて少しすると「HashMap」「TreeMap」「LinkedHashMap」が表示される
- 下の表示は「入力 3回   検索 1回   ヒット 3件」になる。3回の入力に対して検索は1回だけ
- 1文字ずつ間をあけて打つと、そのたびに検索するので、入力と検索の回数が同じになる
- 入力欄を空にすると、結果も空になる

`java WordSearchCheck`を実行すると、検索の結果を確かめられます（最後に「6件中6件OK」と表示されます）。

### 課題2: 素数を数える

**ファイル**（このフォルダーのファイルは解答例です）:

```
advanced/task2-primes/
├── PrimeMath.java        素数かどうかを調べる（GUIなし）
├── PrimeMathCheck.java   PrimeMathの動作確認
└── PrimeCounterApp.java  画面とSwingWorker、mainメソッド
```

2から指定した数までの素数を数える画面を作成してください。
数えている間も画面が固まらず、途中経過の表示とキャンセルができるようにします。

**要求仕様**:

- `PrimeMath`（GUIに依存しない）
    - `isPrime(n)`は、2から√nまでの数で割り切れるかを調べる。`d * d`が`int`の範囲を超えないよう、`long`にしてから比べる
    - `countPrimes(上限)`は、2から上限までの素数の個数を返す
- `PrimeCounterApp`（画面）
    - 上限を選ぶ`JSpinner`（初期値20,000,000）、「数える」「キャンセル」ボタン、`JProgressBar`、途中経過と結果のラベルを置く
    - 計算は`SwingWorker<Integer, Integer>`を継承した内部クラスで行う
        - `doInBackground`: 2から上限まで調べる。上限の1%進むごとに`setProgress`で進み具合（0〜100）を、`publish`でその時点の個数を送る。ループのたびに`isCancelled()`を調べ、キャンセルされたら止める
        - `process`: 届いた値のうち最後のものを「素数の個数: 873606（途中経過）」の形で表示する
        - `done`: `get()`で結果を受け取り、個数とかかった時間を表示する。キャンセルされたときは`get()`が`CancellationException`を投げるので、「キャンセルしました」と表示する
    - 進捗バーは、ワーカーの`addPropertyChangeListener`で`"progress"`プロパティの変化を受け取って更新する
    - 計算中は「数える」を、計算していないときは「キャンセル」を押せなくする

**実行例**:

`java PrimeCounterApp`を実行すると、「素数を数える」というウィンドウが開きます。

- 「数える」を押すと、進捗バーが0%から伸びていき、「素数の個数: 1091314（途中経過）」のように数が増えていく。下には「計算中...」と表示される
- 計算の間も、ウィンドウを動かしたり「キャンセル」を押したりできる
- 最後まで進むと、進捗バーが100%になり、「素数の個数: 1270607」「2から20000000までに1270607個（2886ミリ秒）」と表示される。かかった時間はコンピューターによって変わる
- 途中で「キャンセル」を押すと、進捗バーがその位置で止まり、「キャンセルしました（1611ミリ秒）」と表示される

`java PrimeMathCheck`を実行すると、素数の判定を確かめられます（最後に「7件中7件OK」と表示されます）。

## 本文で扱っていないAPI

- `CancellationException`（課題2）: `java.util.concurrent`パッケージの例外。キャンセルされた`SwingWorker`の`get()`が投げる。本文のサンプル19-8は、キャンセルしたときに`get()`を呼ばない書き方をしている

## 実装のヒント

- `javax.swing.Timer`の処理はEDTで動くので、タイマーの中で部品を書き換えてよい
- `doInBackground`は別のスレッドで動くので、その中で部品に触らない。画面に出したい値は`publish`か`setProgress`で送り、EDTで動く`process`やプロパティのリスナーで表示する
- `publish`した値は、いくつかまとめて`process`に届くことがある。最新の値だけを使うなら、リストの最後の要素を取る
- 素数の判定は、`isPrime`を`main`から呼べるクラスに分けておくと、画面を開かずに正しさを確かめられる
