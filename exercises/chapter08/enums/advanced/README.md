# 第8章 発展課題（列挙型）

## 学習目標
- フィールド・コンストラクター・メソッドを持つ列挙型を定義する
- 列挙子ごとに抽象メソッドを実装し、処理の違いを列挙型の中に閉じ込める
- `values()`と`valueOf()`、列挙子を探すstaticメソッドを使い分ける
- `EnumSet`で列挙子の集合を、`EnumMap`で列挙子ごとの値を管理する

## 課題一覧

### 課題1: コーヒーショップの注文
**ファイル**（このフォルダーのファイルは解答例です）:
```
advanced/
├── Size.java           カップのサイズ（列挙型）
├── Menu.java           飲み物のメニュー（列挙型）
├── Discount.java       割引の種類（列挙子ごとに計算が違う列挙型）
├── Order.java          1杯分の注文
├── CoffeeShop.java     注文を受けて集計するレジ
└── CoffeeShopApp.java  mainメソッド
```

メニュー・サイズ・割引を列挙型で表し、注文を受けて売上を集計するプログラムを作成してください。

**要求仕様**:
- `Size`（列挙型）
    - `SHORT`・`TALL`・`GRANDE`の3つ。表示用の記号（S・T・G）、容量（ml）、Sサイズからの追加料金（0円・50円・100円）をフィールドに持つ
    - 記号から列挙子を探す`fromLabel(String label)`を持つ。見つからなければ`null`を返す
- `Menu`（列挙型）
    - 表示名と基本の価格（Sサイズの価格）を持つ
    - サイズを受け取って価格を返す`priceFor(Size size)`を持つ
- `Discount`（列挙型）
    - 割引なし・学割10%・マイボトル30円引き・2杯目半額の4つ
    - 割引後の価格を返す`apply(int price)`を抽象メソッドにし、列挙子ごとに実装する
- `Order`
    - メニュー・サイズ・割引を持ち、割引後の価格を返す。計算は列挙型のメソッドに任せる
- `CoffeeShop`
    - 売り切れのメニューを`EnumSet<Menu>`で持つ。売り切れのメニューの注文は断る
    - メニューごとの杯数と売上、サイズごとの杯数を`EnumMap`で数える
    - 集計では、メニューごとの杯数と売上、サイズごとの杯数、売上合計、1杯も売れなかったメニュー、売り切れと販売中のメニューを表示する

**実行例**:
```

  カフェラテ S:400円 T:450円 G:500円

  アイスティー S:330円 T:380円 G:430円

  学割10% → 405円

=== 注文 ===

注文: ドリップコーヒー（S 240ml） 割引なし 300円
注文: ドリップコーヒー（S 240ml） 2杯目半額 150円
注文: カフェラテ（S 240ml） 割引なし 400円
```

## 実装のヒント

```java
public enum Discount {
    STUDENT("学割10%") {
        @Override
        public int apply(int price) {
            return price * 90 / 100;
        }
    },
    // ...ほかの列挙子も同じように書く
    ;

    private final String description;

    Discount(String description) {
        this.description = description;
    }

    public abstract int apply(int price);  // 列挙子ごとに実装する
}
```

- 列挙型のコンストラクターは`private`扱いで、外から`new`できない。列挙子の後ろの`( )`に書いた値が渡される
- 列挙子の宣言のあとにフィールドやメソッドを書くときは、最後の列挙子の後ろに`;`を付ける
- `Menu.valueOf("LATTE")`は列挙子の名前と完全に一致する文字列だけを受け付ける。表示用の記号から探すときは、`values()`で全列挙子を調べるstaticメソッドを書く
- `EnumSet.noneOf(Menu.class)`は空の集合、`EnumSet.complementOf(集合)`はその集合に含まれない列挙子の集合を作る
- `EnumMap`の`get`は、まだ`put`していないキーには`null`を返す。コンストラクターで全列挙子を0で用意しておくと、数えるときに`null`を気にしなくてよい
- コレクションの使い方は第9章、`<Menu, Integer>`のような型の書き方は第10章で詳しく学ぶ。ここでは本文のサンプルコード8-10と同じ書き方で使えばよい

## 応用のポイント

1. 値と振る舞いを列挙型に持たせる
    - 価格の表や割引の計算を`if`や`switch`で書かず、列挙型のフィールドとメソッドにした。メニューや割引を足すときは列挙子を1つ足すだけで済む
2. 列挙子ごとの実装
    - 割引の計算は列挙子ごとに違うので、抽象メソッドにして列挙子ごとに実装した。実装を書き忘れるとコンパイルエラーになる
3. `EnumSet`と`EnumMap`
    - 列挙子の集合や対応表を、宣言順に並んだ形で扱える。列挙子の数が少ないので、内部では配列やビットで効率よく管理される
