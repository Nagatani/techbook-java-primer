# 第8章 発展課題（レコード）

## 学習目標
- 値の組をレコードで表し、自動で作られるアクセサー・`equals`・`hashCode`・`toString`を使う
- コンパクトコンストラクターで、値を検証したり整えたりしてからフィールドに入れる
- 静的ファクトリメソッドと、一部の値だけを変えた新しいオブジェクトを返すwithメソッドを書く
- メソッドの中だけで使う値の組を、ローカルレコードで表す
- 不変のオブジェクトを「置き換える」形で、状態の変化を表す

## 課題一覧

### 課題1: ショッピングカート
**ファイル**（このフォルダーのファイルは解答例です）:
```
advanced/
├── Money.java     金額（レコード）
├── Product.java   商品（レコード）
├── CartItem.java  カートの1行（レコード）
├── Cart.java      ショッピングカート
└── CartApp.java   mainメソッド
```

金額・商品・カートの1行をレコードで表し、カートの合計を求めるプログラムを作成してください。

**要求仕様**:
- `Money`（レコード、成分は`int amount`）
    - コンパクトコンストラクターで、金額が0以上であることを確かめる
    - 静的ファクトリメソッド`of(int amount)`と、0円を表す定数`ZERO`を持つ
    - `plus(Money other)`・`times(int n)`・`isGreaterThan(Money other)`を持つ。計算の結果は新しい`Money`で返す
    - `toString`をオーバーライドし、「1,800円」のように3桁区切りで表示する
- `Product`（レコード、成分は商品コード・名前・価格）
    - コンパクトコンストラクターで必須の値を確かめ、商品コードは前後の空白を取って大文字に、名前は前後の空白を取ってからフィールドに入れる
- `CartItem`（レコード、成分は商品と個数）
    - コンパクトコンストラクターで、個数が1〜99であることを確かめる
    - 個数だけを変えた新しいオブジェクトを返す`withQuantity(int newQuantity)`と、小計を返す`subtotal()`を持つ
- `Cart`
    - `CartItem`の配列で中身を持つ
    - 商品を入れるとき、`equals`で等しい商品がすでにあれば、`withQuantity`で作った新しい`CartItem`に置き換えて個数を足す
    - 商品を取り除く・合計を求める・中身を表示する
    - 品目数・個数・小計がいちばん大きい行を、メソッドの中で宣言したローカルレコードにまとめて表示する

**実行例**:
```
=== 商品 ===
Product[code=B01, name=ノート, price=150円]
名前: ノート、価格: 150円
Product[code=B01, name=ノート, price=150円]
同じ商品か: true
== で比べると: false

=== カートに入れる ===
ノートを3個入れました
ボールペンを2個入れました
トートバッグを1個入れました
ノートを5個にしました
  B01 ノート 150円 × 5 = 750円
  B02 ボールペン 120円 × 2 = 240円
  C10 トートバッグ 1,800円 × 1 = 1,800円
  合計 2,790円

=== withメソッド ===
元のオブジェクト: CartItem[product=Product[code=B02, name=ボールペン, price=120円], quantity=2]
新しいオブジェクト: CartItem[product=Product[code=B02, name=ボールペン, price=120円], quantity=5]

=== 取り除く ===
ボールペンを取り除きました
ボールペンはカートにありません
  B01 ノート 150円 × 5 = 750円

  合計 2,550円

=== まとめ ===

  いちばん高い行: トートバッグ 1,800円
```

2つ目の商品は`" b01 "`と`"ノート "`から作りましたが、コンパクトコンストラクターで整えたので、1つ目の商品と`equals`で等しくなります。

## 実装のヒント

```java
public record Product(String code, String name, Money price) {
    public Product {                       // 引数の( )を書かない
        if (code == null || code.isBlank() /* ... */) {
            throw new IllegalArgumentException("商品コード・名前・価格は必須です");
        }
        code = code.strip().toUpperCase(); // 引数を書き換えると、その値がフィールドに入る
    }
}

public record CartItem(Product product, int quantity) {
    public CartItem withQuantity(int newQuantity) {
        return new CartItem(product, newQuantity);  // 自分は変えずに、新しいオブジェクトを返す
    }
}
```

- コンパクトコンストラクターの最後で、引数の値が自動でフィールドに代入される。`this.code = ...`とは書かない
- 不正な値を渡すと`IllegalArgumentException`が投げられてプログラムが止まる。例外を受け止める方法は第13章で学ぶので、mainでは正しい値だけを使う
- レコードの`equals`は、すべての成分を`equals`で比べる。`Product`の成分の`Money`もレコードなので、金額が同じなら等しくなる
- レコードのフィールドは`final`なので、`Cart`で個数を変えるときは配列の要素を新しい`CartItem`に置き換える
- ローカルレコードは、メソッドの中に`record Summary(int kinds, int pieces, CartItem largest) {}`のように書く。複数の値をまとめて扱いたいが、ほかの場所では使わないときに向く
- `"%,d円".formatted(amount)`で、3桁ごとにカンマを入れた文字列を作れる

## 応用のポイント

1. 値オブジェクト
    - 金額を`int`のまま扱わず`Money`にしたので、マイナスの金額が入らないことと、金額の計算方法が1か所にまとまる
2. 整えてから入れる
    - コンパクトコンストラクターで表記のゆれをなくしておくと、`equals`での比較が期待どおりに働く
3. 置き換えで変化を表す
    - `CartItem`は変わらないので、ほかの場所で同じオブジェクトを持っていても、知らないうちに個数が変わることがない
