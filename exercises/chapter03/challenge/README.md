# 第3章 チャレンジ課題

## 学習目標
- 役割の違う2つのクラスを設計し、一方のオブジェクトから他方のオブジェクトに処理を頼む
- フィールドを`private`にして、状態を変える処理をメソッドに閉じ込める（カプセル化）
- オブジェクトの配列と、実際に入っている数を数える変数で、複数のオブジェクトを管理する
- オブジェクトごとに変わらない値と処理を、`static final`の定数と`static`メソッドにする

## 課題一覧

### 課題1: 自動販売機シミュレーター
**ファイル名**: `VendingMachineSimulator.java`（このフォルダーのファイルは解答例です）

お金を入れて飲み物を買い、おつりを受け取る自動販売機を作成してください。
飲み物を表す`Drink`クラスと、自動販売機を表す`VendingMachine`クラスを作ります。
`main`メソッドは、メニューを表示して入力を受け取り、操作を`VendingMachine`に任せるだけにします。

**要求仕様**:
- `Drink`クラス
    - 名前・価格・在庫の本数を持つ
    - 在庫は「1本売る」「補充する」メソッドでだけ変わる。売り切れなら売らない。1本未満の補充は受け付けない
- `VendingMachine`クラス
    - 飲み物を並べる棚（`Drink`の配列）と、並んでいる種類の数・投入金額・売上金額・売れた本数を持つ
    - 使えるお金は10円・50円・100円・500円・1000円だけ。一度に入れられるのは5000円まで
    - 飲み物を番号で選んで買う。番号がない・売り切れ・お金が足りない（あと何円か）のときは、理由を知らせて買わない
    - おつりは大きいお金から順に使い、何円を何枚返すかを表示する
    - 飲み物の一覧には、売り切れなら`[売切]`、いまの投入金額で買えるなら`[購入可]`を付ける
    - 投入金額と売上は、外から直接書き換えられないようにする（値を読むメソッドだけを用意する）
- 管理メニューで、売上の確認と飲み物の補充ができる
- 終了するときに投入金額が残っていたら、おつりを返す
- 数字以外が入力されたら、もう一度入力してもらう

## 実装のヒント

```java
class VendingMachine {
    // どの自動販売機でも同じ値なので、static finalの定数にする
    private static final int[] MONEY_UNITS = {1000, 500, 100, 50, 10};

    private Drink[] drinks;
    private int drinkCount;      // 実際に並んでいる種類の数
    private int insertedAmount;  // 投入金額

    // 使えるお金かどうかは、オブジェクトの状態を使わないのでstaticメソッドにできる
    public static boolean isAcceptable(int money) {
        // MONEY_UNITSのどれかと等しければtrue
    }
}
```

- 買えなかった理由は、`buy`メソッドが結果を文字列で返すようにすると、`main`メソッドの側で場合分けをしなくて済む
- 在庫を減らす処理は`Drink`に任せる。`VendingMachine`が`Drink`の在庫を直接書き換えないようにする
- おつりの枚数は、大きいお金から順に「残りの金額 / お金の額」で求め、その分を残りの金額から引く
- 番号から飲み物を探す処理（範囲外なら`null`を返す）は、`buy`と補充の両方で使うので、`private`メソッドにまとめる
- 数字だけの入力かどうかは、第2章のチャレンジ課題と同じく`charAt`で1文字ずつ調べる。例外処理は第13章で学ぶ
- 要素を必要なだけ追加できる入れ物（`ArrayList`など）は第9章で学ぶので、ここでは配列を使う

## 応用のポイント

1. 責任の分担
    - 在庫のことは`Drink`、お金と棚のことは`VendingMachine`、入力と表示は`main`メソッドのクラスが受け持つ
2. 不正な状態を作らない
    - 投入金額が上限を超える、在庫がマイナスになるといった状態は、メソッドの中の確認で起きないようにする
3. インスタンスとstaticの使い分け
    - 投入金額や在庫はオブジェクトごとに違うのでフィールドに、使えるお金の種類は共通なので`static final`の定数にする
