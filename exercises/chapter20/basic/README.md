# 第20章 基本課題

## 学習目標

- AbstractTableModelを継承したモデルでJTableにデータを表示し、変更を`fireTable...`で知らせる
- TableRowSorterとRowFilterで、表の並べ替えと絞り込みを行う
- JTreeとJTableをJSplitPaneで組み合わせ、選んだノードに合わせて表を切り替える
- Model・View・Controllerに役割を分け、Modelの変更をオブザーバーでViewに知らせる
- `paintComponent`をオーバーライドして、データをグラフとして描く（第17章）

## 課題一覧

このフォルダーのJavaファイルは、「ここに実装してください」「TODO」の箇所を埋めて完成させる雛形です。
同じ名前の解答例が[solutions/](../solutions/)にあります。解答例は、ここに挙げた要求仕様より多くの機能を持つ大きめのプログラムです。

GUIのプログラムなので、実行例ではウィンドウの見た目と、操作したときの反応を説明します。

### 課題1: 学生名簿の表

**ファイル**: `StudentManagementGUI.java`（解答例は`solutions/StudentManagementGUI.java`）

学生の一覧をJTableで表示し、追加・編集・削除・検索ができる画面を作ります。

**要求仕様**:

- `Student`は学籍番号・氏名・年齢・学年・メールアドレス・入学日を持つ
- `StudentTableModel`は`AbstractTableModel`を継承し、`getRowCount`・`getColumnCount`・`getValueAt`と列名（`getColumnName`）を実装する。学生を追加・変更・削除したら、`fireTableRowsInserted`などで表に知らせる
- 「追加」「編集」「削除」のボタンを置く。追加と編集はダイアログで入力させ、削除は選んだ行を消す
- 列の見出しをクリックすると並べ替えられるよう、`TableRowSorter`を設定する
- 検索欄に入力した文字を含む行だけを、`RowFilter`で表示する（大文字と小文字は区別しない）
- 「保存」「読込」で、CSVファイル（第14章）に書き出し、読み込む

**実行例**（解答例）:

- 起動すると、数人の学生の表が表示される
- 「学年」の見出しをクリックすると学年の順に並び、もう一度クリックすると逆順になる
- 検索欄に名前の一部を入れると、その文字を含む行だけが残る。表示の行と元のデータの行は並べ替えや絞り込みでずれるので、編集や削除では`convertRowIndexToModel`で元の行に直してから扱う
- 「保存」で選んだファイルに書き出し、「読込」で同じ内容が表に戻る

### 課題2: ファイルの一覧

**ファイル**: `FileExplorer.java`（解答例は`solutions/FileExplorer.java`）

左にフォルダーの木（JTree）、右にファイルの表（JTable）を並べたファイル一覧を作ります。

**要求仕様**:

- 左のJTreeにフォルダーの階層を表示する。子のフォルダーは、ノードを開いたときに初めて読み込む（`DirectoryTreeNode`の`loadChildren`）
- ツリーでフォルダーを選ぶと、右のJTableにその中のファイルを、名前・大きさ・更新日時の列で表示する
- 検索欄に入れた文字を名前に含むファイルだけを表に残す（`FileTableModel`の`setFilter`）
- ツリーと表を`JSplitPane`で左右に分け、境目をドラッグして幅を変えられるようにする

**実行例**（解答例）:

- 起動すると、左にホームフォルダーから始まるツリー、右にその中のファイルの表が出る
- ツリーのフォルダーを選ぶと、右の表がそのフォルダーの中身に変わる
- 検索欄に「.txt」と入れると、名前に「.txt」を含むファイルだけが残る

解答例には、このほかにコピー・削除・新しいフォルダーの作成と、フォルダーの変化を見張る`WatchService`（本文では扱わないAPI）を使った自動更新があります。

### 課題3: 書籍管理とMVC

**ファイル**: `MVCExample.java`（解答例は`solutions/MVCExample.java`）

書籍の一覧を管理する画面を、Model・View・Controllerに分けて作ります。

**要求仕様**:

- Model（`BookModel`）は書籍のリストを持ち、追加・変更・削除のたびに、登録されたオブザーバー（`ModelObserver`）へ変更の種類と書籍を知らせる。画面の部品は知らない
- View（`BookView`）はModelの変更を受け取って表を描き直す。ボタンが押されたら、自分では処理せずControllerに伝える
- Controller（`BookController`）は、Viewからの操作を受けてModelのメソッドを呼ぶ
- タイトルと著者が空の書籍は登録しない（`validateBook`）
- 検索欄の文字をタイトルか著者に含む書籍を返す`searchBooks`を実装する

**実行例**（雛形を完成させた場合）:

- 起動すると、見本の書籍が数冊表に並ぶ
- 「追加」でタイトルと著者を入力すると、表に1行増える。タイトルを空にしたまま追加しても、表は変わらない
- 書籍を選んで「削除」を押すと、その行が消える。表を描き直しているのはModelからの通知を受けたViewで、Controllerは表に触れていない

解答例は、同じ構造で書籍の代わりにタスク（タイトル・説明・優先度・期限・状態）を管理する例です。Modelからの通知には`PropertyChangeListener`を使っています。

### 課題4: データのグラフ

**ファイル**: `DataVisualization.java`（解答例は`solutions/DataVisualization.java`）

ラベルと値の組を、折れ線グラフ・棒グラフ・円グラフで描きます。

**要求仕様**:

- `ChartPanel`の`paintComponent`で、選んだ種類のグラフを`Graphics2D`で描く。データがないときは「データがありません」と表示する
- グラフの種類は`JComboBox<ChartType>`で切り替え、切り替えたら`repaint()`で描き直す
- 「データ追加」のダイアログでラベルと値を入力すると、グラフに加わる
- 描くときは、パネルの幅と高さ（`getWidth()`・`getHeight()`）と最大の値から、点や棒の位置を計算する

**実行例**（解答例）:

- 起動すると見本のデータの折れ線グラフが出る
- 種類を「棒グラフ」「円グラフ」に変えると、同じデータで描き直される
- ウィンドウの大きさを変えると、グラフもその大きさに合わせて描き直される
- 「アニメーション開始」を押すと、グラフが少しずつ伸びて現れる

解答例は見本のデータの値と色を乱数で作るので、グラフの形と色は起動のたびに変わります。

## ヒント

- モデルのデータを変えたら、必ず`fireTableDataChanged()`などで表に知らせる。知らせないと、表の表示が古いままになる
- 並べ替えや絞り込みをしているときは、`table.getSelectedRow()`の値は表示の行の番号。`table.convertRowIndexToModel(...)`で元のデータの行に直す
- 検索欄に入力するたびに絞り込むには、第19章で学んだDocumentListenerを使う
- 画面の部品はEDTで作り、操作する（第18章）。時間のかかる読み込みは、第19章のSwingWorkerで別のスレッドに任せる
