# 第5章 発展課題

## 学習目標
- 3段の継承階層（親・子・孫）を作り、どの段で何をオーバーライドするかを決める
- 親クラスのメソッドの中から、子クラスでオーバーライドしたメソッドを呼ばせて、処理の手順を1か所にまとめる
- `super.メソッド名()`で親クラスの処理を使い、条件や値を付け足す
- 親クラスの型の配列で種類の違うオブジェクトを同じ処理で扱い、`instanceof`は子クラスだけが持つ情報が必要なときに限る

## 課題一覧

### 課題1: 動物園の飼育管理
**ファイル**（このフォルダーのファイルは解答例です）:
```
advanced/task1-zoo/
├── Animal.java    動物（いちばん上の親クラス）
├── Mammal.java    哺乳類（Animalの子クラス）
├── Bird.java      鳥類（Animalの子クラス）
├── Lion.java      ライオン（Mammalの子クラス）
├── Elephant.java  ゾウ（Mammalの子クラス）
├── Penguin.java   ペンギン（Birdの子クラス）
├── Parrot.java    オウム（Birdの子クラス）
├── Zoo.java       動物をまとめて管理する動物園
└── ZooApp.java    mainメソッド
```

動物ごとの1日のえさの量と代金、健康チェックの結果を表示するプログラムを作成してください。
継承階層は次のようにします。

```
Animal
├── Mammal
│   ├── Lion
│   └── Elephant
└── Bird
    ├── Penguin
    └── Parrot
```

**要求仕様**:
- `Animal`（動物）
    - 名前・年齢・体重を持つ
    - 種類名・分類名・展示エリア・えさの種類・えさ1kgの値段・体重に対するえさの割合（標準3%）・平熱の範囲を返すメソッドを持つ。子クラスはこれらをオーバーライドする
    - 1日のえさの量（体重 × 割合）と代金（量 × 1kgの値段）の計算、体温が平熱の範囲にあるかの判定は、このクラスに1回だけ書く
- `Mammal`（哺乳類）と`Bird`（鳥類）
    - 分類名と平熱の範囲（哺乳類 35.5〜39.0℃、鳥類 38.0〜42.0℃）をオーバーライドする
    - `Bird`は飛べるかどうかを持ち、`toString`で`super.toString()`に「飛べる」「飛べない」を付け足す
- 種類ごとのクラス
    - 種類名・展示エリア・えさの種類と値段・えさの割合のうち、標準と違うものだけをオーバーライドする（ライオンはえさの割合が標準のまま、オウムは展示エリアが標準のまま）
    - `Penguin`は、コンストラクターで「飛べない」を指定して`Bird`のコンストラクターを呼ぶ
- `Zoo`（動物園）
    - 動物を`Animal`の配列で管理する
    - 給餌の予定と健康チェックの処理では、動物の種類を調べない（`instanceof`を使わない）
    - 分類ごとの数と飛べない鳥の数の集計だけ、`instanceof`で型を調べる

**実行例**:
```
=== 動物の登録 ===
登録: [ライオン] レオ（5歳、190.0kg） / 哺乳類・サバンナ
登録: [ゾウ] ハナコ（12歳、4000.0kg） / 哺乳類・アフリカの森
登録: [ペンギン] ピコ（3歳、15.0kg） 飛べない / 鳥類・極地の海
登録: [オウム] ソラ（2歳、1.0kg） 飛べる / 鳥類・ふれあい広場

=== 1日の給餌の予定 ===
  レオ（ライオン）: 牛肉 5.7kg 6840円
  ハナコ（ゾウ）: 干し草 100.0kg 6000円
  ピコ（ペンギン）: 魚 1.5kg 1200円
  ソラ（オウム）: 種子 0.1kg 150円
  1日のえさ代の合計: 14190円

=== 健康チェック ===
  レオ: 38.5℃ 健康
  ハナコ: 36.2℃ 健康
  ピコ: 43.0℃ 要注意（平熱 38.0〜42.0℃）
  ソラ: 41.5℃ 健康

=== 集計 ===
  みなと動物園の飼育数: 4（哺乳類 2、鳥類 2、うち飛べない鳥 1）
  平均年齢: 5.5歳
```

ライオンの1日のえさは、`Animal`の`dailyFoodKg()`で「190kg × 3%」と計算されます。
ゾウは`getFoodRatio()`をオーバーライドしているので、同じ`dailyFoodKg()`の中で2.5%が使われます。

### 課題2: 通学手段の比較
**ファイル**（このフォルダーのファイルは解答例です）:
```
advanced/task2-commute/
├── Transport.java        通学の手段（親クラス）
├── Walk.java             徒歩
├── Bicycle.java          自転車
├── PublicTransport.java  公共交通（Transportの子クラス）
├── Bus.java              バス（PublicTransportの子クラス）
├── Train.java            電車（PublicTransportの子クラス）
├── CommutePlanner.java   手段を比べる
└── CommuteApp.java       mainメソッド
```

家から大学までの距離を与えると、使える通学手段ごとに片道の時間と通学日数分の費用を表示し、いちばん速い手段と安い手段を選ぶプログラムを作成してください。

**要求仕様**:
- `Transport`（通学の手段）
    - 名前と時速を持つ
    - 待ち時間（標準0分）・片道の運賃（標準0円）・その距離で使えるか（標準はどの距離でも使える）を返すメソッドを持つ
    - 片道の時間（待ち時間 + 距離 ÷ 時速。分は切り上げ）と、1日の費用（片道の運賃 × 2）の計算は、このクラスに1回だけ書く
- 子クラス
    - `Walk`（徒歩、時速4km）: 3km以下でだけ使える（`super.canUse()`の条件に足す）
    - `Bicycle`（自転車、時速15km）: 10km以下でだけ使える。運賃はないが、駐輪場の料金が1日1回かかる（`dailyCost`をオーバーライドする）
    - `PublicTransport`（公共交通）: 待ち時間を持ち、`toString`で`super.toString()`に待ち時間を付け足す
    - `Bus`（バス、時速18km、待ち10分）: 運賃は距離によらず230円
    - `Train`（電車、時速40km、待ち5分）: 運賃は150円 + 1kmごとに20円。駅まで歩く時間を、`super.minutes()`で計算した時間に足す。2km以上でだけ使える
- `CommutePlanner`
    - 手段を`Transport`の配列で受け取り、比べる処理では種類を調べない
    - 公共交通の待ち時間の一覧だけ、`instanceof`で`PublicTransport`かどうかを調べる

**実行例**:
```
=== 通学の手段 ===
  徒歩（時速4km）
  自転車（時速15km）
  バス（時速18km） 待ち10分
  電車（時速40km） 待ち5分

=== 比較 ===
距離 1.5km（20日通う場合）
  徒歩: 片道23分、合計0円
  自転車: 片道6分、合計2000円
  バス: 片道15分、合計9200円
  電車: この距離では使わない
  いちばん速い: 自転車、いちばん安い: 徒歩

距離 6.0km（20日通う場合）
  徒歩: この距離では使わない
  自転車: 片道24分、合計2000円
  バス: 片道30分、合計9200円
  電車: 片道22分、合計10800円
  いちばん速い: 電車、いちばん安い: 自転車

距離 15.0km（20日通う場合）
  徒歩: この距離では使わない
  自転車: この距離では使わない
  バス: 片道60分、合計9200円
  電車: 片道36分、合計18000円
  いちばん速い: 電車、いちばん安い: バス

=== 公共交通の待ち時間 ===
  バス: 待ち10分
  電車: 待ち5分
```

### 課題3: RPGの戦闘
**ファイル**（このフォルダーのファイルは解答例です）:
```
advanced/task3-battle/
├── GameCharacter.java  キャラクター（親クラス）
├── Warrior.java        戦士
├── Knight.java         騎士（Warriorの子クラス）
├── Mage.java           魔法使い
├── Healer.java         回復役
├── Battle.java         戦闘を進める
└── BattleApp.java      mainメソッド
```

3人のパーティーがモンスターと戦うプログラムを作成してください。
乱数は使わず、毎回同じ結果になるようにします。

**要求仕様**:
- `GameCharacter`（キャラクター）
    - 名前・最大HP・HP・攻撃力・防御力を持つ
    - `attack(相手)`: ダメージ「攻撃力 - 相手の防御力」（少なくとも1）を相手の`takeDamage`に渡す
    - `takeDamage(ダメージ)`: HPを減らす（0より小さくしない）。`heal(量)`: HPを増やす（最大HPを超えない）
    - `act(味方の配列, 相手)`: 1ターンの行動。標準は相手を攻撃する。子クラスがオーバーライドする
- 子クラス
    - `Warrior`（戦士）: HPが半分以下のときは、攻撃力を1.5倍にした「渾身の一撃」で攻撃する。それ以外は`super.attack()`
    - `Knight`（騎士）: `Warrior`を継承し、`takeDamage`をオーバーライドして、受けるダメージを半分（切り上げ）にしてから`super.takeDamage()`を呼ぶ
    - `Mage`（魔法使い）: MPが10以上あれば、MPを10使って防御力を無視する魔法で攻撃する。MPがなければ`super.act()`
    - `Healer`（回復役）: HPが半分以下の味方がいれば、いちばんHPの少ない味方を回復する。いなければ`super.act()`
- `Battle`（戦闘）
    - 味方を`GameCharacter`の配列で持ち、毎ターン、生きている味方の`act`を順に呼ぶ。職業を調べない
    - 味方の行動のあと、モンスターが前に並んでいる味方を攻撃する。モンスターをたおすか、味方が全滅するか、決まったターン数で終わる

**実行例**:

## 実装のヒント

```java
public class Animal {
    // 割合はオーバーライドされたgetFoodRatio()で決まる
    public double dailyFoodKg() {
        return weightKg * getFoodRatio();
    }
}

public class Train extends PublicTransport {
    // 親クラスの計算に、駅まで歩く時間を足す
    @Override
    public int minutes(double distanceKm) {
        return super.minutes(distanceKm) + walkToStationMinutes;
    }
}
```

- 親クラスのメソッドの中から呼んだメソッドも、オブジェクトの実際のクラスでオーバーライドしたものが呼ばれる。課題1の`dailyFoodKg()`、課題2の`minutes()`の中の`getWaitMinutes()`、課題3の`attack()`の中の`takeDamage()`がこれにあたる
- 孫クラス（`Lion`）でオーバーライドしなかったメソッドは、子クラス（`Mammal`）、親クラス（`Animal`）の順にさかのぼって探される
- 子クラスのコンストラクターでは、最初に`super(...)`で親クラスのフィールドを初期化する。親クラスのフィールドは`private`のままにし、子クラスからはgetterで読む
- `abstract`（抽象クラス）は第7章で学ぶので、ここでは親クラスに標準の値を返すメソッドを書き、子クラスでオーバーライドする
- 課題3の`act`に味方の配列を渡しておくと、回復役は配列から回復する相手を選べる。行動の違いは子クラスの中に閉じ込められ、`Battle`は職業を知らなくてよい

## 応用のポイント

1. どの段に書くか
    - 鳥すべてに共通する平熱は`Bird`に、ペンギンだけの値は`Penguin`に書く。共通する段にまとめるほど、同じコードを書かずに済む
2. 手順は親、値と条件は子
    - 時間や代金の計算の手順は親クラスの1か所にあり、子クラスは値と条件の追加だけを書く
3. 種類を調べない処理
    - 新しい手段（たとえばタクシー）や職業を足しても、`CommutePlanner`や`Battle`を直さなくてよい
