# 第5章 チャレンジ課題

## 学習目標
- 共通の属性と処理を親クラスにまとめ、種類ごとの違いだけを子クラスに書く
- メソッドのオーバーライドと、`super.メソッド名()`による親クラスの処理の再利用
- 親クラスの型の配列で、種類の違うオブジェクトを同じ処理で扱う（ポリモーフィズム）
- `instanceof`で型を調べるのは、子クラスだけが持つ情報が必要なときに限る
- `toString`・`equals`・`hashCode`をオーバーライドする

## 課題一覧

### 課題1: 図書館の資料管理システム
**ファイル**（このフォルダーのファイルは解答例です）:
```
challenge/
├── LibraryItem.java  資料（親クラス）
├── Book.java         本
├── Magazine.java     雑誌
├── Dvd.java          DVD
├── Library.java      資料をまとめて管理する図書館
└── LibraryApp.java   mainメソッド
```

本・雑誌・DVDの貸出と返却を管理するプログラムを作成してください。
日付は「1日」「12日」のような日の番号（整数）で扱います。

**要求仕様**:
- `LibraryItem`（資料、親クラス）
    - 資料番号・題名・貸出中かどうか・返却期限を持つ
    - 貸出期間（14日）、1日あたりの延滞料金（10円）、貸し出せるかどうか（貸出中でなければ可）を返すメソッドを持つ。子クラスはこれらをオーバーライドする
    - 貸出（返却期限を「貸した日 + 貸出期間」にする）、返却、延滞料金の計算（期限を過ぎた日数 × 1日あたりの料金）は、このクラスに1回だけ書く
    - `toString`で種類・資料番号・題名・状態を表す。`equals`と`hashCode`は資料番号で判定する
- 子クラス
    - `Book`（本）: 貸出期間と延滞料金は標準のまま。著者を持ち、`toString`で`super.toString()`に著者を付け足す
    - `Magazine`（雑誌）: 貸出期間は7日。最新号は貸し出さない（`canBorrow`をオーバーライドし、`super.canBorrow()`の条件に「最新号でない」を加える）
    - `Dvd`（DVD）: 貸出期間は7日、延滞料金は1日100円。再生時間（分）を持つ
- `Library`（図書館）
    - 資料を`LibraryItem`の配列で管理する
    - 登録のとき、`equals`で等しい資料（資料番号が同じ）がすでにあれば登録しない
    - 貸出・返却・延滞している資料の表示の処理では、資料の種類を調べない（`instanceof`を使わない）
    - 種類ごとの数と、DVDの再生時間の合計を集計する。ここだけ`instanceof`で型を調べる

## 実装のヒント

```java
public class LibraryItem {
    // 返却期限は、オーバーライドされたgetLoanDays()で決まる
    // Magazineのオブジェクトなら7、Bookなら14が使われる
    public boolean borrow(int day) {
        if (!canBorrow()) {
            return false;
        }
        onLoan = true;
        dueDay = day + getLoanDays();
        return true;
    }
}

public class Magazine extends LibraryItem {
    @Override
    public boolean canBorrow() {
        return super.canBorrow() && !latest;  // 親クラスの条件に、雑誌の条件を足す
    }
}
```

- 親クラスのメソッドの中から呼んだ`getLoanDays()`も、オブジェクトの実際のクラスでオーバーライドしたメソッドが呼ばれる。これで、貸出の処理を子クラスごとに書かずに済む
- 子クラスのコンストラクターでは、最初に`super(id, title)`で親クラスのフィールドを初期化する
- 親クラスのフィールドは`private`のままにし、子クラスからはgetterで読む
- DVDの再生時間は`Dvd`だけが持つので、`LibraryItem`型の変数からは`getMinutes()`を呼べない。`item instanceof Dvd dvd`と書くと、型を確かめたうえで`Dvd`型の変数`dvd`として使える
- `equals`は第5章のサンプルコード5-15と同じ形で書く。`getClass()`で比べるので、資料番号が同じでもクラスが違えば別の資料になる
- `abstract`（抽象クラス）は第7章で学ぶので、ここでは親クラスに標準の値を返すメソッドを書き、子クラスでオーバーライドする

## 応用のポイント

1. 違いだけを子クラスに
    - 子クラスに書くのは「期間や料金の値」と「条件の追加」だけで、貸出や延滞料金の計算の手順は親クラスの1か所にある
2. 種類を調べない処理
    - 貸出・返却に`if (item instanceof Dvd)`と書かずに済むので、新しい種類を足しても`Library`を直さなくてよい
3. `instanceof`を使う場面
    - 子クラスだけが持つ情報を使う集計のように、種類ごとに扱いを変える必要があるときに限る

## 発展（任意）

- 新しい種類（例: 貸出期間3日・延滞料金1日50円の「新刊の本」）を、`Book`を継承した`NewBook`として加え、`Library`を変更せずに動くことを確かめる
- 延滞料金に上限（例: 資料ごとに1000円まで）を設ける。どのクラスのどのメソッドを変えるのがよいかを考える
