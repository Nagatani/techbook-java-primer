## 動かす準備

本付録の例は、Javaで書かれた組み込みデータベースのH2で動かせるように書いています。
H2はJARファイルを1つクラスパスに加えるだけで使え、データベースサーバーを用意する必要がありません。

### H2を使う

Mavenを使う場合は、`pom.xml`に次の依存を加えます（版は2026年11月時点の最新版です）。

<span class="listing-number">**サンプルコードE-1**</span>

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <version>2.5.252</version>
</dependency>
```

Gradleでは`implementation 'com.h2database:h2:2.5.252'`と書きます。
ビルドツールを使わない場合は、Maven Centralから`h2-2.5.252.jar`を取得して、クラスパスに加えます。

```bash
javac -cp h2-2.5.252.jar *.java
java -cp .:h2-2.5.252.jar BasicJDBCExample
```

Windowsでは、クラスパスの区切りを`;`にします（`-cp .;h2-2.5.252.jar`）。

H2の接続URLには、次の2つの形があります。
本付録の例は、メモリ上のデータベース（`jdbc:h2:mem:testdb`）を使います。
ユーザー名は`sa`、パスワードは空文字列です。

| 接続URL | データの置き場所 |
|---|---|
| `jdbc:h2:mem:testdb` | メモリ上。最後の接続を閉じると消える |
| `jdbc:h2:mem:testdb;DB_CLOSE_DELAY=-1` | メモリ上。プログラムが終わるまで残る |
| `jdbc:h2:./testdb` | 今いるディレクトリの`testdb.mv.db`ファイル。プログラムを終えても残る |

### ほかのデータベースを使う場合

MySQLやPostgreSQLなどを使う場合は、そのデータベースのJDBCドライバーをクラスパスに加え、接続URLを変えます。
ドライバーはJDBC 4.0以降の仕組みで自動的に登録されるため、`Class.forName`でドライバークラスを読み込む必要はありません。

| データベース | Mavenの座標（2026年11月時点の最新版） | 接続URLの形 |
|---|---|---|
| MySQL | `com.mysql:mysql-connector-j:26.10.0` | `jdbc:mysql://localhost:3306/testdb` |
| PostgreSQL | `org.postgresql:postgresql:42.7.14` | `jdbc:postgresql://localhost:5432/testdb` |
| SQLite | `org.xerial:sqlite-jdbc:3.54.1.0` | `jdbc:sqlite:testdb.db` |

SQLの方言はデータベースごとに少しずつ違います。
本付録のSQLはH2で確かめたものです。
たとえば、IDを自動で振る列は、H2とPostgreSQLでは`GENERATED BY DEFAULT AS IDENTITY`、MySQLでは`AUTO_INCREMENT`、SQLiteでは`INTEGER PRIMARY KEY AUTOINCREMENT`と書きます。

## SQL基礎の復習

### SQLとは

SQL（Structured Query Language）は、リレーショナルデータベースでデータの操作や管理を行うための標準的な言語です。JDBCを効果的に使用するためには、基本的なSQL文の理解が不可欠です。

### テーブルを定義する（DDL）

テーブルの作成・変更・削除には、データ定義言語（DDL: Data Definition Language）を使います。
次のテーブルは、このあとの例でも使います。

<span class="listing-number">**サンプルコードE-2**</span>

```sql
-- テーブルの作成
CREATE TABLE users (
    id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL,
    age INT,
    password_hash VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- テーブル構造の変更
ALTER TABLE users ADD COLUMN last_login TIMESTAMP;

-- 制約の追加
ALTER TABLE users
ADD CONSTRAINT chk_age CHECK (age >= 0 AND age <= 120);

-- 外部キー制約を持つテーブル
CREATE TABLE posts (
    id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    content CLOB,
    user_id INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- インデックスの作成
CREATE INDEX idx_email ON users(email);
CREATE INDEX idx_username_age ON users(username, age);

-- テーブルの削除（使い終わったときに実行する。参照する側のpostsから消す）
-- DROP TABLE IF EXISTS posts;
-- DROP TABLE IF EXISTS users;
```

### データを操作・検索する（DML）

データの挿入・更新・削除と検索には、データ操作言語（DML: Data Manipulation Language）を使います。
検索（SELECT）を分けて、データ照会言語（DQL: Data Query Language）と呼ぶこともあります。

<span class="listing-number">**サンプルコードE-3**</span>

```sql
-- データの挿入
INSERT INTO users (username, email, age)
VALUES ('tanaka', 'tanaka@example.com', 25);

-- 複数データの挿入
INSERT INTO users (username, email, age) VALUES
    ('sato', 'sato@example.com', 30),
    ('suzuki', 'suzuki@example.com', 28);

INSERT INTO posts (title, user_id) VALUES
    ('はじめての投稿', 1),
    ('JDBCのメモ', 1);

-- データの更新
UPDATE users
SET email = 'tanaka.new@example.com', age = 26
WHERE username = 'tanaka';

-- データの削除
DELETE FROM users WHERE age < 20;

-- 基本的な検索
SELECT * FROM users;

-- 条件付き検索
SELECT username, email FROM users WHERE age > 25;

-- 並び替え
SELECT * FROM users ORDER BY age DESC, username ASC;

-- グループ化と集約関数
SELECT user_id, COUNT(*) AS post_count
FROM posts
GROUP BY user_id
HAVING COUNT(*) > 1;

-- 結合（JOIN）
SELECT u.username, p.title
FROM users u
INNER JOIN posts p ON u.id = p.user_id;
```

### よく使用されるSQL関数と演算子

関数の名前や書き方は、データベースによって違うことがあります。
日付の差を求める`DATEDIFF`はH2の書き方で、PostgreSQLでは`CURRENT_DATE - CAST(created_at AS DATE)`のように書きます。

<span class="listing-number">**サンプルコードE-4**</span>

```sql
-- 文字列関数
SELECT
    CONCAT(username, ' <', email, '>') AS display_name,
    UPPER(username) AS upper_name,
    LENGTH(username) AS name_length
FROM users;

-- 集約関数
SELECT
    COUNT(*) AS total_users,
    AVG(age) AS average_age,
    MAX(age) AS max_age,
    MIN(age) AS min_age
FROM users;

-- 日付関数
SELECT
    username,
    created_at,
    EXTRACT(YEAR FROM created_at) AS created_year,
    DATEDIFF(DAY, created_at, CURRENT_TIMESTAMP) AS days_since_created
FROM users;

-- 条件式
SELECT
    username,
    age,
    CASE
        WHEN age < 20 THEN '未成年'
        WHEN age < 65 THEN '成年'
        ELSE '高齢者'
    END AS age_category
FROM users;

-- パターンマッチング
SELECT * FROM users WHERE email LIKE '%@example.com';
SELECT * FROM users WHERE REGEXP_LIKE(username, '^[a-z]+$');
```

### トランザクションの基本概念

トランザクションは、複数の操作をひとまとまりとして扱い、すべて成功したら確定（コミット）し、途中で失敗したらすべて取り消す（ロールバック）仕組みです。
SQLでトランザクションを始める文は、`START TRANSACTION`（MySQL）や`BEGIN`（PostgreSQL）のようにデータベースによって違います。
JDBCでは、データベースの種類によらず、`Connection`の`setAutoCommit(false)`・`commit()`・`rollback()`で制御します（「トランザクション管理」の節で扱います）。

## JDBCの基礎

### JDBCとは

JDBC（Java Database Connectivity）は、Javaプログラムからリレーショナルデータベースにアクセスするための標準APIです。JDBCを使用することで、データベースの種類に依存しない統一的な方法でデータベース操作を行うことができます。

### JDBCのアーキテクチャ

JDBCは以下の主要コンポーネントで構成されています。

1. JDBC API: Javaアプリケーションが使用するインターフェイス群
2. JDBCドライバー: 各データベース固有の実装
3. DriverManager: ドライバーの管理と接続の確立
4. Connection: データベースとの接続を表現
5. Statement/PreparedStatement: SQL文の実行
6. ResultSet: クエリ結果の保持

### 基本的な接続の流れ

<span class="listing-number">**サンプルコードE-5**</span>

```java
import java.sql.Connection;
import java.sql.DatabaseMetaData;
import java.sql.DriverManager;
import java.sql.SQLException;

public class BasicJDBCExample {
    public static void main(String[] args) {
        // データベース接続情報（H2のメモリ上のデータベース）
        String url = "jdbc:h2:mem:testdb";
        String username = "sa";
        String password = "";

        // try-with-resourcesで自動的にリソースをクローズ
        try (Connection conn = DriverManager.getConnection(url, username, password)) {
            IO.println("データベースに接続しました");

            // データベースのメタデータを取得
            DatabaseMetaData metaData = conn.getMetaData();
            IO.println("データベース製品: " + metaData.getDatabaseProductName());
            IO.println("バージョン: " + metaData.getDatabaseProductVersion());

        } catch (SQLException e) {
            System.err.println("データベース接続エラー: " + e.getMessage());
        }
    }
}
```

実行結果（H2 2.5.252の場合）：

```text
データベースに接続しました
データベース製品: H2
バージョン: 2.5.252 (2026-09-23)
```

### データの検索（READ）

`created_at`のような日付と時刻の列は、`getObject(列名, LocalDateTime.class)`で`LocalDateTime`として読み出します（「日付と時刻の列とjava.time」の節で説明します）。
`User`クラスはサンプルコードE-13で定義します。

<span class="listing-number">**サンプルコードE-8**</span>

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Statement;
import java.time.LocalDateTime;

public class SelectExample {
    private static final String SELECT_ALL_SQL = "SELECT * FROM users";
    private static final String SELECT_BY_ID_SQL = "SELECT * FROM users WHERE id = ?";

    public static void selectAllUsers(Connection conn) throws SQLException {
        try (Statement stmt = conn.createStatement();
             ResultSet rs = stmt.executeQuery(SELECT_ALL_SQL)) {

            while (rs.next()) {
                int id = rs.getInt("id");
                String username = rs.getString("username");
                String email = rs.getString("email");
                LocalDateTime createdAt = rs.getObject("created_at", LocalDateTime.class);

                IO.println("ID: %d, Username: %s, Email: %s, Created: %s".formatted(
                    id, username, email, createdAt));
            }
        }
    }

    public static User selectUserById(Connection conn, int userId) throws SQLException {
        try (PreparedStatement pstmt = conn.prepareStatement(SELECT_BY_ID_SQL)) {
            pstmt.setInt(1, userId);

            try (ResultSet rs = pstmt.executeQuery()) {
                if (rs.next()) {
                    return new User(
                        rs.getInt("id"),
                        rs.getString("username"),
                        rs.getString("email"),
                        rs.getObject("created_at", LocalDateTime.class)
                    );
                }
                return null;
            }
        }
    }
}
```

## PreparedStatementとSQL Injection対策

### SQL Injectionの危険性

SQL Injectionは、悪意のあるSQL文をアプリケーションに実行させる攻撃手法です。
次の例は、`users`テーブルの`password_hash`列（サンプルコードE-2）と照らし合わせてログインを判定しますが、脆弱な書き方です。

<span class="listing-number">**サンプルコードE-11**</span>

```java
import java.sql.Connection;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Statement;

// 危険な例 - 絶対に使用しないでください！
public class VulnerableExample {
    public static void unsafeLogin(Connection conn, String username, String passwordHash)
            throws SQLException {
        // ユーザー入力を直接SQL文に結合している（危険！）
        String sql = "SELECT * FROM users WHERE username = '" + username +
                    "' AND password_hash = '" + passwordHash + "'";

        try (Statement stmt = conn.createStatement();
             ResultSet rs = stmt.executeQuery(sql)) {
            if (rs.next()) {
                IO.println("ログイン成功");
            } else {
                IO.println("ログイン失敗");
            }
        }
    }
}
```

攻撃者がパスワードの欄に`' OR '1'='1`を入力すると、組み立てられるSQLの条件は次のようになります。

```text
WHERE username = 'x' AND password_hash = '' OR '1'='1'
```

`AND`は`OR`より先に評価されるため、この条件はどの行でも真になります。
ユーザー名もパスワードも知らないのに「ログイン成功」と表示されてしまいます。

### PreparedStatementによる安全な実装

`PreparedStatement`では、`?`の位置に入る値はSQL文の一部としてではなく、ただの値として扱われます。
同じ入力を渡しても、`'`を含む文字列のパスワードとして比べるだけなので、ログインは失敗します。

<span class="listing-number">**サンプルコードE-12**</span>

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class SecureExample {
    private static final String LOGIN_SQL =
        "SELECT * FROM users WHERE username = ? AND password_hash = ?";

    public static boolean secureLogin(Connection conn, String username, String passwordHash)
            throws SQLException {
        try (PreparedStatement pstmt = conn.prepareStatement(LOGIN_SQL)) {
            // パラメーターとして値を渡すことで、SQL Injectionを防ぐ
            pstmt.setString(1, username);
            pstmt.setString(2, passwordHash);

            try (ResultSet rs = pstmt.executeQuery()) {
                return rs.next();
            }
        }
    }
}
```

この例はSQL Injectionの対策を示すために単純にしています。
実際のシステムでは、ユーザー名で行を取り出したあと、パスワード用のハッシュ関数（bcryptやArgon2など）を使うライブラリでパスワードとハッシュ値を照合します。

## DAOパターンの実装

### DAOパターンとは

DAO（Data Access Object）パターンは、データアクセスロジックをビジネスロジックから分離するデザインパターンです。

### エンティティクラス

<span class="listing-number">**サンプルコードE-13**</span>

```java
import java.time.LocalDateTime;

public class User {
    private int id;
    private String username;
    private String email;
    private LocalDateTime createdAt;

    // データベースから読み出したユーザー用のコンストラクター
    public User(int id, String username, String email, LocalDateTime createdAt) {
        this.id = id;
        this.username = username;
        this.email = email;
        this.createdAt = createdAt;
    }

    // IDなしのコンストラクター（新規作成用）
    public User(String username, String email) {
        this.username = username;
        this.email = email;
    }

    // getterとsetter
    public int getId() { return id; }
    public void setId(int id) { this.id = id; }

    public String getUsername() { return username; }
    public void setUsername(String username) { this.username = username; }

    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }

    public LocalDateTime getCreatedAt() { return createdAt; }
    public void setCreatedAt(LocalDateTime createdAt) { this.createdAt = createdAt; }

    @Override
    public String toString() {
        return "User[id=%d, username=%s, email=%s, createdAt=%s]".formatted(
            id, username, email, createdAt);
    }
}
```

### DAO実装クラス

`create`では、データベースが振ったIDを`getGeneratedKeys`で受け取り、その行を読み直して返します。
登録日時（`created_at`）はデータベースが既定値として付けるので、Javaの側で時刻を作らずに、データベースの値をそのまま使います。

<span class="listing-number">**サンプルコードE-15**</span>

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Statement;
import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.List;
import java.util.Optional;

public class UserDaoImpl implements UserDao {
    private final Connection connection;

    public UserDaoImpl(Connection connection) {
        this.connection = connection;
    }

    @Override
    public User create(User user) throws SQLException {
        String sql = "INSERT INTO users (username, email) VALUES (?, ?)";

        try (PreparedStatement pstmt = connection.prepareStatement(
                sql, Statement.RETURN_GENERATED_KEYS)) {
            pstmt.setString(1, user.getUsername());
            pstmt.setString(2, user.getEmail());

            int affectedRows = pstmt.executeUpdate();
            if (affectedRows == 0) {
                throw new SQLException("ユーザーの作成に失敗しました");
            }

            // 自動生成されたIDを取得し、データベースが付けた登録日時ごと読み直す
            try (ResultSet generatedKeys = pstmt.getGeneratedKeys()) {
                if (generatedKeys.next()) {
                    int id = generatedKeys.getInt(1);
                    return findById(id).orElseThrow(
                        () -> new SQLException("作成したユーザーが見つかりません"));
                } else {
                    throw new SQLException("IDの取得に失敗しました");
                }
            }
        }
    }

    @Override
    public Optional<User> findById(int id) throws SQLException {
        String sql = "SELECT * FROM users WHERE id = ?";

        try (PreparedStatement pstmt = connection.prepareStatement(sql)) {
            pstmt.setInt(1, id);

            try (ResultSet rs = pstmt.executeQuery()) {
                if (rs.next()) {
                    return Optional.of(mapResultSetToUser(rs));
                }
                return Optional.empty();
            }
        }
    }

    @Override
    public Optional<User> findByUsername(String username) throws SQLException {
        String sql = "SELECT * FROM users WHERE username = ?";

        try (PreparedStatement pstmt = connection.prepareStatement(sql)) {
            pstmt.setString(1, username);

            try (ResultSet rs = pstmt.executeQuery()) {
                if (rs.next()) {
                    return Optional.of(mapResultSetToUser(rs));
                }
                return Optional.empty();
            }
        }
    }

    @Override
    public List<User> findAll() throws SQLException {
        String sql = "SELECT * FROM users ORDER BY id";
        List<User> users = new ArrayList<>();

        try (Statement stmt = connection.createStatement();
             ResultSet rs = stmt.executeQuery(sql)) {

            while (rs.next()) {
                users.add(mapResultSetToUser(rs));
            }
        }

        return users;
    }

    @Override
    public boolean update(User user) throws SQLException {
        String sql = "UPDATE users SET username = ?, email = ? WHERE id = ?";

        try (PreparedStatement pstmt = connection.prepareStatement(sql)) {
            pstmt.setString(1, user.getUsername());
            pstmt.setString(2, user.getEmail());
            pstmt.setInt(3, user.getId());

            return pstmt.executeUpdate() > 0;
        }
    }

    @Override
    public boolean delete(int id) throws SQLException {
        String sql = "DELETE FROM users WHERE id = ?";

        try (PreparedStatement pstmt = connection.prepareStatement(sql)) {
            pstmt.setInt(1, id);
            return pstmt.executeUpdate() > 0;
        }
    }

    private User mapResultSetToUser(ResultSet rs) throws SQLException {
        return new User(
            rs.getInt("id"),
            rs.getString("username"),
            rs.getString("email"),
            rs.getObject("created_at", LocalDateTime.class)
        );
    }
}
```

## 日付と時刻の列とjava.time

JDBC 4.2（Java 8）からは、日付と時刻の列をjava.timeのクラスで直接読み書きできます。
古い`java.sql.Date`・`java.sql.Timestamp`は`java.util.Date`を継承した可変のクラスなので、新しく書くコードではjava.timeのクラスを使います（java.time APIは付録Fで紹介しています）。

| SQLの型 | Javaのクラス |
|---|---|
| `DATE` | `LocalDate` |
| `TIME` | `LocalTime` |
| `TIMESTAMP` | `LocalDateTime` |
| `TIMESTAMP WITH TIME ZONE` | `OffsetDateTime` |

読み出すときは`ResultSet`の`getObject(列, クラス)`を、書き込むときは`PreparedStatement`の`setObject(番号, 値)`を使います。
次の例は、指定した期間に登録されたユーザーを検索します。

<span class="listing-number">**サンプルコードE-17**</span>

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.List;

public class DateRangeExample {
    private static final String SQL =
        "SELECT * FROM users WHERE created_at >= ? AND created_at < ? ORDER BY created_at";

    public static List<User> findCreatedBetween(Connection conn,
            LocalDateTime from, LocalDateTime to) throws SQLException {
        List<User> users = new ArrayList<>();
        try (PreparedStatement pstmt = conn.prepareStatement(SQL)) {
            pstmt.setObject(1, from);   // LocalDateTimeをTIMESTAMPとして渡す
            pstmt.setObject(2, to);

            try (ResultSet rs = pstmt.executeQuery()) {
                while (rs.next()) {
                    users.add(new User(
                        rs.getInt("id"),
                        rs.getString("username"),
                        rs.getString("email"),
                        rs.getObject("created_at", LocalDateTime.class)));
                }
            }
        }
        return users;
    }
}
```

`TIMESTAMP`型（タイムゾーンなし）の列には、時差の情報が残りません。
複数のタイムゾーンから使うシステムでは、`TIMESTAMP WITH TIME ZONE`型の列と`OffsetDateTime`を使うか、UTCにそろえて保存するなど、保存する時刻の基準を決めておきます。

## トランザクション管理

### トランザクションの基本

トランザクションは、複数のデータベース操作を1つの作業単位として扱う仕組みです。ACID特性（Atomicity、Consistency、Isolation、Durability）を保証します。

送金の例で使う口座のテーブルは次のとおりです。
金額は誤差の出ない`DECIMAL`型で持ち、Javaの側では`BigDecimal`で扱います（`double`は2進数の浮動小数点数なので、0.1のような値を正確に表せません）。

<span class="listing-number">**サンプルコードE-18**</span>

```sql
CREATE TABLE accounts (
    id INT PRIMARY KEY,
    owner VARCHAR(50) NOT NULL,
    balance DECIMAL(12, 2) NOT NULL CHECK (balance >= 0)
);

INSERT INTO accounts (id, owner, balance) VALUES
    (1, 'tanaka', 5000.00),
    (2, 'sato', 1000.00);
```

`setAutoCommit(false)`にすると、`commit()`を呼ぶまで変更が確定しません。
途中で例外が出たら`rollback()`ですべての変更を取り消します。

<span class="listing-number">**サンプルコードE-19**</span>

```java
import java.math.BigDecimal;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.SQLException;

public class TransactionExample {
    public static void transferMoney(Connection conn, int fromAccountId,
                                     int toAccountId, BigDecimal amount) throws SQLException {
        // 元の設定を覚えてから、自動コミットを無効化
        boolean originalAutoCommit = conn.getAutoCommit();
        conn.setAutoCommit(false);

        try {
            // 送金元から減額
            deductBalance(conn, fromAccountId, amount);

            // 送金先に加算
            addBalance(conn, toAccountId, amount);

            // すべて成功したらコミット
            conn.commit();
            IO.println("送金が完了しました");

        } catch (SQLException e) {
            // エラーが発生したらロールバック
            conn.rollback();
            System.err.println("送金に失敗しました: " + e.getMessage());
            throw e;
        } finally {
            // 自動コミットを元の設定に戻す
            conn.setAutoCommit(originalAutoCommit);
        }
    }

    private static void deductBalance(Connection conn, int accountId, BigDecimal amount)
            throws SQLException {
        String sql = "UPDATE accounts SET balance = balance - ? WHERE id = ? AND balance >= ?";
        try (PreparedStatement pstmt = conn.prepareStatement(sql)) {
            pstmt.setBigDecimal(1, amount);
            pstmt.setInt(2, accountId);
            pstmt.setBigDecimal(3, amount);

            int rowsAffected = pstmt.executeUpdate();
            if (rowsAffected == 0) {
                throw new SQLException("残高不足または口座が存在しません");
            }
        }
    }

    private static void addBalance(Connection conn, int accountId, BigDecimal amount)
            throws SQLException {
        String sql = "UPDATE accounts SET balance = balance + ? WHERE id = ?";
        try (PreparedStatement pstmt = conn.prepareStatement(sql)) {
            pstmt.setBigDecimal(1, amount);
            pstmt.setInt(2, accountId);

            int rowsAffected = pstmt.executeUpdate();
            if (rowsAffected == 0) {
                throw new SQLException("送金先口座が存在しません");
            }
        }
    }
}
```

たとえば`transferMoney(conn, 1, 3, new BigDecimal("1000"))`のように存在しない口座3へ送金すると、口座1からの減額は成功したあとで加算が失敗します。
このときロールバックによって口座1の減額も取り消され、残高は5000.00のまま残ります。

## コネクションプール

### コネクションプールの必要性

データベース接続の確立は時間のかかる処理です。アプリケーションの性能を向上させるため、接続を再利用するコネクションプールを使用します。
プールから取り出した接続の`close()`は、接続を切らずにプールへ返す動作になります。

### HikariCPの使用例

HikariCPは高性能なコネクションプールライブラリです。
Mavenの座標は`com.zaxxer:HikariCP:7.1.0`（2026年11月時点の最新版）です。
HikariCPはログの出力にSLF4J（`org.slf4j:slf4j-api`）を使います。
ビルドツールを使えば自動で入りますが、JARを手で集める場合は`slf4j-api-2.0.17.jar`もクラスパスに加えます。
ログの出力先（`slf4j-simple`など）を加えていないと、起動時に「No SLF4J providers were found.」という警告が出ますが、プールの動作には影響しません。

HikariCPの設定は、`maximumPoolSize`（接続の最大数）だけを決め、`minimumIdle`は指定しないことが推奨されています。
指定しなければ、常に最大数の接続を用意した固定サイズのプールになります。

<span class="listing-number">**サンプルコードE-20**</span>

```java
import com.zaxxer.hikari.HikariConfig;
import com.zaxxer.hikari.HikariDataSource;
import java.sql.Connection;
import java.sql.SQLException;

public class ConnectionPoolExample {
    private static final HikariDataSource dataSource;

    static {
        HikariConfig config = new HikariConfig();
        // DB_CLOSE_DELAY=-1: 接続がすべてプールに戻っても、メモリ上のデータベースを消さない
        config.setJdbcUrl("jdbc:h2:mem:testdb;DB_CLOSE_DELAY=-1");
        config.setUsername("sa");
        config.setPassword("");

        // コネクションプールの設定
        config.setMaximumPoolSize(10);         // 接続の最大数
        config.setConnectionTimeout(30_000);   // 接続を待つ最長時間（ミリ秒）
        config.setMaxLifetime(1_800_000);      // 1つの接続を使い続ける最長時間（ミリ秒）

        dataSource = new HikariDataSource(config);
    }

    public static Connection getConnection() throws SQLException {
        return dataSource.getConnection();
    }

    public static void close() {
        dataSource.close();
    }
}
```

### コネクションプールを使用したDAO

処理のたびにプールから接続を借り、使い終わったら`close()`で返します。
次の例では、ユーザーの作成と検索で別々に接続を借りていますが、接続を確立し直す時間はかかりません。

<span class="listing-number">**サンプルコードE-21**</span>

```java
import java.sql.Connection;
import java.sql.SQLException;

public class PooledDaoExample {
    public static void main(String[] args) {
        try {
            // テーブルの作成
            try (Connection conn = ConnectionPoolExample.getConnection()) {
                CreateTableExample.createTable(conn);
            }

            // ユーザーの作成（接続を借りて、終わったら返す）
            try (Connection conn = ConnectionPoolExample.getConnection()) {
                UserDao userDao = new UserDaoImpl(conn);
                for (int i = 1; i <= 100; i++) {
                    userDao.create(new User("user" + i, "user" + i + "@example.com"));
                }
                IO.println("100人のユーザーを作成しました");
            }

            // 検索（別の処理として、もう一度接続を借りる）
            try (Connection conn = ConnectionPoolExample.getConnection()) {
                UserDao userDao = new UserDaoImpl(conn);
                IO.println("登録されているユーザー: " + userDao.findAll().size() + "人");
            }

        } catch (SQLException e) {
            e.printStackTrace();
        } finally {
            // アプリケーション終了時にプールを閉じる
            ConnectionPoolExample.close();
        }
    }
}
```

## バッチ処理

### 大量データの一括処理

大量のデータを挿入するときは、`addBatch()`でSQLをためておき、`executeBatch()`でまとめて送ります。
1件ごとに送るよりデータベースとの通信の往復が減るため、速くなります。
どれだけ速くなるかは、データベースや件数、ネットワークの環境によって変わります。
MySQLでは、接続URLに`rewriteBatchedStatements=true`を付けないと、ドライバーが1件ずつ送るためバッチの効果がほとんど出ません。

<span class="listing-number">**サンプルコードE-22**</span>

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.SQLException;
import java.util.List;

public class BatchProcessingExample {
    private static final int BATCH_SIZE = 1000;

    public static void batchInsertUsers(Connection conn, List<User> users)
            throws SQLException {
        String sql = "INSERT INTO users (username, email) VALUES (?, ?)";

        // 元の設定を覚えてから、自動コミットを無効化
        boolean originalAutoCommit = conn.getAutoCommit();
        conn.setAutoCommit(false);

        try (PreparedStatement pstmt = conn.prepareStatement(sql)) {
            int count = 0;
            for (User user : users) {
                pstmt.setString(1, user.getUsername());
                pstmt.setString(2, user.getEmail());
                pstmt.addBatch();
                count++;

                // 1000件たまるごとに送る
                if (count % BATCH_SIZE == 0) {
                    pstmt.executeBatch();
                }
            }

            // 残りのバッチを実行
            pstmt.executeBatch();
            conn.commit();

            IO.println(users.size() + "件のデータを挿入しました");

        } catch (SQLException e) {
            conn.rollback();
            throw e;
        } finally {
            conn.setAutoCommit(originalAutoCommit);
        }
    }
}
```


## まとめ

本付録では、JavaのJDBCを使用したデータベースプログラミングの基礎を学習しました。

- JDBCは、Javaからデータベースにアクセスするための標準APIである
- CRUD操作は、Create、Read、Update、Deleteの基本操作である
- PreparedStatementを使うと、SQL Injectionを防いで安全にSQLを実行できる
- 日付と時刻の列は、getObjectとsetObjectでjava.timeのクラスとして扱える
- トランザクションは、複数の操作を1つの作業単位として扱う
- DAOパターンは、データアクセスロジックを分離して再利用しやすくする
- コネクションプールは、接続を再利用して性能を上げる
- バッチ処理は、大量データをまとめて送って処理する

これらの技術を組み合わせることで、実践的なデータベースアプリケーションを開発できます。
