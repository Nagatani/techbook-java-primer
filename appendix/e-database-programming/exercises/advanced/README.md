# 付録E 発展課題

## 学習目標

- DAOパターンで、データベースを読み書きする処理をインターフェイスと実装クラスに分ける
- `TIMESTAMP`・`DATE`の列を`setObject`と`getObject`で`LocalDateTime`・`LocalDate`として読み書きする
- 日付の範囲を「始まり以上、終わりの翌日の0時未満」の条件で検索する
- `addBatch`・`executeBatch`で多数の行をまとめて送り、トランザクションと組み合わせる
- バッチの途中で失敗したとき（`BatchUpdateException`）に、すべてを取り消す

## 課題一覧

### 課題1: 予定表のDAO

**ファイル**（このフォルダーのファイルは解答例です）:

```
advanced/task1-schedule-dao/
├── Event.java         予定（レコード）
├── EventDao.java      DAOのインターフェイス
├── JdbcEventDao.java  JDBCで書いたDAOの実装クラス
└── ScheduleApp.java   mainメソッド
```

授業やアルバイトの予定を登録し、日付で検索する予定表を、DAOパターンで作成してください。
日時は`LocalDateTime`で扱い、データベースには`TIMESTAMP`型の列で保存します。

**要求仕様**:

- `Event`（レコード）
    - ID・題名・始まりの日時・終わりの日時・場所（なくてもよい）を持つ
    - 題名が空のときと、終わりの日時が始まりの日時以前のときは`IllegalArgumentException`を投げる
    - IDを付け替えた予定を返す`withId`と、長さを変えずに始まりの日時を移した予定を返す`movedTo`を持つ
- `EventDao`（インターフェイス）
    - `create`（登録し、データベースが振ったIDを付けた予定を返す）、`findById`（`Optional`で返す）、`update`、`delete`
    - `findOn(日付)`はその日に始まる予定を、`findBetween(始めの日, 終わりの日)`は終わりの日を含む期間に始まる予定を、始まりの日時の順に返す
    - `findOverlapping(始まり, 終わり)`は、その時間帯と重なる予定を返す。17時に終わる予定と17時に始まる予定は重ならないものとする
- `JdbcEventDao`
    - コンストラクターで`Connection`を受け取り、`createTable`で`events`テーブルを作る
    - 日時は`setObject(番号, LocalDateTime)`で渡し、`getObject(列名, LocalDateTime.class)`で読む（`java.sql.Timestamp`は使わない）
    - `findBetween`は`start_at >= ? AND start_at < ?`とし、2つ目の`?`には終わりの日の翌日の0時を渡す
- `ScheduleApp`
    - 2026年11月16日（月）からの予定を登録し、1日分と1週間分の予定を表示する
    - 予定を足す前に`findOverlapping`で確かめ、重なる予定があれば登録しない
    - 予定の移動（`update`）と削除（`delete`）を行い、削除した予定が`findById`で見つからないことを確かめる

**実行例**:

```text
=== 予定の登録 ===
登録しました: 1 プログラミング演習
登録しました: 2 サークルのミーティング
登録しました: 3 アルバイト
登録しました: 4 ゼミの発表
登録しました: 5 友人と映画
登録しました: 6 レポートの締め切り

=== 11/16(月)の予定 ===
  11/16(月) 09:00-10:30 プログラミング演習（情報演習室A）

=== 11/16(月)から1週間の予定 ===
  11/16(月) 09:00-10:30 プログラミング演習（情報演習室A）
  11/16(月) 18:00-19:00 サークルのミーティング（部室）
  11/18(水) 17:00-21:00 アルバイト（書店）
  11/19(木) 13:00-14:30 ゼミの発表（305教室）

=== 重なりの確認 ===
11/18(水) 16:00-17:30 歯医者: 「アルバイト」と重なるので登録しません

  11/18(水) 15:30-17:00 歯医者（駅前歯科）
```

11月23日のレポートの締め切りは、1週間（16日〜22日）の範囲の外なので表示されません。

### 課題2: 1年分の歩数をバッチ処理で登録する

**ファイル**（このフォルダーのファイルは解答例です）:

```
advanced/task2-batch-steps/
├── DailySteps.java         1日の歩数（レコード）と見本の記録の作成
├── StepBatchImporter.java  バッチ処理での登録と月ごとの集計
└── StepBatchApp.java       mainメソッド
```

スマートフォンで記録した1年分（365日）の歩数を、バッチ処理でデータベースに登録し、月ごとに集計するプログラムを作成してください。

**要求仕様**:

- `DailySteps`（レコード）
    - 日付（`LocalDate`）と歩数を持つ。歩数が負なら`IllegalArgumentException`を投げる
    - `sample(始めの日, 終わりの日)`で見本の記録を作る。何度実行しても同じ値になるよう、乱数を使わずに日付から計算する（解答例は「4000 + (年の何日目 × 37 % 50) × 100」、土日はさらに2000を足す）
- `StepBatchImporter`
    - `daily_steps`テーブルは、日付（`DATE`型、主キー）と歩数を持つ。`DAY`や`MONTH`はSQLの予約語なので、列の名前には使わない
    - `importAll(記録のList)`は、自動コミットを止め、`addBatch`で記録をためて、決めた件数（解答例は100件）ごとに`executeBatch`で送る。最後に残りを送り、`commit`する
    - 登録した行数と`executeBatch`を呼んだ回数を、レコード`ImportResult`で返す
    - 途中で失敗したら`rollback`で、その呼び出しで登録したものをすべて取り消してから、例外を投げ直す
    - `monthlySummaries()`は、`EXTRACT(MONTH FROM 列)`で月ごとに`GROUP BY`し、日数・合計・目標（8000歩）を達成した日数を返す。達成した日数は`SUM(CASE WHEN steps >= ? THEN 1 ELSE 0 END)`で数える
- `StepBatchApp`
    - 2026年の365日分を登録し、月ごとの集計と1年の合計を表示する
    - 2027年1月の10日分の途中に、登録済みの2026年12月31日を紛れ込ませて登録し、主キーの重複で失敗すること、行数が365件のままであることを確かめる

**実行例**:

## 実装のヒント

```java
// LocalDateTimeをそのまま渡し、そのまま受け取る
pstmt.setObject(1, from.atStartOfDay());              // 始めの日の0時
pstmt.setObject(2, to.plusDays(1).atStartOfDay());    // 終わりの日の翌日の0時
LocalDateTime start = rs.getObject("start_at", LocalDateTime.class);
```

- 「終わりの日の23時59分59秒以下」と書くと、59秒より後の時刻（ミリ秒を含むもの）を取りこぼす。「翌日の0時未満」と書けば、その日の終わりまでを漏れなく含められる
- 始まりs1・終わりe1の時間帯と、始まりs2・終わりe2の時間帯が重なる条件は「s1 < e2 かつ s2 < e1」である。SQLでは`start_at < ? AND end_at > ?`になる
- DAOのインターフェイスには`SQLException`が出てくるが、呼び出す側（`ScheduleApp`）は`Connection`やSQLの文を知らずに済む
- `executeBatch`は、ためたSQLごとの変更した行数を`int`の配列で返す
- バッチの途中で失敗すると、`SQLException`の子クラスの`BatchUpdateException`が投げられる。どこまで実行されたかはドライバーによって違うので、トランザクションでまとめて取り消すのが確実である
- 日付から曜日の文字を出すには、`DateTimeFormatter.ofPattern("M/d(E)", Locale.JAPANESE)`のようにロケールを指定する（java.time APIは付録Fで紹介している）

## 応用のポイント

1. 処理の分け方
    - SQLは`JdbcEventDao`と`StepBatchImporter`のなかだけにあり、mainは予定や記録のオブジェクトだけを扱う
2. 日時の扱い
    - データベースとのやり取りでも`LocalDateTime`・`LocalDate`のまま扱い、文字列や`java.sql.Timestamp`に変換しない
3. まとめて送る・まとめて取り消す
    - バッチ処理で通信の回数を減らし、トランザクションで「全部登録されたか、1件も登録されていないか」のどちらかにする
