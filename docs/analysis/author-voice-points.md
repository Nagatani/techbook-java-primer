# 著者に書き足してほしい箇所（AIらしさを減らすために）

2026-11-24に、第1〜26章を章ごとに読んで洗い出した。
本文は語彙の面ではかなり整っているが、次の点でAIが書いた文章に見える。
どれも著者の知識・経験・立場がなければ書けない内容なので、Claudeでは埋められない。

- 判断がない
    + AとBを並べて「それぞれ利点があります」「どちらでも満たせます」で終わる
- 講義の経験がない
    + 学生が実際につまずく点、よく受ける質問、C言語から来た学生の誤解が1つも書かれていない
- 重みが均一
    + 必修の所と読み飛ばしてよい所の案内がない。発展的な節が基本と同じ密度で続く
- 冒頭が宣言、末尾が一般論
    + 「この章では〜について学習します」で始まり、「〜を理解することで、より良い〜」で終わる
- まとめが再掲
    + 本文の見出しを箇条書きで並べ直しただけで、判断の基準がない
- 学習目標が漢語の名詞止め
    + 「〜の理解」「〜の活用」
- コラムが伝聞
    + 「現場のエンジニアは」「よく口にされます」が主語で、著者の体験がない

## 使い方

- 各項目の「提案」は著者への問いの形にしてある。答えをメモ書きで返してもらえれば、本文の文に整えて入れるのはClaudeが行う（textlint・脚注・文体の規則に合わせる）
- 体験談は作らない。経験がない項目は「なし」で飛ばしてよい。その場合は、判断や重み付けの1文だけで十分なことが多い
- 行番号は2026-11-24時点のもの。本文を直すとずれるので、節名と引用で探す
- 種類は次のとおり。判断（どれを勧めるか）、経験（講義や開発での実例）、つまずき（学生の誤りとその頻度）、重み付け（読み飛ばしてよいかどうか）、動機（困る場面から始める）、冒頭、まとめ、学習目標、具体化（抽象語の中身）

## 全章に共通して効くもの（先に決めると速い）

2026-11-24に1〜4を決めた（結果は`TODO.md`の「AIらしさを減らす」と`docs/guides/book-defaults.md`）。残りは5。

章ごとに答える前に、次の5つを決めておくと、多くの項目が同じ形で片づく。

1. 学習目標の書き方
    - 26章すべてが名詞止め。「章を終えたら〜できる」の形に統一するか決める。決まれば、演習の内容に合わせた文案はClaudeが作れる（著者は確認だけ）
2. まとめの型
    - 本文の再掲をやめ、「迷ったときの判断の順序」と「最低限持ち帰ってほしい1つ」を書く形にするか決める
3. 読み飛ばしの案内
    - 「初めて読むときは飛ばしてよい」の印をどう示すか（節の頭の1文、見出しの記号、コラムに移すなど）。対象の節は各章の【重み付け】の項目にある
4. 本書の既定の選択
    - 章をまたいで同じ問いが何度も出る。Maven/Gradle、Gson/Jackson、H2/SQLite、検査例外/非検査例外、ArrayList/LinkedList、for文/Stream、Swingを選んだ理由。本書としての答えを一覧で決めておけば、各章の判断の1文はそこから書ける
5. 生成AIと講義の方針
    - 第1章のコラムのほか、第24章（AIが出す連結のSQL）、第26章（AIの提案をそのまま入れる）にも関わる
