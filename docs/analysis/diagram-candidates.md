# 図を加えると分かりやすくなる箇所（2026-11-11）

現行の原稿（23章）を読み、文章・番号付きリスト・コードだけで説明していて、図があると理解しやすくなる箇所を洗い出した。行番号は2026-11-11時点の原稿のもの。

以前の一覧`docs/diagrams/diagram-recommendations.md`（2025-08、旧24章構成）は章番号がずれており、ほとんどが未着手のため、こちらを正とする。

## 選んだ基準

- C言語から来た読者がつまずきやすい、目に見えない仕組み（参照とメモリ、実行の順序、スレッドの時間関係）を文章だけで説明している
- 手順や状態を番号付きリストで並べていて、図にすると関係が一目で分かる
- 本文の説明がコードだけで、コードの前後に構造の説明がない
- すでに図がある箇所（21枚）と、表で十分に説明できている箇所は除いた

図を作るときは`docs/diagrams/chapterXX-内容.mmd`に置き、`npm run check:diagrams`で文字の大きさを確かめる（CLAUDE.mdの項目11）。

## 優先度A: 本書の中心となる概念で、図がないと理解しにくい

1. 3章「クラス、インスタンス、オブジェクトの関係」（chapter03-oop-basics.md:230）
    + 設計図と家のたとえを文章だけで説明している
    + 1つのクラスから複数のインスタンスができ、それぞれが別のフィールド値を持つ図にする
2. 3章 参照とメモリ（オブジェクトの作成、オブジェクト配列 :1998付近、`==`と`equals` :2193）
    + 本文は「参照の配列であることを理解し」と書くが、変数・参照・オブジェクトの関係を示す図がない。1〜4章にはスタックとヒープの説明もない
    + 変数からオブジェクトへの矢印、`null`の要素、同じ内容の別オブジェクトと同じオブジェクトを指す2つの変数を描く。C言語のポインタと対比すると、本書の読者に伝わりやすい
3. 3章「staticとインスタンスメンバーの違い」（:1776）
    + リストだけで説明している
    + クラスに1つだけあるstaticフィールドと、インスタンスごとのフィールドを並べた図にする
4. 12章「遅延評価のしくみ」（chapter12-advanced-collections.md:185）

5. 13章 例外の制御の流れ（`try-catch-finally` :89、`throws`による委譲）

6. 15章「共有リソースと同期制御」（chapter15-multithreading.md:903）
    + ATMの二重引き出しを番号付きリストで説明している

8. 21章「疎結合設計（Dependency Injection）」（chapter21-unit-testing.md:192）
    + 具象クラスに直接依存する設計と、インターフェイスに依存して外から注入する設計の違いを文章だけで説明している
