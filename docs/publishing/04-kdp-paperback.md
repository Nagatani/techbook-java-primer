# Amazon KDPのペーパーバック

KDP（Kindle ダイレクト・パブリッシング）のペーパーバックは、注文を受けてから1冊ずつ印刷する形（オンデマンド印刷）です。入稿するものは「本文のPDF」と「表紙のPDF」の2つで、本文は`npm run build:kdp`で作ります。表紙を作るしくみはまだありません（下の「表紙を作る」）。

## 本文のPDFを作る

```bash
npm run build:kdp   # → output/techbook-java-primer-kdp.pdf
```

正規版の組版に、KDP向けの次の変更を加えたPDFができます。

- 1ページ目を紺の表紙から白地の本扉にする（`theme/my-theme/kdp-title-theme.css`）。表紙は別のファイルで入稿するため
- のど（綴じる側の余白）を24mm、小口（外側）を18mmにする（`theme/my-theme/kdp-theme.css`）。本文の幅は通常のPDFと同じ132mm
- 上端の柱を紙の端から8mmまで下げる
- 裁ち落とし（塗り足し）とトンボは付けない。判型はB5（176×250mm）のまま

## 本文のPDFを確かめる

紙面の中身は[02-pdf.md](02-pdf.md)で正規版のPDFを見ていれば、見直す必要はありません。KDPのPDFでは次の点だけを見ます。

1. ページ数を確かめる
    ```bash
    mdls -name kMDItemNumberOfPages output/techbook-java-primer-kdp.pdf
    ```
2. ページ数が下の表のどの区切りに入るかを見て、のどの幅が足りているか確かめる
3. 1ページ目が白地の本扉で、紺の地や模様が出ていない
4. 見開きで、のど側の余白が外側より広い（右ページは左が広く、左ページは右が広い）

### KDPの余白の条件（2026-11-18に確かめた値）

| ページ数 | のどの最小値 |
|---|---|
| 24〜150 | 9.6mm（0.375インチ） |
| 151〜300 | 12.7mm（0.5インチ） |
| 301〜500 | 15.9mm（0.625インチ） |
| 501〜700 | 19.1mm（0.75インチ） |
| 701〜828 | 22.3mm（0.875インチ） |

- 小口・天・地は、裁ち落としなしで6.4mm（0.25インチ）以上
- 白黒印刷のページ数の上限は828ページ。これを超えるとKDPのペーパーバックでは出せない
- いまの設定（のど24mm）は701〜828ページに合わせてある。ページ数が700以下になってものどが広すぎるだけで入稿はできるが、828を超えたら内容を削る必要がある

のどの幅を変えるときは、`kdp-theme.css`ののどと小口を同じだけ逆向きに動かし、本文の幅（132mm）を変えないようにします。本文の幅が変わると、コードの1行に入る桁数（73桁）が変わり、`check:code-wrap`の前提が崩れます。

### 余白を数値で測る（任意）

KDPは入稿したPDFの余白を自動で検査し、足りなければプレビューで警告を出します。手元で前もって測りたいときは、PyMuPDFで各ページの文字と画像の枠を取り、紙の端からの距離の最小値を出します。2026-11-18に測った結果は、のどから22.4mm以上、小口から7.3mm以上、天から8.0mm以上、地から10.7mm以上でした。

## 表紙を作る

KDPのペーパーバックの表紙は、裏表紙・背・表表紙を1枚につなげたPDF（またはKDPの「表紙作成ツール」で作ったもの）です。大きさはページ数と紙で決まります。

### 大きさの計算（白い紙、白黒印刷）

| 部分 | 計算 | 766ページのとき |
|---|---|---|
| 背幅 | ページ数 × 0.0572mm（0.002252インチ） | 43.8mm |
| 幅 | 塗り足し3.2mm ＋ 裏表紙176mm ＋ 背幅 ＋ 表表紙176mm ＋ 塗り足し3.2mm | 402.2mm |
| 高さ | 塗り足し3.2mm ＋ 250mm ＋ 塗り足し3.2mm | 256.4mm |

クリーム色の紙を選ぶと背幅の係数が変わります（1ページ0.0635mm、0.0025インチ）。

KDPのヘルプにある「表紙の計算ツールとテンプレート」に、判型（6.93×9.84インチ）・ページ数・紙の色を入れると、背の位置と文字を置いてはいけない範囲を描いたテンプレート（PDFとPNG）を取得できます。表紙はこのテンプレートに合わせて作るのが確実です。

### 表紙の注意点

- 文字や大事な絵は、仕上がりの線から3.2mm以上内側に置く
- 背の文字は、背の折り目から1.6mm（0.0625インチ）以上離す。背幅は印刷のたびに多少ずれるので、背の文字は小さめにする
- 裏表紙の右下にKDPがバーコードを印刷する（約50.8×30.5mm）。そこに絵や文字を置かない
- 本文のPDFの表紙（`manuscripts/cover.md`と`theme/my-theme/cover-theme.css`）の色と模様（`manuscripts/images/cover-motif.svg`）を流用すると、電子版の表紙とそろう
- 表紙をこのリポジトリのビルドで作るようにしたい場合は、Claudeに「KDPの表紙のPDFを作るビルドを加えて」と依頼してください（ページ数から背幅を計算する形にできます）

## KDPに入稿する

KDPの本棚で「ペーパーバック」を新しく作り、次のように設定します。

1. 本の詳細
    + 言語は日本語、書名・副題・著者名を正規版の表紙と奥付に合わせる
    + 内容紹介とキーワード、カテゴリーを入れる
2. コンテンツ
    + ISBNは、KDPが無料で割り当てるもの（選べる場合）を使うか、自分で取得したものを入れる。一度決めると変えられない
    + 印刷のオプションは「白黒、白い紙」（カラーはページ数の上限が小さく、費用も高い）
    + 判型は「別の判型を選ぶ」から176×250mm（6.93×9.84インチ）
    + 裁ち落としは「なし」
    + 表紙の仕上げは光沢かマットを選ぶ
    + 原稿に`output/techbook-java-primer-kdp.pdf`、表紙に表紙のPDFをアップロードする
3. プレビュー
    + 「本のプレビューアーを起動」で、KDPが検出した問題（余白の不足、解像度の低い画像、文字が埋め込まれていないフォント）の一覧を見る。問題が出たら、その一覧のページ番号のところを本文のPDFで確かめて直す
    + 見開きで数か所をめくり、のどの余白と柱を見る
4. 校正刷り
    + 校正刷り（プルーフ）を注文できる場合は注文し、紙で文字の大きさ、コードの濃さ、背の文字の位置、綴じたときにのど側の文字が読めるかを確かめる
5. 価格
    + 印刷の費用はページ数で決まる。766ページは費用が大きいので、ロイヤリティの計算画面で最低価格を確かめてから価格を決める

## 内容を直して入れ替えるとき

1. 原稿を直し、[01-checks.md](01-checks.md)の検査を通す
2. `npm run build:kdp`で作り直し、ページ数が変わっていないか確かめる
3. ページ数が変わったら、背幅が変わるので表紙も作り直す
4. KDPの本棚で原稿（と表紙）を差し替えて、もう一度プレビューを通す
5. 版の表示を変えるかどうかは[07-release.md](07-release.md)の「版を重ねるとき」
