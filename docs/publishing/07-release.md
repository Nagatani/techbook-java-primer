# 出版の日に書き換えるところと、版を重ねるとき

## 出版の前に決めること

2026-11-19の時点で、次のことが決まっていません（`TODO.md`の「出版時に決めること」と同じ内容です）。

- 正規版の発行日
- 奥付に載せる項目（発行者、印刷所など。入稿先のサービスの指定に合わせる）
- 電子版の奥付の表示（「初版第1刷発行」は印刷の言い方。電子版では「電子版発行」などにするか）
- 正規版を出版した後も、Web版（ALPHA版）の公開を続けるか
- `scripts/`・`theme/`などビルドのしくみのライセンス（いまは「個別に問い合わせ」）

## 奥付を書き換える

奥付は`manuscripts/colophon.md`です。正規版だけに出る行は`edition-release`のクラスが付いた行です。

```html
<p class="colophon-date edition-release">2026年○月○日　初版第1刷発行</p>
```

「2026年○月○日」を発行日に書き換えます。ALPHA版の行（`edition-alpha`）はビルドした日が自動で入るので、触りません。

### 電子版だけ表示を変えたいとき

いまの奥付は、ペーパーバックとEPUBで同じ文字が出ます。電子版だけを「電子版発行」などにしたい場合は、出力先（`BOOK_TARGET`）で行を出し分けるしくみが要ります。`scripts/vfm-edition.js`の版の出し分けと同じ形で作れるので、Claudeに「奥付の発行の表示を電子版と紙の版で分けて」と依頼してください。

### 書き換えた後

```bash
npm run lint && npm run check:compliance   # 奥付も検査の対象
npm run build:release                      # 奥付のページを目で確かめる
```

確かめたら`docs: 正規版の奥付に発行日を入れる`のようにコミットします。

## 出版した後

- 出版に使ったコミットに印（タグ）を付けておくと、後で同じものを作り直せる
    ```bash
    git tag -a v1.0 -m "初版第1刷"
    git push origin v1.0    # pushするときだけ
    ```
- `TODO.md`の「出版時に決めること」を完了にし、決めた内容（発行日、入稿先、判型と紙、ISBN）を書き残す
- 入稿したファイル（`output/`の中身と表紙）を、リポジトリの外に保管しておく。`output/`はビルドのたびに上書きされる

## 版を重ねるとき

誤りを直して入稿し直すときは、次の順に進めます。

1. 誤りを直す。読者から報告された誤りは`docs/analysis/issues-tracking.md`に記録してから直す
2. 奥付の表示を変えるか決める（直した量が少なければ「初版第2刷発行」、大きく書き直したら「第2版第1刷発行」が一般的）。変える場合は、初版の日付の行を残して、その下に新しい行を足すのが市販の書籍の形
3. [01-checks.md](01-checks.md)の検査を通す
4. 出している形ごとに作り直して入れ替える（[04-kdp-paperback.md](04-kdp-paperback.md)・[05-kindle-epub.md](05-kindle-epub.md)・[06-press.md](06-press.md)の「内容を直して入れ替えるとき」）
5. タグを付ける（`v1.1`など）

Web版（ALPHA版）は、mainへpushするたびに直した内容で公開し直されます。
