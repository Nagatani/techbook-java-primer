# 校正の進め方

本文の校正（表現の改善、textlintの指摘への対応、内容の誤りの修正）を進めるときの手順と注意点です。
2025-08に`tools/`の分割・自動校正ツールで第1〜4章を校正しましたが、2026-11-09にそれらのツールは削除し、この手順に置き換えました。

## 手順

1. 対象の章の要約（`docs/summaries/chapterXX.md`）で節の構成と既知の問題をつかむ
2. 索引（`docs/book-index/`）の行範囲を使い、節ごとに本文を読む（章全体を一度に読まない）
3. 問題を1つずつ確かめて直す
    + サンプルコードは本文を直接直さず、`sample-code/`の全文を直してから`npm run samples:sync`する
4. 検査する
    + `npm run lint`（textlint）
    + `npm run check:structure`（章名・付録・演習・用語集の食い違い）
    + `npm run check:samples -- chapterXX`（サンプルコードを変えた場合）
5. `npm run index`と`npm run index:check`で、内容が変わった節の要約とハッシュを更新する
6. `git diff --word-diff`で全変更箇所を読み直してからコミットする

章をまたぐ校閲は、章ごとにサブエージェントへ任せ、指摘事項だけを受け取る。

## 自動変換をしない

正規表現による一括置換は、過去に文言の欠落や不自然な文を生んだ（Issue #013）。表現の修正は1か所ずつ文脈を読んで行う。

- 次の語は意味が文脈で変わるため、機械的に置き換えない
    + 「より」（比較と手段）、「から」（起点と理由）、「ため」（目的と原因）
    + 「によって」「により」「において」「における」
- 文法的に誤った簡潔化に注意する
    + 「保つことができます」→「保てます」（「保つできます」は誤り）
- 長い文を機械的に分割しない。区切る位置と接続のしかたは文ごとに決める
- コードブロックの中、技術用語、固有名詞は直さない

## 変更ごとに確かめること

- 日本語として自然か（声に出して読んで違和感がないか）
- 意味が変わっていないか
- 技術的に正確か
- 前後の文脈と整合しているか

迷ったら変更しない。元の表現が不自然でない限り維持し、判断が必要なものは著者に相談する。

## textlintの指摘への対応

- 文章のルールは`docs/writing-guidelines-textlint-compliance.md`を参照する
- 技術文書として適切な表現が指摘されることもある。無理に直さない（規約上の例外は`TODO.md`に記録している）
