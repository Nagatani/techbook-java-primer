# コラム作成ガイドライン

（2025-07-14作成、2026-11-16に現在の書き方に合わせて更新）

## コラムの目的

コラムは本文の流れを妨げることなく、次のような内容を提供する枠外の読み物です。

1. 補足的な技術情報（本文では深く触れない技術的詳細）
2. 歴史的背景（技術の発展や歴史的経緯）
3. 実務的なヒント（実際の開発現場で役立つ知識）
4. よくある誤解の解説（初学者が陥りやすい誤解の説明）

後の章で学ぶ内容は、コラムで先に説明せず「第N章で学びます」と誘導します（`CLAUDE.md`の方針12）。
1〜3文で済む余談は、コラムではなく脚注にします（`docs/guides/writing-guidelines-textlint-compliance.md`の11節）。

## コラムの記述方法

引用（blockquote）の1行目に、`{.column-section}`を付けた太字で「コラム：題」を書きます。
各行の先頭に`>`を付けます。

```markdown
> **コラム：Integer.parseIntのエラーから学ぶ**{.column-section}
>
> ### プログラミングにおけるエラーとの向き合い方
>
> サンプルコード1-13で`IO.readln`を使った入力処理を学習しました。
> （各行に`>`を付けて続ける）
```

- 題は必ず「コラム：」で始める（本書のコラムはすべてこの形）
- コラムの中の見出しはh3・h4にする
- コラムの中に脚注を置かない（脚注の規則）
- テーマには`<div class="column">`のスタイルも残っているが、原稿では使わない（`::: column`などほかの記法も使わない）
- コラムの中のコードブロックにも番号を付ける（例：第1章のサンプルコード1-14）

## 実例

本書のコラムは次のとおりです（2026-11-16時点）。

- 第1章「System.out.printlnとIOクラス」
- 第1章「Integer.parseIntのエラーから学ぶ」
- 第1章「生成AIと初学者のプログラミング学習」
- 第3章「システム開発に『銀の弾丸などない』」

## コラム作成時の注意点

1. 長さ
    + 本文の1/3程度を超えないようにする
2. 位置
    + 関連する本文の直後に配置する
3. 内容
    + 本文の理解に必須ではない補足情報にとどめる
4. 文体
    + 本文と同じですます調
5. 図表
    + 必要に応じて図表やコードを含めてもよい

## スタイルの特徴

テーマ（`theme/my-theme/theme.css`の`blockquote:has(strong.column-section)`）で、次の見た目になります。

- 薄い灰色の地、細い枠、上端に青の太い線
- 題は枠の上端の行に置き、下に細い罫線を引く（13Q、青）
- 余白は枠の側だけに付け、中の段落には付けない
