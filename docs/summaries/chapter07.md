# 第7章 抽象クラスとインターフェイス 要約

行番号・サンプルコード番号の正確な対応は `docs/book-index/chapter07-abstract-classes-and-interfaces.md` を参照する。

## 章の概要

- 「図形の面積は親クラスでは決められない」という例を動機に、抽象クラス・抽象メソッドとインターフェイスを教える
- 両者の使い分けをis-a関係とcan-do関係で整理し、「迷ったらインターフェイス」という経験則を示す
- Java 8以降のdefaultメソッド・staticメソッド、ダイヤモンド問題と優先順位規則を扱う
- 後半はMixin、トレイト、ISP、関数型インターフェイスの拡張、バージョニング、Factoryパターンといった設計パターン集になっている
- 前提は第5章（継承）と第6章（final）。章全体で版の結合のような二重構造はないが、後半の設計パターン節は後続章の知識を多く前提にしている

## 節ごとの要約

- 本章の学習目標（L3–19）
    + 抽象クラス、インターフェイス、Java 8以降の機能、設計パターン（Factory・Strategy・Mixin）の4項目を挙げる
    + 前提は第5章と第6章の理解のみと書いている（後半の内容とは釣り合わない）
- 抽象化の必要性（L20–27）
    + 図形ごとに面積の計算方法が異なる例で、共通の概念はあるが実装は子クラスに任せたい場面を示す
    + 関数型プログラミングでは高階関数や型クラスで同様の抽象化をする、という一文の脱線がある
- 抽象クラスと抽象メソッド（L28–155）
    + 抽象メソッドを持つクラスはabstract宣言が必要、newできない、子クラスはすべての抽象メソッドを実装する、という3つのルール
    + `Shape`抽象クラス（7-1）、`Circle`と`Rectangle`による実装（7-2）、親クラス型の配列によるポリモーフィズム（7-3）
- インターフェイス：振る舞いの契約（L156–241）
    + インターフェイスのルール6項目と、主要インターフェイスの実装関係図（chapter07-interface-implementation）
    + `Exportable`と`Archivable`の定義（7-4）と、両方を実装する`Document`（7-5）。継承関係にないクラス間で共通の能力を持たせる用途を説明する
- 抽象クラス vs インターフェイス（L242–256）
    + 目的（is-a/can-do）、継承と実装、持てるメンバー、使い分けの比較表
    + 経験則として、まずインターフェイスで考え、共通のコードや状態が必要なときに抽象クラスを検討する
- Java 8以降のインターフェイス進化（L257–561）
    + defaultメソッドによる後方互換な機能追加を`Collection`風のインターフェイスで示す（7-6）
    + defaultメソッドによるテンプレートメソッドパターンとフックメソッド（7-7）
    + ダイヤモンド問題と`X.super.method()`による解決（7-8）、「クラス優先」「より具体的なインターフェイス優先」「それでも曖昧ならコンパイルエラー」の優先順位規則（7-9）
    + staticメソッドによるユーティリティの提供（JSONシリアライズの例、7-10）
    + defaultメソッドで`Optional`や不変リストを返す防御的なラッパー（7-11）
- 高度な設計パターン（L562–822）
    + Mixin: `Timestamped`・`Identifiable`・`Versioned`を組み合わせる`Document`（7-12）
    + トレイト: `Comparable`を拡張して比較メソッドを追加する`ComparableTrait`（7-13）
    + インターフェイス分離原則: 肥大化した`BadUserService`を役割ごとに分割する（7-14）
    + `Function`を拡張した`EnhancedFunction`で条件付き実行・メモ化・計測を追加する（7-15）
    + `ServiceV1`〜`ServiceV3`の継承とdefaultメソッドによるAPIのバージョニング（7-16）
- Factoryパターン：オブジェクト生成の抽象化（L823–1000）
    + Simple Factory: 文字列から`Circle`・`Rectangle`・`Triangle`を生成する`ShapeFactory`（7-17）
    + Factory Method: 抽象クラス`DocumentFactory`のサブクラスがWord/PDF文書を生成する（7-18）
    + 利点4項目（結合度の低減、拡張性、生成ロジックの隠蔽、一貫性）
    + MySQL/PostgreSQLの接続を切り替える`DatabaseConnectionFactory`（7-19）
- よくあるエラーと対処法（L1001–1020）
    + 2026-11-09に、エラーメッセージの例・修正コード・デバッグのヒントを`appendix/h-common-errors/chapters/chapter07.md`へ移した。本文には出会いやすいエラーと原因の要点のリストとGitHubのURLだけを残す
    + 本文に挙げるエラー: 抽象クラスのインスタンス化、抽象メソッドやインターフェイスのメソッドの実装忘れ、多重継承とダイヤモンド問題、defaultメソッドとstaticメソッドの混同、抽象クラスとインターフェイスの使い分けの誤り、@Overrideの省略

## 他章との関係

- 第5章（継承とポリモーフィズム）: 抽象クラスを使わないテンプレートメソッドパターンを示し、インターフェイスによる解決を「第7章で詳しく説明」と予告している。本章はその抽象クラス版を示していない
- 第8章（列挙型とレコード）: Strategyパターンを扱う。本章の学習目標のStrategyはこちらに任せるか、目標から外すのが自然
- 第9章（コレクション）: `Collection`、`Map`、`List.of`を本章で先に使っている
- 第10章（ジェネリクス）: `Collection<E>`、`ComparableTrait<T>`、`EnhancedFunction<T, R>`などで先取りしている
- 第11章（ラムダ式と関数インターフェイス）: 7-15は第11章の関数型インターフェイスの節と内容が近い。第11章にも関数型のテンプレートメソッドパターンがある
- 第12章（Stream API）: 7-6のコード内コメントで「Chapter 12」と英語表記で参照している
- 第15章（マルチスレッド）: 7-16で`CompletableFuture`を先取りしている
