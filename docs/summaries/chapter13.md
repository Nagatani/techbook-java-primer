# 第13章 例外処理 要約

行番号・サンプルコード番号の正確な対応は `docs/book-index/chapter13-exception-handling.md` を参照する。

## 章の概要

- エラーの3分類（構文・実行時・論理）から入り、try-catch-finally、try-with-resources、検査例外と非検査例外、throws、独自例外、例外の連鎖を教える
- try-with-resourcesを正式に説明する章（2026-11-11に、第14章の説明を本章へ集めた）
- 後半はリトライ、サーキットブレーカー、例外の集約、複数リソースとカスタムAutoCloseable、ログ記録、ビジネス例外とシステム例外の分離、エラーコード管理と、業務システム寄りの応用が続く
- 基礎部分（L42–318）より応用部分（L319–913）の分量が多い
- 前提は「第12章まで」で、後半はジェネリクス（第10章）とラムダ式（第11章）も使うと明記している（L18–19）

## 節ごとの要約

- 本章の学習目標（L3–20）
    + 例外処理の基本、リソース管理、カスタム例外、堅牢なシステム設計の4項目。前提は第12章までと、第10章・第11章の内容を使う旨
- エラーの種類と対処法（L21–41）
    + ソフトウェアの信頼性の重要性。構文エラー・実行時エラー・論理エラーの3分類を文章で示し、実行時エラーに焦点を当てると宣言する
    + 節名は「対処法」だが、対処法は論理エラーの1文だけ
- 例外処理の基本: `try-catch-finally`（L42–168）
    + 例外とスローの定義のあとに、例外発生時の制御の流れ（呼び出しスタックをさかのぼってcatchブロックを探す）
    + try-catchとNullPointerExceptionの捕捉（13-1）。catchは具体的な例外から書き、親クラスを先に書くとコンパイルエラーになる理由、finallyの骨組み（13-2）と図
    + try-with-resources（13-3）。リソースリーク、finallyで閉じる書き方の煩雑さ、AutoCloseable、ファイルの読み書きは第14章で学ぶ旨。実行結果の前提（mainは全文にある、メッセージはOSで異なる）を説明
- 検査例外と非検査例外（L169–235）
    + Throwableを根とする階層の図（2026-11-11時点でASCII図はなく図だけ）
    + 検査例外はコンパイラーが処理を強制する。throwsによる委譲（13-4）と伝播の図
    + 非検査例外はバグが原因なので、catchせずコードを直すのが原則
- 独自例外と例外の連鎖（L236–318）
    + Exceptionを継承したBalanceInsufficientExceptionとthrow（13-5）。実行結果の前提とmainは全文にある旨
    + SQLExceptionをDataAccessExceptionでラップする例外の連鎖（13-6）と図。データベースに接続せず例外が起きたと仮定する旨
    + 呼び出し側は`getCause()`で元の例外を取り出せ、スタックトレースには`Caused by:`で原因が出る旨
- 実践的な例外処理パターン（L319–495）
    + Callableとジェネリクスを使ったリトライ（13-7）。`Callable`と`Class<? extends Exception>`の説明を加えた
    + 状態を持つサーキットブレーカー（13-8、しきい値とtimeoutのフィールドも載せる）と状態の図。名前の由来とNygard『Release It!』の脚注
    + 複数の処理を順に実行して例外を集めるExceptionAggregator（13-9）
- リソース管理の実践例（L496–602）
    + 複数リソースのtry-with-resources（13-10）
    + AutoCloseableを実装したResourcePool（13-11）と実行結果。1スレッド前提で、排他制御は第15章で学ぶ旨
- 例外処理とログ記録（L603–715）
    + java.util.loggingで例外の種類ごとにログレベルを使い分け、エラーIDを発行する（13-12）。ログと再スローを両方行うと二重に記録される注意
    + LogRecordとJSON形式の1行の文字列による構造化ログ（13-13、`createStructuredMessage`も載せ、JSONは第7章で紹介した旨）
- 業務アプリケーションでの例外設計（L716–899）
    + 検査例外のBusinessException（抽象）と非検査例外のSystemException（抽象）の基底クラス、InsufficientBalanceException（13-14、金額はBigDecimal）
    + enumによるエラーコードとメッセージの一元管理、`BusinessException(ErrorCode)`のコンストラクターとそれを使うInsufficientBalanceException、ErrorResponse（13-15）。13-14の文字列のコードをenumに置き換えられる旨
    + 送金サービスでのビジネス例外の伝播と予期せぬ例外のラップ（13-16、Springに依存しない形。Loggerで記録する）
- 例外処理のベストプラクティス（L900–913）
    + 空のcatchを避ける、具体的な例外だけをcatch、try-with-resources、ユーザー向けメッセージとログの分離を文章で示す
    + 性能面の詳細は付録B.12「例外処理のパフォーマンス」で扱う旨（2026-11-14に例外の連鎖の節から移した）
- よくあるエラーと対処法（L914–935）
    + try-catch文の範囲が広すぎる、握りつぶし、例外の型の選び方の誤り、リソースの解放漏れ、カスタム例外の設計の誤り、再スロー時の情報の欠落、スレッドのなかで発生した例外の要点と、`appendix/h-common-errors/chapters/chapter13.md`のURL
- まとめ（L936–954）
    + 例外処理の基本、例外の種類、独自例外と例外の連鎖、実践的な例外処理の4項目と、第14章への導入
- 章末演習（L955–966）
    + 演習リンクは`exercises/chapter13/`。第12章と同じ形（課題構成3項目と、basic・advanced・challengeの脚注）
