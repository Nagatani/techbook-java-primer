# 第13章 例外処理 要約

行番号・サンプルコード番号の正確な対応は `docs/book-index/chapter13-exception-handling.md` を参照する。

## 章の概要

- エラーの3分類（構文・実行時・論理）から入り、try-catch-finally、try-with-resources、検査例外と非検査例外、throws、独自例外、例外の連鎖を教える
- 後半はリトライ、サーキットブレーカー、例外の集約、カスタムAutoCloseable、ログ記録、ビジネス例外とシステム例外の分離、エラーコード管理と、業務システム寄りの応用が続く
- 最後に「よくあるエラー」7種（13-17〜13-30）とデバッグのヒント
- 基礎部分（L79–343）は短く、応用部分（L344–1107）が分量の大半を占める。基礎と応用の比重が逆転している
- 前提は「第5章まで」と書くが、本文はジェネリクス（第10章）、ラムダ式（第11章）、ExecutorService/CompletableFuture（第15章）、JDBC（付録E）、Springを使う

    + 13-10のJDBCの例は、2026-11-08に本文の抜粋から外した（全文はsample-codeにある）
    + 13-16はSpringのアノテーションをコメントアウトした形で載せており、AccountRepositoryなど未定義のクラスに依存して単体では動かない
- 学習目標と本文の不一致
    + 学習目標の「メモリリークの防止」「フェイルセーフ設計」は本文で独立した説明がない
- 章内の重複

## 節ごとの要約

- 本章の学習目標（L3–19）
    + 例外処理の基本、リソース管理、カスタム例外、堅牢なシステム設計の4項目。前提は「第5章まで」
- エラーの種類と対処法（L20–39）
    + ソフトウェアの信頼性の重要性。構文エラー・実行時エラー・論理エラーの3分類を示し、実行時エラーに焦点を当てると宣言する
    + 節名は「対処法」だが対処法は書かれていない
- 例外処理の基本: `try-catch-finally`（L40–141）
    + 例外発生時の制御の流れ（呼び出しスタックをさかのぼる）
    + try-catchとNullPointerExceptionの捕捉（13-1）、finallyの骨組み（13-2）、try-with-resourcesでBufferedReaderを自動クローズ（13-3）
    + 13-3の実行結果はコードにないmainメソッドを前提にしている（L196で注記）
- 検査例外と非検査例外（L142–216）
    + Throwable→Error/Exception→RuntimeExceptionの階層図（ASCII図と図13-1の両方がある）
    + 検査例外はコンパイラが処理を強制する。throwsによる委譲（13-4）
    + 非検査例外はバグが原因なのでcatchせずコードを直すべき、という方針
- 独自例外と例外の連鎖（L217–288）
    + Exceptionを継承したBalanceInsufficientExceptionとthrow（13-5）。実行結果はコードにないmainを前提にしている
    + SQLExceptionをDataAccessExceptionでラップする例外の連鎖（13-6）
    + 付録B.12「例外処理のパフォーマンス」へのリンク（L341）
- 実践的な例外処理パターン（L289–451）
    + Callableとジェネリクスを使ったリトライ（13-7）、状態を持つサーキットブレーカー（13-8）、複数タスクの例外をまとめるAggregateException（13-9）
- リソース管理の実践例（L452–540）
    + 複数リソースのtry-with-resources（逆順クローズ）（13-10）
    + AutoCloseableを実装したResourcePool（13-11）
- 例外処理とログ記録（L541–624）
    + java.util.loggingで例外の種類ごとにログレベルを使い分け、エラーIDを発行する（13-12）
    + LogRecordとJSON風文字列による構造化ログ（13-13）。13-13の本文はimport文を省いている（全文には補った）
- 業務アプリケーションでの例外設計（L625–782）
    + 検査例外のBusinessException（エラーコード・タイムスタンプ付き）と非検査例外のSystemExceptionの基底クラス（13-14）
    + enumによるエラーコードとメッセージの一元管理、ErrorResponse（13-15）
    + 送金サービスでのビジネス例外の伝播と予期せぬ例外のラップ（13-16、Spring前提）
- 例外処理のベストプラクティス（L783–791）
    + 空のcatch禁止、具体的な例外をcatch、try-with-resources、ユーザー向けメッセージとログの分離の4項目
- よくあるエラーと対処法（L792–813）
    + 2026-11-09に、エラーメッセージの例・修正コード・デバッグのヒントを`appendix/h-common-errors/chapters/chapter13.md`へ移した。本文には出会いやすいエラーと原因の要点のリストとGitHubのURLだけを残す
    + 本文に挙げるエラー: try-catch文の範囲が広すぎる、例外の握りつぶし、例外の型の選び方の誤り、リソースの解放漏れ、カスタム例外の設計の誤り、再スロー時の情報の欠落、スレッドのなかで発生した例外
- まとめ（L814–832）
    + 例外処理の基本、例外の種類、独自例外と例外の連鎖、実践的な例外処理の4項目と、第14章への導入（2026-11-08に新設）
- 章末演習（L833–868）

    + 「詳細な課題内容と実装のヒントは…README.mdを参照」がL31とL40で二重に出る

## 他章との関係

- 第9章: 「よくあるエラーと対処法」でNullPointerException、ConcurrentModificationException、IndexOutOfBoundsExceptionなどを個別に扱っており、本章の例外体系の説明より先に出る
- 第10章・第11章: 13-7、13-29/13-30などで構文を前提にしているが、学習目標の前提（第5章まで）に書かれていない
- 第14章: 「try-with-resourcesによる安全なリソース管理」節（L71付近）があり、本章13-3・13-10・13-24と重複する。第14章の前提は「第13章の例外処理とtry-with-resources」と書いており、役割分担の整理が必要
- 第15章: CompletableFutureの`exceptionally`/`handle`を扱う。本章13-30はその先取り
- 第16章: タイムアウトとリトライを扱っており、本章13-7のリトライパターンと重なる
- 第21章: 例外のテスト（assertThrows）との接続は本文にない
- 付録B.12: 例外処理のパフォーマンス（ディレクトリ`b12-exception-performance`）。原稿の付録B索引ではB.12は「Enumの高度な活用」でずれている（Issue #011）
- 付録E: 13-10のJDBCとトランザクションの本来の説明場所
- 付録H: 実行時例外とデバッグ手法を体系的にまとめる付録で、本章「よくあるエラー」「デバッグのヒント」と役割が重なる
