# 第4章 クラスとインスタンス 要約

行番号・サンプルコード番号の正確な対応は `docs/book-index/chapter04-classes-and-instances.md` を参照する。

## 章の概要

- 第3章で学んだクラスの基本を前提に、カプセル化・アクセス制御・パッケージ・コンストラクタ設計を「実践的なクラス設計」として掘り下げる
- 銀行口座クラスをV0（全フィールドpublic）→V1（private化）→V2（検証追加）→V3（final・取引履歴・防御的コピー）と段階的に改善するのが章の背骨
- 後半はビルダー、コンストラクタチェーン、オーバーロードによるAPI設計、神クラス・過度なgetter/setter・防御的コピーの欠如という設計上の問題、エラー集を扱う
- 章のタイトルは「クラスとインスタンス」だが、インスタンス生成そのものより設計技法が中心で、内容は「中級のクラス設計」に近い

## 構成上の問題

- 防御的コピーの説明が3か所に分散している
    + V3の`getTransactionHistory`（4-10）
    + 設計上の問題3「防御的プログラミングの欠如」（4-30、4-31）
    + エラー集4「オブジェクト参照と防御的コピー」（4-38、4-39）
    + さらに第6章「防御的コピーとビルダーパターン」とも重なる
- 「設計原則とソフトウェアアーキテクチャ」（L386–391）は本文2段落だけの孤立した節で、SOLID原則の名前を出すだけで以降つながらない。「クラス設計のベストプラクティス」（L767–777）と統合するのが自然
- 章順との矛盾
    + サンプルコード4-11が`extends`・`super`・`@Override`を使う（継承は第5章）。要点で「テンプレートメソッドパターン」と呼ぶが、実際はsuper呼び出し付きのオーバーライドにすぎない

## 他章との関係

- 第3章: クラス作成、コンストラクタ・this・オーバーロードの基本、「publicとprivate」の節がある。本章の4-2〜4-5やコンストラクタ節は第3章と重なりやすく、どこまでが復習かの線引きが必要
- 第5章: 継承を正式に扱う。4-11はその前に継承を使ってしまっている
- 第6章: 不変性、final、防御的コピー、ビルダーパターンを体系的に扱う。本章の防御的コピー3か所と4-21は第6章へ寄せるか、予告にとどめる候補
- 第9章: 本章で先行使用するList・Mapを正式に扱う
- 第13章: 例外処理。本章のIllegalArgumentExceptionの送出やNullPointerExceptionの扱いを体系化する
- 付録H: Java共通エラーガイド。L1887では正しく付録Hを指すが、L1863・L1865は「付録A.1.3」「付録A.3」を指している（付録Aは開発環境の構築なので誤り）

## 校正で見つけた個別の問題

- L759: 「第3章のBankAccountV3を基に」は誤り。BankAccountV3は本章のサンプルコード4-10
- 4-11: コンストラクタ引数`accountHolder`を受け取るが使っていない
- 4-32: 「エラー例2」の`public void User() { }`はコンパイルエラーにならない（クラス名と同名の普通のメソッドとして合法）。説明を「コンストラクタのつもりがメソッドになる」に直す必要がある
- 4-33: `this.name`に代入するが`name`フィールドの宣言がない
- 4-25: 「型安全性を高めるオーバーロード」の例で`log(String level, String message)`と`log(String format, Object... args)`が共存し、`log("Hello %s", "World")`がレベル付きのほうに解決される。エラー集3が警告する曖昧なオーバーロードそのものになっている
- L555: V2の残る問題「口座番号が後から変更可能（getterがない）」は理由づけが矛盾している（setterもなく、問題はfinalでないこと）
- L287: 「柔軍性」は「柔軟性」の誤字
- 4-9、4-10の例外メッセージ「0以上である必要です」「正の値である必要です」は不自然（「必要があります」の脱落）
- L944がL777と同じ文（「これらの原則に従うことで…」）の繰り返し
- L195: protectedの使用例だけ`#####`見出しでなく「`protected`の使用例。」という本文行になっている
- L856–876: 「1. 単一型インポート。」などの番号付き項目の直後にサンプルコード番号のspanが続き、リストとして崩れている
- L678: 「防御的コピー: 内部リストの参照を…」が「項目名: 説明」形式のまま（階層化リストのルール違反）
- L757: 「この設計の要点。」は自動変換による不自然な導入文。L1274「実践的なオーバーロード設計原則。」も同様
- L1697「（統合版）」、L1734「完全ガイド」は編集作業の名残と思われる見出し
- L1863–1867: 太字の使用と2スペースの入れ子インデントが他のリストと不統一。L1286以降のまとめのリストも3スペースインデント
- L1713、L1729など「解決策:」「重要なポイント:」が半角コロンの擬似見出し
