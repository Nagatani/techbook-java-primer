# 第11章 ラムダ式と関数インターフェイス 要約

行番号・サンプルコード番号の正確な対応は `docs/book-index/chapter11-lambda-and-functional-interfaces.md` を参照する。

## 章の概要

- 匿名クラスの冗長さを動機にラムダ式を導入し、関数型インターフェイス、ラムダ式の構文の省略形、`java.util.function`の標準インターフェイス、メソッド参照の4種類を教える
- 応用としてComparatorによる並び替え、ExecutorService、Threadでのラムダ式の利用を示す
- 一方で、導入節の中に高階関数・リアクティブストリーム・CQRS・金融取引などの高度な実務例が大量に挿入されている
- 前提は第7章のインターフェイス、第9章のコレクション、第10章のジェネリクス

## 構成上の重大な問題

この章は、基本の版に高度な事例と後付けの節が継ぎ足された状態で残っている。

- 導入節「匿名クラスからラムダ式へ」（L20–705）の肥大化
    + 匿名ActionListener（11-2、L61–76）と、そのラムダ式版（11-19、L697–704）の間に約620行の高度な事例（11-3〜11-18）が挟まっていて、本来隣接していた対比が分断されている
    + 挟まった事例は、ラムダ式の構文や関数型インターフェイスの定義（L706以降）より前に、Function・Predicate・Supplier・Consumer、Stream、Optional、sealed interface、record、パターンマッチングのswitch、Reactor（Mono/Flux）、Vavr（Try）、ConcurrentHashMapを使う。多くは未定義クラスに依存する断片で、実行できない
    + 小見出しの代わりに「アンチパターン1: 過度なラムダネスト。」「設定ビルダーパターンの関数型実装。」などの地の文を使い、番号付きリスト（L243「1.」、L325「2.」、L419「3.」）と####見出しが交互に現れて階層が崩れている
- 章の終わりが二重になっている
    + 2026-11-08に解消した。見出しだけの「さらに深い理解のために」を削除し、ほぼ同文だった2つのまとめを1つにし、章末演習の中にあったバリデーションの事例（11-28）を「ラムダ式の応用例」へ移し、末尾を「よくあるエラー → まとめ → 章末演習」の順にした
- 学習目標と本文の不一致
    + 「関数の合成」を掲げるが、標準の`Function.andThen`/`compose`や`Predicate.and`/`or`/`negate`は説明していない（独自Middlewareの`then`（11-10）があるだけ）
    + 「副作用の最小化」はアンチパターン例（11-5）だけで、実質的finalと変数キャプチャはエラー集（11-35、11-36）と11-14のコメントにしか出ない。本文での説明がない
- 第12章との重複と先取り
    + Comparatorのラムダ式化、`Comparator.comparing`、`thenComparing`、`reversed`（11-20、11-22）は、第12章「ラムダ式によるカスタムソート」（12-1〜12-3、匿名クラスのComparatorからの書き換えを含む）とほぼ同じ内容
    + Streamの`map`/`filter`/`collect`/`reduce`（11-4、11-5、11-12、11-24、11-26、11-33〜11-40）とOptional（11-8、11-13、11-18、11-34）を説明なしで使う。どちらも第12章で初めて解説される
- 他の後続章の先取り（2026-11-08に、初出の箇所へ後の章で学ぶ旨と最小限の読み方の案内を加えた）
    + ExecutorService・Callable・invokeAll（11-25）とThread・join（11-27）は第15章、ActionListener（11-2、11-19）は第17・18章の内容

## 節ごとの要約

- 本章の学習目標（L3–19）
    + ラムダ式の基本、標準関数型インターフェイス、メソッド参照の4種類、関数型スタイル（宣言的・関数合成・副作用の最小化）の4項目
- 匿名クラスからラムダ式へ（L20–664）
    + RunnableとActionListenerで匿名クラスとラムダ式を対比（11-1、11-2、11-19）
    + 高階関数によるリスク管理の抽象化（11-3、取引システムの例）
    + アンチパターンとして過度なネストと副作用（11-4、11-5）
    + Netflixを例にした同期処理とリアクティブ処理の比較と、出典のない性能値（11-6、11-7）

- 関数型インターフェイス（L665–905）

    + ラムダ式とメソッド参照の比較、`Person::new`と`ArrayList::new`（11-26）。11-24とコンストラクタ参照の例が重複
