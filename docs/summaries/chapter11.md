# 第11章 ラムダ式と関数インターフェイス 要約

行番号・サンプルコード番号の正確な対応は `docs/book-index/chapter11-lambda-and-functional-interfaces.md` を参照する。

## 章の概要

- 匿名クラスの冗長さを動機にラムダ式を導入し、関数型インターフェイス、ラムダ式の構文の省略形、`java.util.function`の標準インターフェイス、メソッド参照の4種類を教える
- 応用としてComparatorによる並び替え、ExecutorService、Threadでのラムダ式の利用を示す
- 一方で、導入節の中に高階関数・リアクティブストリーム・CQRS・金融取引などの高度な実務例が大量に挿入されている
- 前提は第7章のインターフェイス、第9章のコレクション、第10章のジェネリクス

## 構成上の重大な問題

この章は、基本の版に高度な事例と後付けの節が継ぎ足された状態で残っている。

- 導入節「匿名クラスからラムダ式へ」（L20–705）の肥大化
    + 匿名ActionListener（11-2、L61–76）と、そのラムダ式版（11-19、L697–704）の間に約620行の高度な事例（11-3〜11-18）が挟まっていて、本来隣接していた対比が分断されている
    + 挟まった事例は、ラムダ式の構文や関数型インターフェイスの定義（L706以降）より前に、Function・Predicate・Supplier・Consumer、Stream、Optional、sealed interface、record、パターンマッチングのswitch、Reactor（Mono/Flux）、Vavr（Try）、ConcurrentHashMapを使う。多くは未定義クラスに依存する断片で、実行できない
    + 小見出しの代わりに「アンチパターン1: 過度なラムダネスト。」「設定ビルダーパターンの関数型実装。」などの地の文を使い、番号付きリスト（L243「1.」、L325「2.」、L419「3.」）と####見出しが交互に現れて階層が崩れている
- 章の終わりが二重になっている
    + 「さらに深い理解のために」（L1217–1218）は見出しだけで本文がない
    + 1つ目の「まとめ」（L1219–1231）と「章末演習」（L1232–1327）のあとに、バリデーションの事例（11-28）と付録参照、「よくあるエラーと対処法」（L1328–1607）、「まとめ (2)」（L1608–1619）が続く
    + 2つの「まとめ」は1文目以外が同一の文章
    + 統合するなら、エラー集を「章末演習」の前に移し、まとめを1つにし、11-28は応用例か章末演習の外に移すのが自然
- 学習目標と本文の不一致
    + 「関数の合成」を掲げるが、標準の`Function.andThen`/`compose`や`Predicate.and`/`or`/`negate`は説明していない（独自Middlewareの`andThen`（11-10）があるだけ）
    + 「副作用の最小化」はアンチパターン例（11-5）だけで、実質的finalと変数キャプチャはエラー集（11-35、11-36）と11-14のコメントにしか出ない。本文での説明がない
- 第12章との重複と先取り
    + Comparatorのラムダ式化、`Comparator.comparing`、`thenComparing`、`reversed`（11-20、11-22）は、第12章「ラムダ式によるカスタムソート」（12-1〜12-3、匿名クラスのComparatorからの書き換えを含む）とほぼ同じ内容
    + Streamの`map`/`filter`/`collect`/`reduce`（11-4、11-5、11-12、11-24、11-26、11-33〜11-40）とOptional（11-8、11-13、11-18、11-34）を説明なしで使う。どちらも第12章で初めて解説される
- 他の後続章の先取り
    + ExecutorService・Callable・invokeAll（11-25）とThread・join（11-27）は第15章、ActionListener（11-2、11-19）は第17・18章の内容

## 校正で見つけた個別の問題

- 11-28（L1288、L1291、L1294）: `errors.add("...");。`とコード内に句点が混入していて、コンパイルできない。L1288は「名前はポイントです」と誤変換されていて、実行結果（L1322）の「名前は必須です」とも一致しない
- 11-13、11-28、11-31〜11-40: コードコメントの末尾に句点が付けられている（「// 関数型ファクトリパターン。」など）。自動変換がコードブロック内に及んだと推測される
- 11-39、11-40: エラー例と対処法の1つ目が同じコード（`map(Integer::parseInt)`）で、エラー例は実際にはコンパイルできる（事実誤認）
- 11-32、11-34、11-36: 同じブロック内で変数`comp`、`contents`やメソッド`processNumbers`を二重に宣言している。11-36の2つ目は`initialThreshold`が未使用で、対処法として意味をなさない
- L461: 11-12の脚注で「Java 17以降」としているが、switchでのrecordパターン（`case AccountCreated(var id, var owner)`）はJava 21以降の機能
- L187–239: Netflixの事例と「レイテンシ300ms→50ms」などの数値に出典がない。L187、L189、L233、L635は体言止めや「活用。」で終わる不完全な文
- 11-1、11-3、11-20〜11-27、11-30: クラス名が`SampleCode12_2`などの旧章番号のまま
- 11-22（L859–877）: 実行結果を載せているが、コードに出力文がない。11-20と11-22でStudentのコンストラクタが異なり、どちらも定義が示されていない
- 11-3: MarketData、TradingDecisionなどが未定義でimportもないのに、実行結果を載せている
- L722: 「付けることがあるとよいでしょう」は不自然（「付けるとよいでしょう」の誤りと推測される）
- L943: 文末に句点がない
- L1010、L1076、L1256: 「実践的なラムダ式の活用パターン」などの見出し相当の文がMarkdown見出しになっていない
- L53ほか: 「**実行結果:**」と太字を見出しとして使っている（第10章は「実行結果：」で表記も不統一）
- L1606: 「6. コードレビュー: 可読性と…」が項目名と説明を1行に並べた形式で、ほかの項目の階層化リストと揃っていない
- 11-35（L1490）のエラーメッセージはjavacの出力（local variables referenced from a lambda expression must be final or effectively final）と異なる
- 11-29〜11-40: コードコメントに絵文字（✅、❌）を使っている
