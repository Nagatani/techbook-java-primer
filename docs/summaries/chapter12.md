# 第12章 Stream APIと高度なコレクション操作 要約

行番号・サンプルコード番号の正確な対応は `docs/book-index/chapter12-advanced-collections.md` を参照する。

## 章の概要

- 第9章のコレクションと第11章のラムダ式を土台に、宣言的なデータ処理を教える
- 主な内容は、実装クラスの選択、Comparatorによるソート、Stream API（filter・map・flatMap・reduce・Collectors）、Optional、並列ストリーム
- 共通の題材は`Student`（name・score・height）で、サンプルコード12-3で定義し以降のサンプルで使い回す
- 前提は第9章・第10章・第11章（L18）。ただし並列ストリーム（スレッドセーフティ、Fork/Join）は第15章、チェック例外のラップ（12-37、12-38）は第13章、`Files.readString`は第14章の内容を先取りしている（2026-11-08に、初出の箇所へ後の章で学ぶ旨と最小限の読み方の案内を加えた）

## 構成上の問題

第9章のように2つの版が丸ごと結合されたものではないが、後から節を継ぎ足した痕跡が残っている。

- まとめが2つあり、章末演習とエラー集が1つ目のまとめの後ろにあった（2026-11-08に解消。「データ構造の選択」を含む1つ目のまとめを残し、末尾を「よくあるエラー → まとめ → 章末演習」の順にした）
- Optionalを二重に説明している
    + 独立節「Optional型による安全なnull処理」（L311–798、12-8〜12-14）で作成・取得・変換・Stream連携・アンチパターンまで扱う
    + 「高度なStream操作」内の「Optionalによる安全なデータ処理」「Optionalの連鎖操作」「null安全な処理パターン」（L1094–1219、12-21〜12-23）で、findFirst・map・orElseなどを導入から説明し直している。L1096は「Java 8で導入された重要な仕組みです」と初出のように書いている
    + isPresent()とget()の組み合わせを避けよ、という注意も12-14と12-33/12-34で重複
- 学習目標と本文の不一致
    + 学習目標の「カスタムCollectorの作成」（L12）は本文で扱っていない
    + 逆に、本文の大きな部分を占めるOptional、Comparator、データ構造の選択は学習目標に挙がっていない
- 他章との重複（詳細は「他章との関係」）
    + 「データ構造の選択」は第9章の各インターフェイス節・「コレクションの選択指針」とほぼ同じ内容
    + 「ラムダ式によるカスタムソート」は第11章の関数型インターフェイス節（匿名クラスのComparatorからラムダ式へ、thenComparing、メソッド参照）と重複
- 統合するなら、Optionalは独立節に一本化して「高度なStream操作」からL1094–1219を削るか、Stream連携部分（12-12）に吸収するのが自然。データ構造の選択とComparatorは第9章・第11章への参照に置き換え、本章はStreamに集中できる

## 節ごとの要約

- 本章の学習目標（L3–19）
    + Stream APIの基本、高度なコレクション操作、Collectors、並列ストリームの4項目
    + 前提知識で第11章を「ラムダ式と関数型インターフェイス」と呼ぶが、第11章の題名は「関数インターフェイス」（表記の揺れ）
- データ構造の選択（L20–67）
    + ArrayList/LinkedList、HashSet/LinkedHashSet/TreeSetの比較表と使い分けの指針。サンプルコードなし
    + 表でLinkedListの中間への追加・削除をO(1)としているが、位置までの走査にO(n)かかる点に触れていない
- ラムダ式によるカスタムソート（L68–163）
    + 匿名クラスのComparator（12-1）をラムダ式に書き換え（12-2）、comparing・reversed・thenComparingを紹介（12-3）
    + 12-3の比較器は、2回目の`reversed()`が全体を反転して点数昇順になっていたため、2026-11-08に`thenComparing(Comparator.comparingInt(...).reversed())`へ直し、reversedが全体にかかる注意を加えた
    + 12-2の後の実行結果（データがコード中になかった）は、2026-11-08に12-3への橋渡しの説明に置き換えた
- Stream APIによる現代的なコレクション操作（L164–336）
    + Stream APIが必要な理由、遅延評価（12-4）、生成・中間操作・終端操作の3フェーズと主なメソッド一覧、filter（12-5）、map（12-6）、組み合わせた例（12-7）
    + 「なぜ必要か」の4つ目に「null安全性の欠如」を挙げるが、これはStreamではなくOptionalが解決する問題
- Optional型による安全なnull処理（L337–717）
    + null参照の問題とTony Hoareの「10億ドルの過ち」、Optionalの作成（12-8）、値の取得（12-9）、存在確認（12-10）、map・flatMap・filter（12-11）、Stream連携とOptional::stream（12-12）、リポジトリ・設定値の実例（12-13）、アンチパターン（12-14）、ベストプラクティス5項目
    + 12-11はUserのフィールドを`Optional<String>`にしており、12-14で「フィールドにOptionalを使うのはアンチパターン」とする説明と矛盾する
    + L319「コンパイル時にnull安全性を強制できます」は過大な表現
- 並列ストリームによるパフォーマンス向上（L718–848）
    + parallelStreamの使い方（12-15）、Fork/Joinによる分割・処理・統合と計測例（12-16）、オーバーヘッド・スレッドセーフティ（12-17）・順序の注意、使うとよい4条件
    + スレッドやデータ競合の概念は第15章より前に出てくるため、説明が最小限にとどまっている
- 高度なStream操作（L849–1263）
    + flatMap（12-18）、reduce（12-19）、CollectorsのtoList・groupingBy・partitioningBy（12-20）、Optional再説明（12-21〜12-23）、早期終了操作allMatch・anyMatch・limit（12-24）、toArray（12-25）、groupingBy＋collectingAndThen・averagingIntの複合パイプライン（12-26）
    + 12-26の実行結果は2026-11-08に実際の出力に合わせ、HashMapで表示順が保証されない注意を加えた
- よくあるエラーと対処法（L1264–1283）
    + 2026-11-09に、エラーメッセージの例・修正コード・デバッグのヒントを`appendix/h-common-errors/chapters/chapter12.md`へ移した。本文には出会いやすいエラーと原因の要点のリストとGitHubのURLだけを残す
    + 本文に挙げるエラー: 中間操作の順序の誤り、終端操作の書き忘れ、並列ストリームでの共有データの変更、Optionalの誤用、同じ処理の繰り返しによる性能の低下、ラムダ式のなかでのチェック例外
- まとめ（L1284–1302）
    + データ構造の選択からStream操作まで6項目
- 章末演習（L1303–1314）
    + 演習リンクは`exercises/chapter12/`（2026-11-09に演習ディレクトリを現行の章番号に組み替え、リンクを直した。Issue #010）

## 他章との関係

- 第9章（コレクション）
    + 「データ構造の選択」は第9章のList・Set節と「コレクションの選択指針」（計算量表）の繰り返し
    + 第9章の「今後の学習へ向けて」でStream APIを予告しているが、本章側から第9章のその記述への言及はない
- 第11章（ラムダ式）
    + 匿名クラスのComparatorからラムダ式への書き換え、thenComparing・reversed、メソッド参照は第11章で既出。L162でメソッド参照を初出のように説明している
    + 第11章でもStream（map・collect）を先行使用しており、`Optional.of`→`filter(Optional::isPresent)`→`map(Optional::get)`のパターン（第11章L255–266）や、Stream内の`Files.readString`の例外処理（第11章「例外処理での問題」）が12-37/12-38と重複する
- 第13章（例外処理）・第14章（ファイルI/O）: 12-37/12-38でチェック例外とUncheckedIOException、Files.readStringを先取り
- 第15章（マルチスレッド）: 並列ストリームのスレッドセーフティ、synchronizedListを先取り
- 付録B.09（原稿の付録B索引での番号。ディレクトリは`b08-stream-api-internals`）: Stream APIの内部実装。本章からは参照していない

## 校正で見つけた個別の問題

- L170、L231、L328: 文章を見出し（####、#####）にしている。L230、L240は「中間操作（Intermediate Operations）: 」のように項目名と説明をコロンでつないでいる
- L1378–1379、L1702–1703: 「ラムダ式と`Comparator`: …」の「項目名: 説明」形式が残っている（階層化リストのルール違反）
- L214: コード断片の後に句点だけがある文
- L413、L709: 「…する方法。」「…ベストプラクティス。」の体言止めの断片文
- L495: コメント「getUserは…」がコードに存在しないメソッドを指している
- 12-17、12-32、12-38: 同じ変数（results、contents）を1つのコード中で2回宣言しており、そのままではコンパイルできない
- 12-31: 「非同期安全でない」は不自然。ArrayListへの並列追加でConcurrentModificationExceptionが出るという説明も不正確（実際はデータの欠落や配列外アクセス例外が多い）
- 12-35: 変数名`count`に合計（reduce(0, Integer::sum)）を代入している
- 12-37: エラーメッセージがEclipse形式で、javacの「unreported exception IOException」と異なる
- L1415ほか: コードブロック内のコメントに絵文字（❌、✅）がある
- L1096、L1177: 「nullポインタ例外」と「NullPointerException」の表記揺れ
