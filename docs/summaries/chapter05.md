# 第5章 継承とポリモーフィズム 要約

行番号・サンプルコード番号の正確な対応は `docs/book-index/chapter05-inheritance-and-polymorphism.md` を参照する。

## 章の概要

- extendsによる継承、is-a関係、オーバーライドと`@Override`、`super`と`super()`、ポリモーフィズム、instanceofとダウンキャストを教える
- 題材は決済システム、ドキュメントクラスのリファクタリング、RPGキャラクター、ユーザー管理、図形描画と多い
- 継承の誤用（ArrayList継承のスタック、権限階層、正方形と長方形）を通じてリスコフ置換原則とコンポジションを紹介する
- 抽象クラスを使わず、具象クラスの継承とオーバーライドでテンプレートメソッドパターンを実現している（抽象クラスは第7章）
- 前提は第4章のクラス設計。第4章ですでに`extends`を使ったサンプル（Vehicle/Car、EnhancedBankAccount）がある

## 構成上の問題

- 導入順が逆転している
    + 「実践的な継承設計パターン」（L61–1246）が、`extends`の基本構文（L691）より前に、テンプレートメソッドパターンの決済システム（5-1〜5-3）や段階的リファクタリング（5-4〜5-8）を置いている
    + 冒頭（L63）で「第3章で継承を学び、第4章で継承を活用した」とし、本章を発展編として位置づけているが、学習目標では`extends`の基本から学ぶ構成になっており、章の性格づけが食い違う
    + 基本構文・is-a関係・オーバーライドのルールを先に、決済システムやリファクタリングを後に置くのが自然
- 同じ誤用例が章内で二重に説明されている（過去の版の結合と見られる）
    + 「継承の誤用例：よくある間違い」の誤用例1（MyStackがArrayListを継承、5-12）と解決策（5-13）
    + 「そのほかの継承の誤用パターン」の誤用例1（同じMyStack、5-18）と改善策（5-19）
    + 小見出しの番号も「誤用例1〜3」と「誤用例1〜2」が並立している
- 章末の構成
    + 「章末演習」のあとに「例外処理の基礎（補足）」と「よくあるエラーと対処法」が続き、まとめもなかった（2026-11-08に解消。末尾を「よくあるエラー → まとめ → 章末演習」の順に並べ替えた。まとめは新設した）
- 前提知識と章順の矛盾
    + 5-1で`final`メソッドを使い、L212で「不変性の保証」として説明する（finalは第6章）
    + 5-12〜5-14、5-18〜5-19でジェネリクス（`MyStack<E>`、`List<Employee>`）と例外の`throw`を使う（第9章・第10章・第13章）
    + 5-33で`throws IOException`を扱う（第13章・第14章）。節の冒頭で第13章参照を断っている
    + 章末演習のヒントに「抽象メソッドの活用」（L1984）があるが、抽象メソッドは第7章
- 学習目標・予告と本文の不一致
    + L77の「戦略パターンとの組み合わせ（継承と委譲の使い分け）」は本文で扱っていない（コンポジションの解決策のみ）
    + L57–59の開放閉鎖原則・依存性逆転の原則は名前だけで、説明がない

## 節ごとの要約

- 本章の学習目標（L3–27）
    + 継承の基本、オーバーライド、ポリモーフィズム（テンプレートメソッドパターンを含む）、型変換と型判定の4項目
    + 前提は第4章のカプセル化とクラス設計
- なぜ継承とポリモーフィズムが必要なのか（L28–60）
    + 給与計算の雇用形態を例にコード重複の問題（保守性・バグ・拡張性）を示す
    + 継承によるDRY原則と変更の局所化、ポリモーフィズムによる開放閉鎖原則・依存性逆転の原則を名前だけ紹介する
- 実践的な継承設計パターン（L61–1140）
    + 決済システム: 具象クラスPaymentProcessorのfinalなprocessPaymentでテンプレートメソッドパターンを実装し、CreditCardPayment/PayPalPaymentが検証やAPI呼び出しをオーバーライドする。例外を使わずboolean戻り値とerrorMessageで失敗を扱う（5-1〜5-3、chapter05-inheritance-hierarchy）
    + 段階的リファクタリング: WordDocumentとPDFDocumentの重複（5-4、5-6）から親クラスDocumentを抽出し（5-7）、子クラスを再実装する（5-8）。継承階層は3層以上を避けるべきとの注意
    + 継承の書き方: Employeeを継承するManager/Developerで、フィールド・メソッドの継承と固有メンバの追加を示す（5-10）
    + is-a関係とhas-a関係（コンポジション）の区別
    + 継承の誤用例: ArrayList継承のスタックとコンポジションによる解決（5-12、5-13）、全従業員にシステム管理権限を持たせる権限階層のLSP違反（5-14）、正方形と長方形（5-15、使用例5-16、5-17）
    + そのほかの誤用パターン: 実装の都合だけの継承（5-18、5-19。5-12、5-13と重複）、多重継承の代替としての無理な継承（5-20）。解決は第7章のインターフェイスへ送る
    + 継承の実践例: RPGのHero/Wizardで親のフィールド・メソッドを使う（5-21）
- メソッドのオーバーライド（L1141–1256）
    + シグネチャの一致、共変戻り値型、アクセス修飾子は緩める方向のみ、というルール
    + `@Override`アノテーションの役割
    + Character/Wizardのattackのオーバーライドと、`super.attack()`で親の処理を利用するKnight（5-22。2026-11-08に、実行結果のブロックに紛れていたKnightをコードへ移した）
    + コンストラクタ先頭での`super()`の暗黙挿入と、引数なしコンストラクタがない場合の明示呼び出し
- ポリモーフィズム（多態性）（L1257–1686）
    + 親クラス型の変数への子クラスインスタンスの代入（アップキャスト、5-23）と、同じ呼び出しで異なる振る舞い（5-24）
    + User配列をループで処理し、PremiumUser追加時にも呼び出し側を変えなくてよいことを示す（5-25）
    + ユーザー通知のBefore/After比較（5-26、5-27。2026-11-08に、実行結果に合うよう全文のmainに処理を足し、番号なしのUserクラスは5-27の抜粋に含めた）と利点のまとめ、動的バインディングの図（chapter05-polymorphism）
    + 図形描画システムのBefore/After比較（5-28、5-29）と、OCP・SRP・DIP・テスト容易性・並列開発の利点
- `instanceof`演算子とキャスト（L1687–1772）
    + 親クラス型では子クラス固有メソッドを呼べないこと（5-30）
    + instanceofによる型調査とダウンキャスト、ClassCastExceptionの注意（5-31）
    + Java 16のinstanceofパターンマッチング（5-32）
- 例外処理の基礎（補足）（L1773–1811）
    + オーバーライドで親より広い検査例外を宣言できない制約（5-33）
    + 付録B.04「仮想メソッドテーブル」への参照（appendix/ディレクトリ名とも一致）
- よくあるエラーと対処法（L1812–1825）
    + 2026-11-09に、エラーメッセージの例・修正コード・デバッグのヒントを`appendix/h-common-errors/chapters/chapter05.md`へ移した。本文には出会いやすいエラーと原因の要点のリストとGitHubのURLだけを残す
    + 本文に挙げるエラー: super()の呼び出しに関するエラー、オーバーライドの制約違反、ClassCastException
- まとめ（L1826–1846）
    + 継承、オーバーライド、ポリモーフィズム、instanceofとキャスト、継承と例外の5項目と、第6章への導入（2026-11-08に新設）
- 章末演習（L1847–1884）

    + 次のステップとして第6章を案内する

## 他章との関係

- 第3章: 継承の考え方を軽く紹介している（「オブジェクト指向言語でつまずやすい継承」）。instanceofもすでに登場する
- 第4章: protectedの説明でVehicle/Carの`extends`、EnhancedBankAccountの継承を先に使っている。本章が継承の初出という扱いと矛盾する
- 第6章: finalメソッド・finalクラスを扱う。本章5-1のfinalメソッドを先取りしている
- 第7章: 抽象クラスShapeとテンプレートメソッドパターンを再度扱う。本章の具象クラス版テンプレートメソッド、図形描画（5-29）と題材が重なる。誤用例の解決策（インターフェイス）を本章から送っている
- 第8章: 正方形・Shapeの題材が再登場する（レコード・sealedの文脈）
- 第13章: 例外処理の本体。本章の補足節と誤用例のthrowが先取りしている
- 付録B.04: 仮想メソッドテーブル
