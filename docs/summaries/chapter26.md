# 第26章 統合プロジェクトの技術選定と実装 要約

行番号・サンプルコード番号の正確な対応は `docs/book-index/chapter26-integrated-project-technology.md` を参照する。

## 章の概要

- 2026-11-16に新設した、統合プロジェクトの後半の章で、本書の最終章
- 第25章の非機能要求を根拠に、保存先・CSV・GUI・ログ・テストの道具を選ぶ事例を示し、初版から改善版へ移す手順と振り返りで締める
- 選定の事実（版・公開日・ライセンス・依存・JARの大きさ）は2026-11-16にMaven Centralのpom.xmlとJARで確かめた。Commons CSVがBOMを取り除かないことは試作で確かめた
- サンプル: 26-1 SQLiteのJdbcStudentRepository（sqlite-jdbc 3.54.1.0）、26-2 split(",")が崩れる例、26-3 Commons CSV 1.14.1とBOMInputStream、26-4 JUnitでフェイクを使うテスト

## 節ごとの要約

- 本章の学習目標（L3–32）
    + 6項目。前提は第25章、第14・21・22章、付録E
- 技術を選ぶ前に考えること（L33–106）
    + 標準APIで足りる例、依存を増やす負担5つ、選定の流れの図、観点と確かめ方の表（第22章「外部ライブラリ選定の指針」を前提にする）
- 事例1：データをどこに保存するか（L107–239）
    + 要求4（異常終了で壊れない）を比較の途中で書き足した例、5候補の表、SQLiteとH2の表、ADRの影響、サンプルコード26-1（例外の変換・kind列・トランザクション）
- 事例2：CSVを自分で読むか、ライブラリを使うか（L240–398）
    + サンプルコード26-2、RFC 4180（脚注）、ExcelのCSV UTF-8のBOM、要求の書き出し、自作・Commons CSV・OpenCSVの表、試作（サンプルコード26-3）でBOMの扱いがわかった話、ライブラリを1つのクラスに閉じ込める
- 事例3：画面を何で作るか（L399–421）
    + Swing・JavaFX・Webの表。EDTでの保存は数千人なら問題ない。遅いと確かめてからSwingWorker（Nielsenの応答時間の目安は脚注）
- 事例4：ログを何で出すか（L422–443）
    + IO.println、java.util.logging、System.Logger、SLF4J+Logback。単独のアプリかライブラリかで選ぶものが変わる
- 事例5：テストに何を使うか（L444–507）
    + JUnitだけにする理由、サンプルコード26-4、フェイクとモックの違い、SQLは本物のデータベースで
- 初版から改善版へ移す（L508–555）
    + 書き直さずリファクタリング、6つの手順、表の構造の変更（Flyway・Liquibaseに触れる）
- 作ったものを振り返る（L556–607）
    + 振り返りの観点4つ、初版に残る課題5つ、次に学ぶこと
- よくある失敗と対処法（L608–624）・まとめ（L625–654）・章末演習（L655–672）
    + まとめに本書を終えるにあたっての段落。演習は`exercises/chapter26/`（GsonとJacksonの比較、Commons CSVで成績のCSV、H2のリポジトリ、フェーズ6に変更機能。チャレンジは方針だけ）
