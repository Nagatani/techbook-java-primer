# 第16章 ネットワークプログラミング 要約

行番号・サンプルコード番号の正確な対応は `docs/book-index/chapter16-network-programming.md` を参照する。

## 章の概要

- TCPのSocket/ServerSocketによるエコーサーバーから始め、スレッドプールによるマルチクライアント化、HTTP、UDP、チャット、JSON API、SSL、NIOまでを一通り示す
- HTTPはソケット直書き、HttpURLConnection、Java 11のHttpClient（非同期）の3段階で扱う
- 後半のREST・WebSocketはコードのない数行の紹介にとどまる
- 前提は第14章のストリームと第15章のExecutorService・CompletableFuture
- 二重構成（過去の版の結合）は見られない。ただし理論的な基礎部分が削られた痕跡がある

## 構成上の問題

- 「ネットワークプログラミングの基礎」（L34–54）は空行の後にIPアドレスとポート番号の箇条書きがあるだけで、本文が抜け落ちた痕跡がある
    + 学習目標の「TCP/IPプロトコルスタックの理解」「TCPとUDPの違いと使い分け」「ソケットの概念」を説明する節が存在しない
    + TCPとUDPの比較は16-1の前の1文とUDP節末尾の箇条書きに散在するのみで、まとめでは「違いを理解し」と書いている
- 学習目標で予告しているが本文で扱っていない内容
    + UDPのブロードキャスト通信（UDP節末尾で「可能」と触れるだけ）
    + ファイル転送プログラム（エラー集の16-17でサイズ先送りとreadFullyを示すのみ）
- 学習目標で挙げていないのに節がある内容
    + 非同期HttpClient、JSON API（Jackson）、SSL、NIO
- 「REST API実装の基礎」「WebSocketクライアントの基礎」はコードのない短い節で、まとめの「次のステップ」とも重複する。コラム化するか次のステップへ統合するのが自然
- 16-11はJacksonを使うが、外部ライブラリの導入方法は第22章で初めて扱うため、依存関係の追加方法が示されていない

## 節ごとの要約

- 本章の学習目標（L3–27）
    + 4つの大項目（基礎、TCP、UDPとHTTP、実用アプリ）。前提は第14章のストリーム、第15章のマルチスレッド
    + 「HTTPURLConnection」はクラス名の表記誤り（正しくはHttpURLConnection）
- はじめに（L28–33）
    + ネットワーク通信の重要性と章の位置付けを述べる2段落
- ネットワークプログラミングの基礎（L34–54）
    + IPv4/IPv6、ポート番号の3区分（Well-known・登録済み・動的）の箇条書きのみ
    + 子リストのインデントが崩れている（L44–45、L49–51）
- ソケットプログラミングの基礎（L55–164）
    + Socket、PrintWriter、BufferedReaderによるTCPクライアント（16-1）と、accept()で待ち受けるエコーサーバー（16-2）。try-with-resourcesで自動クローズする
- マルチスレッドサーバーの実装（L165–240）
    + 単一スレッドサーバーの限界を述べ、ExecutorServiceの固定スレッドプールでClientHandlerを実行するサーバー（16-3）。ECHO・TIME・QUITの簡易プロトコル
    + L173–175で項目名と説明が連結している（Issue #013）（2026-11-11に箇条書きを文章にした際に解消）
- HTTPクライアントの実装（L241–450）
    + HTTPリクエスト・レスポンスの構造
    + ソケットで直接HTTPを話すクライアント（16-4）、HttpURLConnectionによるGitHub APIへのGET（16-5）、Java 11のHttpClientのsendAsyncとCompletableFutureの連鎖（16-6）
    + 16-4の実行結果がコードの出力と一致しない（個別の問題を参照）。16-6は2026-11-08に、連鎖した処理の完了を待つよう直し、実行結果を実際の出力に合わせた（2026-11-11に解消）
- UDP通信の実装（L451–561）
    + DatagramSocketとDatagramPacketによるエコーサーバー（16-7）とクライアント（16-8）、UDPの特徴
    + H3「UDP受信側」の中身は送信して応答を受け取るクライアントで、見出しと内容が合わない
- 実践的な例：チャットアプリケーション（L562–699）
    + 全クライアントへブロードキャストするチャットサーバー（16-9、ポート5000）と、受信スレッドとメインの送信ループを分けたクライアント（16-10）
    + 本文は「ConcurrentHashMapでクライアントを管理」と書いていた（2026-11-09に`Collections.synchronizedSet`へ直した）
    + 2026-11-09に、クライアントが`/quit`のあとデッドロックして終わらない不具合（受信スレッドがロックを持つ`BufferedReader`を先に閉じようとする）を、`shutdownInput()`と`join()`で直した。サーバーも`/quit`で接続を閉じる。終了の手順を本文で説明した
    + 実行結果が接続拒否のエラー表示だけで、見出しの「サーバー接続時の例」と食い違っていたため、2026-11-08にサーバーが起動していない場合の例として説明し直した
- JSON APIクライアントの実装（L700–746）
    + JacksonとHttpClientで汎用GET/POSTクライアントを作る（16-11）。JSON処理のポイント4点
- REST API実装の基礎（L747–758）
    + RESTの4原則を挙げ、実装はSpring BootやJAX-RSを使うと述べるのみ。L873–876は項目名と説明が連結している（Issue #013）（2026-11-11に箇条書きを文章にした際に解消）
- WebSocketクライアントの基礎（L759–769）
    + WebSocketの特徴3点のみでコードなし。L885–887も連結している（Issue #013）（2026-11-11に箇条書きを文章にした際に解消）
    + 「Java標準APIで実装できる」とあるが、Java 11のHttpClient.newWebSocketBuilderなど具体名がない
- セキュリティの考慮事項（L770–847）
    + 入力検証・暗号化・認証・タイムアウト・リソース制限の5対策
    + SSLSocketFactoryによるTLS 1.3クライアント（16-12）
- パフォーマンスの最適化（L848–915）
    + SelectorとServerSocketChannelによる単一スレッドのNIOサーバー（16-13）
    + 第14章ではSelector/チャネルを扱っておらず、NIOの説明はこの節だけで完結している
- まとめ（L916–939）
    + 重要なポイント5点と次のステップ（REST、WebSocket、gRPC、マイクロサービス）
    + 「NIOを使用した非同期I/Oによる応答時間の短縮」は不正確（NIOのSelectorはノンブロッキングI/Oで、利点は応答時間より接続数に対するスケーラビリティ）
- 章末演習（L940–963）
    + 演習リンクは`exercises/chapter16/`（2026-11-09に演習ディレクトリを現行の章番号に組み替え、リンクを直した。Issue #010）
    + 「詳細な課題内容と実装のヒントは…」が2回ある（L1076、L1085）
- よくあるエラーと対処法（L964–978）
    + 2026-11-09に、エラーメッセージの例・修正コード・デバッグのヒントを`appendix/h-common-errors/chapters/chapter16.md`へ移した。本文には出会いやすいエラーと原因の要点のリストとGitHubのURLだけを残す
    + 本文に挙げるエラー: 接続のエラー、データの送受信のエラー、HTTPのステータスコードの確認漏れ、リソースの解放漏れ
