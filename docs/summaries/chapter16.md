# 第16章 ネットワークプログラミング 要約

行番号・サンプルコード番号の正確な対応は `docs/book-index/chapter16-network-programming.md` を参照する。

## 章の概要

- TCPのSocket/ServerSocketによるエコーサーバーから始め、スレッドプールによるマルチクライアント化、HTTP、UDP、チャット、JSON API、SSLまでを一通り示す。NIOのSelectorは考え方だけを述べ、コード例は付録Hに置く
- HTTPはソケット直書き、HttpURLConnection、Java 11のHttpClient（非同期）の3段階で扱う
- REST・WebSocketは独立した節をやめ、まとめの「次のステップ」で説明する（2026-11-11）
- 前提は第14章のストリームと第15章のExecutorService・CompletableFuture

## 節ごとの要約

- 本章の学習目標（L3–26）
    + 4つの大項目（基礎、TCP、UDPとHTTP、実用アプリ）。実用アプリの項目の1つは「接続や送受信で起こりやすいエラーと対処」。前提は第14章のストリーム、第15章のマルチスレッド
- はじめに（L27–32）
    + ネットワーク通信の重要性と章の位置付けを述べる2段落
- ネットワークプログラミングの基礎（L33–129）
    + 小節「TCP/IPの階層」「TCPとUDP」（比較と図chapter16-tcp-vs-udp）「IPアドレスとポート番号」「ソケットとクライアント・サーバー」
    + 通信相手はIPアドレスとポート番号の組で指定する。IPv4（32ビット）とIPv6（128ビット）、ポート番号の役割と0〜65535の範囲を文章で説明し、3区分（Well-known・登録済み・動的）をリストで示す
- ソケットプログラミングの基礎（L130–243）
    + ServerSocketとSocketの役割をシーケンス図（chapter16-tcp-socket）で示す
    + Socket、PrintWriter、BufferedReaderによるTCPクライアント（16-1）と、accept()で待ち受けるエコーサーバー（16-2）。try-with-resourcesで自動クローズする。TCPの性質は「TCPとUDP」で説明済みなので、この節では繰り返さない
- マルチスレッドサーバーの実装（L244–327）
    + 単一スレッドサーバーの限界と、複数クライアントを同時に処理する利点（各クライアントがほかのクライアントの処理を待たずに済む）を文章で述べる
    + ExecutorServiceの固定スレッドプールでClientHandlerを実行するサーバー（16-3）。ECHO・TIME・QUITの簡易プロトコル
    + 同時に処理できるのはプールの大きさ（10）までで、各接続はQUITまでスレッドを占有するため、11番目のクライアントは空きを待つと明記する
- HTTPクライアントの実装（L328–583）
    + HTTPリクエスト・レスポンスの構造
    + ソケットで直接HTTPを話すクライアント（16-4）。実際の開発ではHttpURLConnectionやHttpClientを使うと断る。HTTP/1.1ではチャンク形式（各かたまりの前に大きさの16進数の行、最後に大きさ0の行）で返ることがあるため、HTTP/1.0で送る。HTTPの行末はCRLFで`println`の改行はOSで変わるため、`print`で`\r\n`を付けて`flush()`する
    + HttpURLConnectionによるGitHub APIへのGET（16-5、`URI.create(...).toURL()`、タイムアウトの設定も抜粋に含む）、Java 11で標準になったHttpClient（`java.net.http`）のsendAsyncとCompletableFutureの連鎖（16-6、HttpClientの生成も抜粋に含む。`done.join()`で完了を待つ）。16-6の出力は「実行結果の一例」として示す
    + 16-6の後に、非同期で他の処理を続けられること、サーバーも対応していればHTTP/2で1つの接続に複数のリクエストを多重化できることを文章で説明する
    + コラム「タイムアウトを設定しない通信は、いつか障害になる」（2026-11-19）。HttpClient・HttpURLConnectionの既定は無限に待つこと、待つスレッドが埋まって障害が広がること、業務の要件からタイムアウトを決めること
- UDP通信の実装（L565–678）
    + 冒頭で小節「TCPとUDP」を参照する
    + DatagramSocketとDatagramPacketによるエコーサーバー（16-7、H3「UDPサーバー」）とクライアント（16-8、H3「UDPクライアント」）
- 実践的な例：チャットアプリケーション（L679–819）
    + `ConcurrentHashMap.newKeySet()`で管理し全クライアントへブロードキャストするチャットサーバー（16-9、ポート5000）と、受信スレッドとメインの送信ループを分けたクライアント（16-10）
    + 各クライアントは`PrintWriter`を用意してから集合に加える（先に加えるとNullPointerExceptionの競合が起こる）。synchronizedSetは反復時に利用側のロックが要ることを脚注で述べる
    + 終了時に`shutdownInput()`と`join()`で受信スレッドを終わらせてから資源を閉じる理由（BufferedReaderのロック）を説明する
    + 実行結果はサーバー未起動時の接続エラーの例として示す
- JSON APIクライアントの実装（L820–881）
    + JacksonとHttpClientで汎用GET/POSTクライアントを作る（16-11）。受け取る型を指定してJSONを扱う。POSTのメソッドは紙面で省き、GitHubの全文に載せている旨を脚注のURLとともに書く。Jacksonは外部ライブラリで、追加方法は第22章で学ぶと断る
    + GET・POSTに共通の`readBody`で、ステータスが200番台のときだけJSONを変換する（POSTの成功は201が多いため）
    + JSON処理のポイント（ライブラリに任せる、`Class<T>`で型を渡す、Content-Type/Accept、ステータスコードの確認）を文章で述べる
- セキュリティの考慮事項（L882–982）
    + 入力検証・暗号化・認証・タイムアウト・リソース制限の5対策
    + SSLSocketFactoryによるTLSクライアント（16-12）。プロトコルをTLS 1.2以上に限り（JDK 25の既定と同じ）、`setEndpointIdentificationAlgorithm("HTTPS")`でホスト名の検証を有効にする。SSLSocketは既定ではホスト名を検証しないこと、HttpClient・HttpURLConnectionでは自動で行われることを説明する
- 多数の接続を1つのスレッドで扱う（L983–990）
    + 接続ごとにスレッドを使うと、数千の接続でスレッドとメモリが足りなくなる。`java.nio`のノンブロッキングのチャネルと`Selector`で、準備のできた接続だけを1つのスレッドで順に処理できる。エコーサーバーの例は付録Hにあると案内する
- まとめ（L991–1023）
    + 重要なポイント5点（パフォーマンスはNIOのSelector、コード例は付録H）
    + 次のステップでREST（リソース、HTTPメソッド、ステートレス、Spring Boot・JAX-RS）とWebSocket（双方向通信、`HttpClient.newWebSocketBuilder()`）を説明し、gRPC、マイクロサービスを挙げる
- 章末演習（L1024–1044）
    + 演習リンクは`exercises/chapter16/`。最後の文で第17章へ誘導する（「次のステップ：」の見出し語は2026-11-18に除いた）
- よくあるエラーと対処法（L1045–1059）
    + 本文に挙げるエラー: 接続のエラー、データの送受信のエラー、HTTPのステータスコードの確認漏れ（`HttpClient`は例外を投げない、`HttpURLConnection`は`getInputStream()`が例外を投げる）、リソースの解放漏れ。詳細は`appendix/e-common-errors/chapters/chapter16.md`
