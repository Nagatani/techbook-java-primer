# 書籍の索引と要約

校閲や構成の見直しで原稿全体を読み込むと、コンテキストが肥大化します。
全体を見渡す作業では、まず索引と要約を使い、本文は必要な節だけを行範囲を指定して読みます。

## 構成

| 層 | 場所 | 作り方 | 内容 |
|---|---|---|---|
| 機械的な索引 | `docs/book-index/` | `npm run index`で自動生成 | 節（H2）の行範囲、節ハッシュ、サンプルコード番号、章参照、脚注・コラム数、小見出し |
| 内容の要約 | `docs/summaries/` | LLMまたは手作業で作成 | 節ごとに教える概念、前提、他章との関係、構成上の問題 |
| 全体概観 | `docs/summaries/overview.md` | 要約から集約 | 章の地図と、章をまたぐ問題 |

索引は再生成できるので手で編集しません。
行番号やサンプルコード番号などの事実は、要約ではなく索引を正とします。

## 要約ファイルの形式

frontmatterに原稿のパスと、要約したときの節ハッシュを記録します。
節ハッシュは`docs/book-index/`の表からそのまま写します。

```yaml
---
source: manuscripts/chapter09-collections.md
summarized: 2026-11-07
sections:
  - key: "なぜコレクションフレームワークが必要か"
    hash: b336e328
---
```

本文は次の見出しで構成します。

- 章の概要
- 構成上の問題（あれば）
- 節ごとの要約
- 他章との関係
- 校正で見つけた個別の問題

## 鮮度の確認

```bash
npm run index:check
```

- 要約が古い節
    + 原稿の本文が変わった節。要約を見直し、hashを更新する
- 原稿から消えた節、要約がない節
    + 見出しの追加・削除・改名があった節

## 作業での使い方

- 全体を見渡す作業（重複の洗い出し、構成の見直し、章参照の確認）
    + まず`overview.md`を読み、要約と索引だけで判断し、問題のある節だけ本文を読む
- 章をまたぐ校閲
    + 章ごとにサブエージェントへ任せ、指摘事項だけを受け取る
- 1つの章の校正
    + 要約で節構成をつかみ、索引の行範囲で節ごとに読んで修正する
- 原稿を修正したら
    + `npm run index`で索引を更新し、`npm run index:check`で古くなった要約を確認する
