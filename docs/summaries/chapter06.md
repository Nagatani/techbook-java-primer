# 第6章 不変性とfinal 要約

行番号・サンプルコード番号の正確な対応は `docs/book-index/chapter06-immutability-and-final.md` を参照する。

## 章の概要

- 可変オブジェクトが引き起こす競合状態と副作用を動機に、不変オブジェクトとfinalキーワードを教える
- finalの3用途（変数・メソッド・クラス）、不変クラスの5つのルール、防御的コピー、ビルダーパターンを扱う
- 後半の「よくあるエラーと対処法」がL729–1221と章の約4割を占め、本文の内容（final、防御的コピー、継承による破綻）を誤りの側から繰り返す
- 前提は第4章のカプセル化と第5章の継承
- 動機づけの例（6-1）と使用例（6-8）でスレッドとラムダ式、6-4でラムダ式と「実質的にfinal」、各所でList・ArrayListを説明なしに使っている（第9章・第11章・第15章で学ぶ内容）（2026-11-08に、初出の箇所へ後の章で学ぶ旨と最小限の読み方の案内を加えた）

- 「まとめ」の中に新しい内容（Recordによる不変クラス、6-31）が入っている。Recordは第8章で本格的に扱うため、ここでは第8章への予告にとどめるのがよい

## 節ごとの要約

- 本章の学習目標（L3–19）
    + 不変性の概念、finalの使い分け、不変オブジェクトの設計（防御的コピー・ビルダー）、パフォーマンスとのトレードオフの4目標
    + パフォーマンスのトレードオフは本文では扱わず、エラー集の「6. パフォーマンスへの影響」でのみ触れる
- 不変性の概念と重要性（L20–151）
    + 可変な`MutablePoint`を2スレッドで更新する競合状態（6-1）と、getterが内部の可変オブジェクトを返す副作用（6-2）を問題として示す
    + final フィールドと`withX`/`withY`を持つ`ImmutablePoint`で解決を示し（6-3）、利点4点を列挙する
    + 6-1はスレッドとラムダ式を使っており、第15章・第11章より前に登場する
- finalキーワードの3つの用途（L152–275）
    + final変数（static final定数、finalフィールド、finalローカル変数と初期化タイミング）（6-4）
    + finalメソッドでテンプレートメソッドの流れを固定する例（6-5）
    + finalクラス。`String`を例に挙げ、`ImmutablePerson`の継承をコンパイルエラーにする（6-6）
- 不変オブジェクトの設計パターン（L276–413）
    + 不変クラスの5ルール（final クラス、private final フィールド、setterなし、コンストラクタで初期化完了、防御的コピー）
    + 検証・防御的コピー・with系メソッド・equals/hashCode/toStringを備えた完全な`ImmutablePerson`（6-7）と、その使用例（6-8。2つのスレッドからの読み取りは2026-11-08に3回ずつに減らし、出力順が変わる旨と実行例を載せた）
- 防御的コピーとビルダーパターン（L414–572）
    + `DateRange`で入力時・出力時の防御的コピーを示す（6-9）
    + 必須とオプションのパラメータを分けた`Book.Builder`（6-10）とメソッドチェーンでの使用例（6-11。2026-11-08に実行結果を出力するコードを加えた）、ビルダーの利点
    + `Builder`は静的ネストクラスで書かれているが、静的ネストクラスの説明は第8章のPart 4まで出てこない
- よくあるエラーと対処法（L573–1072）
    + 1. finalの再代入と未初期化（6-12〜6-15）
    + 2. 可変コレクションの露出（6-16〜6-18）
    + 3. `java.util.Date`の防御的コピー漏れと、`LocalDateTime`を使う推奨策（6-19〜6-22）
    + 4. final配列・finalなListでも中身は変更できるという誤解（6-23〜6-25）
    + 5. 非finalクラスの継承による不変性の破綻（6-26、6-27）
    + 6. 不要な防御的コピーと、unmodifiableListによる改善・遅延初期化（6-28〜6-30）
    + デバッグのヒント4点
- まとめ（L1073–1123）
    + 学習内容4点と不変性の利点4点を再掲する
    + 「Java 14以降の不変性サポート」としてRecordで`ImmutablePoint`を書き直す（6-31）
- 章末演習（L1124–1150）
    + `exercises/chapter06/`へのリンクと、基礎・発展・チャレンジ課題の概要。付録B.05への参照

## 校正で見つけた個別の問題

- L148、L272: 「不変オブジェクトの利点。」「finalクラスの利点。」はリスト導入文として不自然（コロン削除の機械的な置換の跡と推測される）
- L250（6-6）: `public final class String { }`と書いており、標準の`String`を再定義するように読める。コメントで示すだけにするのがよい
- L667: 「状態が変わらない　→　動作を予測しやすい」に全角スペースと矢印が入っている
- L822–835（6-16）: `List`のimportがない。6-17の`RuntimeException`というコメントは実際には`UnsupportedOperationException`
- L876–879（6-18）: コメントは「防御的コピーを返却」だが、既に不変のリストを再度`unmodifiableList`で包んでいるだけ
- L1131（6-28）: クラス名`IneffientImmutableClass`は`Inefficient`の綴り誤り
- L1179–1207（6-30）: unmodifiableListのビューを作るだけの処理にダブルチェックロッキングを使っており、「大量データの最適化」として説明するには根拠が弱い。volatileとsynchronizedも第15章より前に出てくる
